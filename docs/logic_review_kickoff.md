# LOGIC 검토 메뉴 — 새 세션 첫 회차 지시

> 새 Claude Code 세션의 첫 메시지로 이 파일 내용을 통째로 붙여 넣고,
> Logic Diagram · Loop Diagram · System Diagram 샘플 PDF 를 각각 1~2개 첨부한다.

## 0. 먼저 읽을 것
- 저장소: AI-P-ID-Extraction-tool (이미 운영 중인 P&ID 계기·밸브 추출 프로그램)
- CLAUDE.md 와 docs/state_and_roadmap.md 를 먼저 읽는다. 특히 §2 진행 원칙, §9 범용성 원칙,
  §8 "다음 프롬프트를 쓸 때" (실행 규율 포함).
- 작업 브랜치: claude/logic-review (새로 만든다). 기존 브랜치 claude/titleblock-parsing-c5st4x 에는
  커밋하지 않는다. PR 은 내가 요청할 때만 만든다.

## 1. 무엇을 만드나
P&ID 분석과 나란히 "LOGIC 검토" 메뉴를 하나 더 만든다. 같은 서버, 같은 첫 화면, 같은 프로젝트에 속한다.
입력: Logic Diagram / Loop Diagram / System Diagram PDF (첨부 샘플).
기능:
 1) 도면 읽기 — 블록(기능 블록·논리 게이트·타이머 등), 태그, 신호선, 시트 간 연결(off-sheet / from-to 참조)
 2) from-to 선 연결 적합성 검토 — 끊긴 선, 짝이 없는 시트 간 참조(A 시트의 "TO 3-B" 가 3번 시트에 없음),
    입력 없이 끝나는 블록 입력/출력, 같은 참조 번호가 두 군데에서 쓰임 등
 3) 정합성 확인 — 같은 프로젝트의 P&ID 분석 결과와 태그 대조 (P&ID 에 있는데 Logic/Loop 에 없음, 그 반대),
    Loop Diagram 의 계기가 P&ID 의 계기와 같은지
 4) 결과 — 목록 + 도면 위 표시(오버레이) + Excel 출력. 사람이 O/X 로 확인하고 고칠 수 있게
    (P&ID 화면의 검토·마크업·VOC 방식을 그대로 따른다)

## 2. 첫 회차에 할 일 (코드는 조사·설계 뒤에)
 1) 샘플 PDF 를 열어 실태 조사: 글자층이 있는지(선으로 그려진 글자인지), 블록·선·참조 표기가 어떻게 그려졌는지,
    범례/심볼 시트가 있는지, 시트 간 참조 표기의 꼴. 렌더 이미지로 눈으로 확인한다.
 2) 기존 코드에서 재사용할 것을 먼저 찾는다 (CLAUDE.md §9 3: "없는 것을 만들기 전에 있는 것을 찾는다").
    후보: app/engine/pidcache.py (PDF 읽기·SHX 글자·회전), 타이틀블록 유도, 커넥터 문구 읽기,
    app/engine/tags.py (태그 체계 학습), 업로드/프로젝트/리비전/뷰어/마크업/VOC/대시보드 임베드.
 3) 설계 문서 docs/logic_review_design.md: 판정 규칙(무엇을 오류로 볼지), 데이터 구조, 화면 흐름,
    P&ID 와의 대조 방법, 도면이 답하지 않는 것은 무엇인지(사람에게 물을 자리).
 4) 내가 승인하면 그다음에 구현한다. 설계 중 판단이 필요한 것은 질문 목록으로 낸다.

## 3. 원칙 (P&ID 와 같다)
- 도면이 말하는 것은 도면에서 읽는다. 특정 샘플에서 잰 숫자·낱말을 코드에 박지 않는다(§9).
- 판정(검출·연결 검사)에 LLM 을 쓰지 않는다. 규칙만.
- 도면에 없는 값을 지어내지 않는다. 못 읽으면 비워 두고 사유를 남긴다. 못 읽는 도면은 사유를 말하고 멈춘다.
- 모양·관계·비율로 판정한다. 절대 pt 값을 문서마다 외우지 않는다.

## 4. 건드리면 안 되는 것
- P&ID 판정 엔진: app/engine/* 의 검출 코드, app/pipeline.py. LOGIC 에 필요하면 함수를 **부르기만** 하고
  고쳐야 하면 먼저 나에게 묻는다.
- 새 코드는 별도 폴더(예: app/logic/)와 별도 화면 파일에. app/main.py, app/static/app.js, index.html 에는
  메뉴 연결 같은 최소한의 줄만 더한다 (다른 브랜치와 충돌을 줄이려고).
- DB 는 새 테이블만 더한다. 기존 테이블·열을 바꾸지 않는다.
- 회귀 기준선 다섯은 그대로여야 한다 (python3 spike/regression_3p.py 로 확인 — PDF 가 있는 프로젝트만):
