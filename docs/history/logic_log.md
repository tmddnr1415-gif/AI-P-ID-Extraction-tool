## L81 — Logic 분석 · 작성 더 가볍게 (2026-10-30)

* 사용자: *Logic 분석과 작성 더 가볍게, 너무 무거워.*  두 화면을 19VA(846쪽) 분석 · 아미랄 827장 그림 묶음으로 재고 큰 것부터.
* **작성 — 시뮬레이션 첫 켜기 23초 → 0.29초.**  ★ 원인은 계산량이 아니라 **끝없이 뒤집히는 고리**였다: 들여올 때 NOT(⊠) 상자 안쪽 획이
  선 토막으로 옮겨져(19VA Typical 0013 SOV) 입력선과 출력선이 상자 한가운데서 만나 한 신호가 되었고, NOT 이 자기 입력을 뒤집어 그 매크로가
  든 모든 장에서 MAX_ITER(300)까지 돌았다 (분석 결과로는 같은 장이 0.003초).  `draw_sim._drop_inside` — 기호 상자 안에 통째로 든 선 토막은
  신호선이 아니다 (변에 닿는 선은 그대로 단자).  같이: 분석이 장 NOTE 로 토글이라 읽은 글자(SRST)는 `from_sheet` 가 그 NOTE 를 장 노트로 옮기고,
  예전에 들여온 그림은 공통 Typical 사전이 토글로 배운 글자로 읽는다 (`_learned_toggles`).
* 남은 첫 계산(827장을 시뮬레이션 시트로 바꾸기 약 5초)은 그림 폴더 `sheet.pkl` 에 남겨 서버를 다시 켜도 안 한다 (열쇠 + 코드 판) ·
  묶음을 열면 뒤에서 한 번 미리 돌린다 (`_warm_sim` · 0.8초 조용한 뒤 · 계산은 잠금 하나로 겹치지 않게 · `PID_LOGIC_WARM=0` 이면 끔).

## L82 — 선이 엉뚱하게 이어지던 것 · 신호 처리 블록 두 번 누름 계산 (2026-10-30)

* 사용자: *라인이 이어지는 것들은 문제를 파악하고 이어지지 않도록 · signal processing 은 로직 화면에서 더블클릭해 input 을 넣으면 어떻게 계산되어 출력이 무엇인지.*
* **원인** — 작성 시뮬레이션의 그물 짓기(`draw_sim._pair_joined`)가 '선 끝이 다른 선 몸통에 닿으면 연결' 이었다.  CAD(19VA 를 다시 그린 827장)는
  엇갈리는 자리에서 한 선을 둘로 끊어 그리므로, 엇갈린 두 신호가 한 선이 되었다.  분석기(`graph.passes_through` · L13)와 같은 규칙으로:
  끝이 몸통에 닿았는데 그 자리에서 **반대 방향으로 같은 직선이 이어지면 지나가는 교차** (연결점 dot 이 있으면 연결).  `_crossing` · 끝점 색인 `endmap`.
* 감사(들여온 선 id 의 분석 선 번호): 서로 다른 분석 선 둘 이상을 합친 그림 그물 161개/73장 → 69개/9장 (남은 것은 0024~0029 화살촉 토막 — 같은 블록).
* **계산 판** — Logic 작성에서 글자 상자(Σ · ÷ · F(X) · T …) 두 번 누름 (시뮬레이션 중이면 연산자 메뉴의 '∑ 입력 넣고 계산 보기'도) →
  `POST /logic/api/drawings/{id}/aop` (그 장만 · 검토 화면 sheet_aop 와 같은 analog.nets + 입력선 출처) → 입력 칸 · 계수 · 설정값 → 칠 때마다
  `/logic/api/aopsim` (aops.compute) → 식 · 값 넣은 식 · 출력.  두 입력 연산(÷ · − · 전환)은 ⇅ 로 앞 · 뒤를 바꾼다 · 신호 처리 페이지로 넘기기.
* 같이 고침: `aop_trace.run_static` 이 이름 없는 입력의 계수를 계산에서 빠뜨렸다 (식은 −X1 + X2 인데 −10 + 4 = 14).
* 시험 `tests/test_logic_l82_crossing.py` 5 · 화면 자기검증 `spike/ui_audit_l82.py` (평균 · 나눗셈 · 전환 각 5항목 통과) · 빠른 시험 1606 통과.
