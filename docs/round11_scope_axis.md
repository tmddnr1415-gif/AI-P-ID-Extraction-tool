## 3. 밸브 SCOPE (C)

### 원인 — **(a)**, 그리고 그 안에 두 번째 원인이 있었습니다

1. **벤더 마크 판정이 계기 경로에만 있었습니다.**  `detect_symbols.detect()`
   안에서 버블마다 마크를 읽고 `det.rules_hit` 에 적는데, 밸브는
   `detect_valves` 가 따로 잡고 그 모듈은 마크를 **아예 읽지 않습니다.**
   `_valve_rows` 도 `scope=` 를 세팅하지 않았습니다.
2. 그것만 고쳐서는 **여전히 안 잡혔습니다.**  마크를 몸체 사각형 위에서 찾으니
   전 도면에서 **1건**만 걸렸습니다.  실측하니 자리가 달랐습니다:

```
p6 GATE 밸브     몸체 rect [873.5, 563.5, 890.5, 573.5]
                액추에이터(M 원) rect [875.0, 534.4, 889.2, 548.6]
                별표 (882, 526) · 1개 · GLYPH
  별표 → 액추에이터 위쪽 간격   8.4pt   ← 허용치 mark_above 25.0pt 안
  별표 → 몸체     위쪽 간격    37.5pt   ← 허용치 밖
```

**별표는 그 항목의 심볼 위에 찍히고, 작동 밸브에서 맨 위에 그려진 심볼은 몸체가
아니라 액추에이터입니다.**  그래서 허용치를 늘리지 않고 **재는 자리**를
바로잡았습니다 — 액추에이터가 있으면 그 사각형 위에서, 없으면 몸체 위에서.
계기와 같은 허용치(25.0pt)를 그대로 씁니다.

### 구현 — 함수는 하나입니다

- `detect_symbols.read_vendor_mark(rect, ...)` 를 `detect()` 안에서 꺼냈습니다.
  움직인 것은 **위치뿐**이고 판정은 한 글자도 바뀌지 않았습니다.
- `detect_symbols.package_box_marks(boxes, marks, lay)` 도 같이 꺼냈습니다.
- 밸브 행은 그 결과를 `_MarkedRect` 로 싸서 **10회차의 `_scope_of` 에 그대로**
  넘깁니다.  밸브용 SCOPE 로직은 없습니다
  (`test_valve_scope_uses_the_same_function_as_instruments` 가 강제).
- `detect_valves.Body.actuator_rect` 를 추가했습니다.  판정에 쓰이지 않고
  이미 계산된 사각형을 들고만 있습니다.

## 4. 발주처 양식 SCT 필터 (D)

### 규칙

`excel_out.in_client_scope(row)` 하나입니다.  **내보내기 단계에서만** 걸고
검출·판정·저장은 건드리지 않습니다.

```
SCOPE == "SCT"   →  담는다
SCOPE == 다른 값  →  뺀다        (VENDOR / VENDOR(이름) / 검토자가 적은 값)
SCOPE 가 없음     →  담는다      ← §4-2
```

NO 열은 **파일 안에서 1부터 연속**입니다 (667 / 66 / 22 전부 확인).
`excel_no`(리비전을 넘어 고정되는 번호)는 **자리**를 정하는 데 그대로 쓰이고,
찍히는 숫자만 다릅니다 — 발주처가 받는 것은 리스트이지 우리 내부 대장이
아니기 때문입니다.  §7.3 의 "확정 삭제 행은 원래 NO 유지"와는 다른 이야기이고
(그쪽은 리비전 사이의 정체성), 삭제 행은 여전히 제자리에 남습니다.

**안정 ID 는 1029행 전량에 부여된 그대로**입니다.  걸러진 행의 ID 를 회수하거나
다시 매기지 않습니다 —
`test_the_export_filter_does_not_touch_stable_ids` 가 소스 검사로 강제합니다.

### 4-2. ⚠ 스스로 뒤집은 판단 — 값이 **없는** 행은 담습니다

처음에는 `SCOPE == "SCT"` 만 담게 했습니다.  UI 스위트가 그 상태로 돌면서
**발주처 양식 네 개가 통째로 빈 파일**로 나왔습니다 (`{'kind': 'MOV',
'rows': 0}`).  원인은 그 스위트가 **실 DB 의 사본**으로 도는데, 거기 저장된
분석이 SCOPE 열이 생기기 전 것이라 모든 행의 scope 가 빈 문자열이기 때문입니다.

**회사 PC 의 기존 분석 결과가 정확히 그 상태입니다.**  값이 없는 것은 "타사
공급"이 아니라 "아직 판정한 적 없음"이고, 없는 판정을 타사 공급으로 읽는 것은
근거 없는 값 생성입니다.  그래서 빈 값은 담고, 몇 행이 그랬는지를
MANIFEST 의 `legacy_no_scope_rows` 에 싣습니다 — 그 숫자가 0 이 아니면
**다시 분석해야 한다**는 뜻입니다.  뺀 행 수는 `out_of_scope_rows` 에 적힙니다.

### 캡처에서 발견한 결함 — 셋 다 이번 회차에서 고치지 않았습니다 (UI 는 별도 회차)

1. **오버레이 색이 이제 사실과 다릅니다.**  p6 범례가
   `포함 2 · 벤더 제외 26 · 공급자 인터페이스 구간 18 · 검토 필요 0` 인데,
   그 18은 **SCT 행 18개**(계기 12 + 밸브 6)이고 "공급자 인터페이스 구간"이
   아닙니다.  색 판정이 `scope == "SCT"` 를 보는데, 10회차 전에는 그 값이
   SCT 파선 구간(2행)에만 붙었고 지금은 **우리 공급 전체**에 붙기 때문입니다.
   그리고 `포함 2` 는 벤더 밸브 2행입니다 — `vendor_supply` 를 밸브에 쓰지
   않기로 했으므로(§3) 주황으로도 못 가고 초록으로 떨어집니다.
   → 색 규칙을 `scope` 가 아니라 **벤더 여부 + SCT 파선 구간 근거**로 다시
   짜야 합니다.  피드백 5장(범례 색상 설명)과 같이 처리하는 것이 맞습니다.
2. **근거 패널의 문장이 틀립니다.**  벤더 행에 `스코프 판정 — 벤더 공급 —
   이 행은 리스트에 포함됩니다` 라고 적히는데, 이제 발주처 양식에서는
   **빠집니다.**  "화면·DB 에는 남고 발주처 양식에는 안 나갑니다"가 맞습니다.
3. **SCOPE 열이 그리드에서 잘립니다** — `VENDOR(ST SUPP…`.  이름이 긴 값이
   11종 중 넷이라 열 폭을 넓히거나 툴팁이 필요합니다.
