## 무제한 순회 진단 — §2.3 금지가 옳았다는 세 번째 실측

판정 트리의 전제는 "탭한 라인의 양끝이 커넥터/기기에 닿는다"이다.  진단
전용으로 §2.3 의 순회 금지를 풀고(무제한 BFS, 접합 허용치 min_run=16.97pt)
810행을 다시 재면:

- 무엇에든 도달: **324/810 (40.0%)**
- FROM·TO 짝 성립: **84/810 (10.4%)**

즉 **그래프 순회를 허용해도 판정률은 10.4%** 다.  원인은 도면의 선분 단절:
양끝 무명 행의 끝점→최근접 직교 런 간격이 p50 21.4pt 로 min_run 을 넘고,
16.97pt 미만 스터브는 런 병합이 이미 버렸다.  같은 벽의 실측이 이제 셋이다:

| 실측 | 값 | 회차 |
| --- | --- | --- |
| 배관 그래프 추적 성공 | 13.1% | 배관 그래프 회차 |
| 국소 연결(리드선→런→기기) | 4.9% | 국소 연결 회차 |
| **무제한 순회 · FROM/TO 짝** | **10.4%** | 5회차 (이 문서) |

**결론: 순회를 금지한 §2.3 은 성능을 깎은 제약이 아니라, 이 도면에서 어차피
안 되는 길을 막아 둔 것이었다.**  판정률을 올리는 길은 순회가 아니라 선분
복원(아래 표준 끊김)과 도면 품질이다.

## 실측 유도 다섯 가지 (1부에서 ④ 100% → 75.2%)

1. **자기 몸통 획 제외** — 계기 사각형의 제 변이 런 후보에 들어와 "런 2개
   동률"을 만들었다 (`_own_body`).
2. **인출선 착지 = 교차** — 인출선이 라인을 지나쳐 그려진 실측 4.9pt.
   근접(join_slack 0.8pt)이 아니라 교차로 판정한다 (`_crossings`).
3. **끊긴 라인 병합** — 오리피스·밸브가 끊은 자리(마주보는 콜리니어 쌍)는
   한 라인이다 (`_gap_pair`).
4. **모선 승계 접합 = min_run** — 버려진 스터브 길이 상한(16.97pt, 범례 유도)
   보다 짧은 간격은 "스터브가 있던 자리"와 구별되지 않는다.  승계는 여전히
   딱 한 번이다.
5. **표준 끊김 다리** — 콜리니어 간격 분포: 17~18pt 봉우리 2,644/6,128건(43%),
   **19pt 칸 0건**, 두 번째 봉우리 35pt(인라인 밸브 몸통).  최빈 직후 첫 빈
   칸(18.5pt)을 상한으로 같은 좌표의 직선을 복원한다 (`standard_break` —
   문서마다 재유도, 상수 없음.  35pt 는 다리를 놓지 않는다).

## 지표 (발주처 541행 대조 · `spike/desc_metrics.py`)

주 지표는 **식별 가능성**, F1 은 참고다 (F1 하락은 회귀 실패가 아니다 —
5회차 프롬프트).  주의: 이 채점기는 원본(이전 회차, /tmp 소실)의 재구현이라
절대값이 이전 기록과 어긋난다 (같은 현행 문장에서 F1 73.2 ↔ 기록 74.6,
완전일치 33 ↔ 34).  **같은 채점기로 현행·신규를 다 재고 차이만 읽는다.**

| 지표 | 현행(④ 유지분) 전체 | 혼합 적용 후 |
| --- | ---: | ---: |
| 식별 가능성 | 42.3% (229행) | **39.6% (214행)** |
| 완전일치 | 33 | 24 |
| 토큰 F1 (참고) | 73.2 | 69.3 |

**혼합 적용 후가 발주처 표기 기준으로는 낮다.**  구조적이다: 새 문형은
`FROM … TO … {TYPE풀네임}` 형태라 발주처의 기기 주어 문형과 낱말이 다르고,
채점기는 발주처 표기와의 일치를 잰다.  "그 문장으로 계기를 찾아갈 수
있는가"는 라벨링 워크북(`out/label_nouf1.xlsx`, 사람 O/X)이 가른다 — 그것이
이 워크북을 만든 이유다.

## 6회차 — ④ 618행의 사용자 확정 경로

자동 추적의 세 실측이 막은 자리를 사람이 확정하고 재사용한다.

- **UI**: ④ 행의 근거 패널에 FROM/TO 지정 — 후보는 그 도면에서 이미 읽은
  텍스트 세 층(커넥터 문구 · 기기 라벨 · 도면 텍스트)뿐이다.  후보 그대로 =
  `후보선택`, 병합된 도면 텍스트에서 일부만 = `후보선택(부분)`, 후보에 없는
  입력 = `자유입력` 으로 서버가 출처를 기록한다.  확정 전에는 현행 문장이
  그대로 남는다.
- **후보 잡음 필터와 그 탈출구** (승인 2026-08): 도면 텍스트 층은 이미 측정된
  제거 패턴(`DRAWING_NO` · `BORE` · `GRID_CELL` · `NOTE_REF` + 점선 리더 ·
  버블 안 ISA 글자 · 배관 치수 · ASME 코드)으로 거른다 — p6 38→7 · p16
  119→49 · p18 33→11.  **거른 것은 버리지 않는다**: 서버가 `texts_filtered`
  로 함께 돌려주고 화면의 **"전체 후보 보기"** 가 펼친다(파선 알약 + "걸러낸
  텍스트" 이름표).  정답이 주석 덩어리에 섞여 인쇄되는 일이 있기 때문이고
  (p6 `HP TURBINE IP TURBINE`), 그렇게 고른 문구도 출처 판정 pool 에 들어가
  `자유입력` 이 아니라 `후보선택`/`후보선택(부분)` 으로 기록된다.
- **문형**: 판정 트리 ② 그대로 — 선두 FROM/TO 벗김 · TYPE 풀네임 · Suffix 는
  같은 페이지 · 같은 TYPE · 같은 (FROM, TO) 묶음에서 위→아래 · 왼→오.
- **저장**: `{데이터}/projects/{프로젝트}/axis_overrides.json`, 키는 안정 ID.
  정렬 키 고정 + 같은 값 재확정은 confirmed_at 유지 → 두 번 저장하면 같은
  파일.  구현 `app/axis_overrides.py`.
- **승계**: 다음 리비전에서 같은 안정 ID 가 매칭되면 확정 문장을 자동 승계
  (근거 패널에 "확정 승계" 표시).  ID 가 안 물리면 승계하지 않고, 그 리비전에서
  사람이 이미 고친 행은 덮지 않는다.
- **일괄 보조**: 같은 런으로 판정된 다른 ④ 행에 "같은 값 적용?"을 **제안만**
  한다 — 행마다 사람이 누른다.  런 판정 자체가 실패한 행은 제안하지 않는다.
- **감사**: 확정은 user_values 로 저장되므로 감사기의 "사람이 도면 값을
  덮어쓴 칸" 집계에 자동으로 잡힌다.  ai_values 는 그대로 남는다.

## 7회차 — 한쪽만 성립하는 FROM / TO (②a · ②b)

④ 618행을 끝점 판독으로 갈라 세면 **출발만 9 · 도착만 69 · 양쪽 실패 540**
이다.  읽힌 반쪽을 버리지 않고 쓰되, **없는 반대쪽은 지어내지 않는다.**

| 갈래 | 행 | 현행 공란이던 행 | 현행 문장이 있던 행 |
| --- | ---: | ---: | ---: |
| ②a 출발만 | 9 | 4 | 5 |
| ②b 도착만 | 69 | 38 (MOV 31 · BFV 4 · PNEUMATIC 3) | 31 |

- **같은 방향 커넥터가 둘이면 고르지 않는다** (실측 4행: p12 TIT 2 ·
  p16 FE·FIT 2).  양 끝이 다 `TO …` 인 경우 어느 쪽이 이 라인의 도착지인지
  도면이 말하지 않으므로, 하나를 고르는 것은 근거 없는 선택이다 → ④ 유지.
  이 규칙이 없으면 82행이 되고, 넣으면 **78행**이다.
- **분기가 먼저다** — `FROM` 하나 + 분기 2개 이상이면 ③ 이 ②a 를 가로챈다
  (기존 규칙 불변).

### ④→② 전환율 — **정의를 넓혔다**

라인 탭 문형이 성립한 비율이므로 한쪽만 성립도 성립으로 센다:
**(② + ②a + ②b) / (② + ②a + ②b + ④)**.

| 회차 | 정의 | 값 |
| --- | --- | ---: |
| 5·6회차 | ② / (② + ④) | 5.4% |
| **7회차** | **(② + ②a + ②b) / (… + ④)** | **17.3%** |
| (참고) 7회차를 옛 정의로 재면 | ② / (② + ④) | 6.1% |

## 8회차 — ②a · ②b 는 현행 문장이 없을 때만 쓴다

7회차는 한쪽만 성립한 78행 전부에 새 문형을 썼다.  8회차에 그중 **현행 문장이

가르지 않는다 (드레인·BD 같은 목록은 프로젝트 종속 어휘가 된다).

근거: 읽힌 반쪽은 라인이 **어디서 오고 어디로 가는지**만 말한다.  현행 문장은
계통(UNIT · 계통명 · 변수어)을 담고 있어, 반쪽 문형이 그것을 밀어낼 만큼 낫다고
말할 수 없다.  반대로 현행이 공란인 행에서는 없던 이름이 생기므로 명백히 낫다.

**판정은 그대로 기록하고 적용만 하지 않는다** — `evidence["axis"]` 에 축(②a/②b)과
`withheld` 사유가 남고, 문형 출처는 `현행유지` 다.  즉 ④→② 전환율(도면 벽의
측정 축)은 판정 기준이므로 **17.3% 그대로**다.
