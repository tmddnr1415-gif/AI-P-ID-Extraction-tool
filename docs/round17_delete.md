# 17회차 [E] — 이전 기록 삭제.  안정 ID 를 깨지 않는 범위에서만

## 요구

> 이전 기록 삭제 할 수 있는 기능 추가 요망  (2차 피드백 1장)

## ⚠ 먼저 답한 것 — 안정 ID 는 깨지는가

**§7.3 의 불변식**: 안정 ID(`10LBA10-001`)는 **Rev.A 에서 한 번만 부여하고
회수하지 않는다.**  깨지면 리비전 승계(13회차 `_carry_edits`)와 이미 나간
Excel 의 NO 가 어긋난다.

장부는 `app/_data/projects/{프로젝트}/id_registry.json` 이고, 번호를 내주는
곳은 `revisions.Registry.next_seq` 한 곳이다.  그 함수의 주석이 답을 이미
적어 두었다:

```python
def next_seq(self, code: str) -> int:
    """그 계통의 최대 순번 + 1.  삭제된 번호도 최대값 계산에 넣는다."""
    top = 0
    for rec in self.data["ids"].values():
        if rec["system_code"] == code:
            top = max(top, rec["seq"])
    return top + 1
```

**상태(`status`)를 보지 않는다.**  그러므로:

| 지우는 단위 | 안정 ID | 판단 |
| --- | --- | --- |
| **분석 하나(job)** | 장부 파일을 건드리지 않는다 → 번호가 그대로 남고 재사용되지 않는다 | **안전 — 구현했다** |
| 프로젝트 전체 | 폴더째 사라지면 장부도 사라진다.  같은 이름으로 다시 만들면 **번호가 1부터 다시 나간다** | **깨진다 — 구현하지 않았다** |

프롬프트의 진행 조건("깨진다면 구현하지 말고 보고한다")을 그대로 따랐다.
화면에도 프로젝트 전체를 지우는 버튼이 **없다**.

## 구현한 것

### 무엇을 지우는가

분석 하나(job)와 그 분석에 딸린 것 전부:
`item` · `revision_state` · `deleted_candidate` · `pid_page` · `revision` ·
`feedback` · `review_state` · `report` · `job`.

**건드리지 않는 것**: `app/_data/projects/…` 의 어떤 파일도 —
`id_registry.json` · `project.json` · `axis_overrides.json` ·
`legend_profile.json`.

### 지우기 전에 무엇이 사라지는지 보여 준다

`GET /jobs/{id}/deletion_preview` 가 세기만 하고 아무것도 바꾸지 않는다.

```
추출한 행 · 사람이 고친 칸 · 검토 표시 · 수정 이력 · 오류 신고 ·
산출물 스냅샷 · 쪽 수 · 업로드 PDF 를 함께 지우는지 · 안정 ID 장부는 그대로
```

### 확인을 두 번 받는다

1. 화면이 위 목록을 보여 주고 "되돌릴 수 없습니다" 를 말한 뒤 확인
2. **분석 id 를 그대로 옮겨 적어야** 서버가 받는다
   (`confirm` 이 다르면 400, 실측 확인)

분석 중(`queued`/`running`)인 것은 거절한다 — 먼저 취소해야 한다.

### 누가 언제 무엇을 지웠는지 남는다

새 테이블 `deletion_log` (가산 — `CREATE TABLE IF NOT EXISTS`).
작성자는 13회차와 같은 **자기신고**이고, 비우면 비운 채로 저장된다.
행은 사라져도 "누가 언제 무엇을 몇 행 지웠나" 는 남아야 다음 사람이 빈 자리를
설명할 수 있다.  `GET /deletions` 로 읽는다.

### 업로드 PDF

**그 분석만 쓰고 있을 때에만** 지운다.  다른 분석이 같은 파일을 가리키면
남긴다 (그 분석이 도면을 못 열게 되므로).  그리고 그 파일이 이 인스턴스의
`uploads/` 안에 있을 때에만 지운다 — 실측에서 다른 데이터 폴더에서 복사해 온
DB 로 시험하니 경로가 밖이라 **지우지 않고 `pdf_removed: false` 로 답했다.**
디스크 회수보다 "남의 파일을 지우지 않는 것" 이 먼저다.

## 하지 않은 것과 이유

| 항목 | 이유 |
| --- | --- |
| 프로젝트 전체 삭제 | 안정 ID 장부가 사라져 §7.3 이 깨진다 (위) |
| 리비전만 골라 삭제 | 지금은 **분석 = 리비전**이라 분석 삭제가 곧 리비전 삭제다.  둘이 갈리면 그때 |
| 되돌리기(휴지통) | 되돌릴 수 있으면 "되돌릴 수 없습니다" 를 말할 수 없다.  대신 지우기 전에 보여 주는 쪽을 택했다 |
| 여러 개 한 번에 | 실수의 크기를 키운다.  하나씩 지운다 |
