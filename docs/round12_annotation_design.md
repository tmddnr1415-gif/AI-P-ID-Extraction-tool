## 1. 어디에 저장하는가 — `app.db` 의 새 테이블

`app/_data/app.db` 안입니다.  세 가지가 자동으로 따라옵니다.

- **갈음 대상이 아닙니다.**  `app\_data\` 는 모든 회차의 갈음 금지 목록에 있고,
  주석도 그 안에 있으므로 코드를 덮어써도 지워지지 않습니다.
- 백업 절차가 이미 있습니다 (README 의 `app.db` · `-wal` · `-shm` 복사).
- 감사기(`app/audit.py`)와 진단 zip 이 이미 이 파일을 셉니다.

JSON 파일(`app/_data/annotations/*.json`)도 후보였으나 **택하지 않습니다**:
같은 도면을 두 사람이 동시에 보고 있을 때 마지막 저장이 앞의 것을 통째로
덮습니다.  SQLite 는 행 단위라 그 일이 없습니다.

```sql
CREATE TABLE IF NOT EXISTS annotation (
  id          TEXT PRIMARY KEY,      -- uuid4 hex 12
  job_id      TEXT NOT NULL,
  page_no     INTEGER NOT NULL,
  drawing_no  TEXT NOT NULL DEFAULT '',   -- 리비전 승계의 키 (§3)
  kind        TEXT NOT NULL,         -- 'LINE' | 'TEXT'
  geom_json   TEXT NOT NULL,         -- PDF 좌표 (§2)
  text        TEXT NOT NULL DEFAULT '',
  colour      TEXT NOT NULL DEFAULT '#c0271d',
  author      TEXT NOT NULL DEFAULT '',   -- §4
  created_at  REAL NOT NULL,
  deleted     INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS annotation_job ON annotation(job_id, page_no);
```

**마이그레이션은 없습니다** — `CREATE TABLE IF NOT EXISTS` 는 가산이고, 이
테이블을 모르는 옛 빌드가 같은 파일을 열어도 아무 일도 일어나지 않습니다.
`db._ADDED_COLUMNS` 를 건드리지 않습니다.

## 2. 좌표계 — PDF 좌표

화면 픽셀로 저장하면 확대·팬 뒤에 어긋납니다.  검출 상자(`row.rect`)가 이미
PDF 좌표이고, 오버레이가 `scale = 자연폭 / page.width` 하나로 그것을 그립니다.
주석도 **같은 좌표계 · 같은 변환**을 씁니다.

```
LINE  {"x0":.., "y0":.., "x1":.., "y1":.., "w": 1.5}
TEXT  {"x":.., "y":.., "size": 11}       size 는 PDF 포인트
```

화면 → PDF 변환은 이미 있습니다 (`sheetPoint(ev)` — 미검출 신고가 쓰는 함수).
새 변환을 만들지 않습니다.

## 3. 리비전이 바뀌면 — **판단 필요**

주석은 job(=리비전)에 붙습니다.  Rev.B 는 새 job 이므로 그대로 두면 Rev.A 의
주석이 안 보입니다.  세 안이고, 어느 것도 기술적으로 어렵지 않습니다.

| 안 | 동작 | 좋은 점 | 나쁜 점 |
| --- | --- | --- | --- |
| (가) Rev.A 에만 남는다 | job 단위 | 그 리비전에 한 말이 그 리비전에만 남는다 | Rev.B 에서 같은 말을 다시 써야 한다 |
| (나) 자동 승계 | `drawing_no` 가 같은 페이지로 복사 | 다시 안 써도 된다 | **도면이 바뀐 자리에 옛 주석이 남는다** — 그 자리가 개정된 부분이면 정반대를 말한다 |
| (다) 승계하되 표시 | 복사하되 "Rev.A 에서 옮겨 옴" 을 붙인다 | 둘 다 | 화면에 층이 하나 는다 |

**권고는 (다)** 입니다 — §7.3 이 삭제 후보를 자동 확정하지 않고 사람이 굳히게
한 것과 같은 판단(승계는 하되 출처를 남긴다)입니다.  다만 **정하지 않았습니다.**

## 4. 작성자 — 이 앱에는 신원이 없다

로그인도, 세션도, 사용자 테이블도 없습니다.  서버가 아는 것은 IP 뿐이고 그것은
사람 이름이 아닙니다.  **없는 값을 지어내지 않습니다** (§2.1 ③).

| 안 | 동작 | 비고 |
| --- | --- | --- |
| (가) 안 남긴다 | `author` 를 빈 칸으로 | 지금 상태 그대로. 나중에 되짚을 수 없다 |
| (나) 브라우저마다 한 번 묻는다 | 첫 주석 때 이름을 받아 `localStorage` 에 둔다 | 자칭이고 검증되지 않는다. 그래도 없는 것보다 낫다 |
| (다) 로그인을 만든다 | 별도 회차 | 사내망 단일 서버라 지금 필요한지 불확실 |

**권고는 (나)** 이고, 그 경우 화면에 "자칭입니다" 를 적어야 합니다 — 검증된
신원처럼 읽히면 그것이 더 나쁩니다.  **정하지 않았습니다.**

같은 문제가 이미 대기 목록에 있습니다: "작성자 이름 열 — 누가 확정했는지 남지
않는다".  둘을 **같이** 정하는 것이 맞습니다.

## 5. Excel 산출물 영향 — 없음

`excel_out.write_all` 은 `snapshot["rows"]` 만 읽습니다.  주석은 행이 아니므로
어느 열에도 닿지 않고, `unmapped_values` 에도 들어가지 않습니다.
`in_client_scope` 필터와도 무관합니다.

## 6. 붉은색 — 실측

크림 배경(`--paper #f7f2e6`) 위 대비, WCAG 2.1:

| 색 | 크림 위 | 도면(흰 바탕) 위 |
| --- | ---: | ---: |
| `#ff0000` (순정 red) | 3.58 | 3.43 |
| `#d1332a` | 4.46 | 4.28 |
| **`#c0271d`** | **5.30** | **5.92** |

**`#c0271d` 를 권합니다** — 두 바탕 모두에서 4.5 를 넘는 유일한 후보이고,
§7.2 가 어두운 판의 개정 3색을 크림 위에서 다시 고른 것과 같은 절차입니다.
(12회차의 `분석 취소` 버튼이 이미 이 색을 씁니다.)

## 7. 오버레이와 섞이지 않게

주석은 검출 상자와 **다른 층**에 그립니다: 검출은 테두리만 있는 사각형,
주석은 **채운 선과 글자**입니다.  표시 범례에 주석 켜기/끄기를 한 줄 더해
(§7.2 의 네 층과 같은 방식) 필요할 때 치울 수 있게 합니다.
