# 전역 심볼 사전 — 18회차 [D]

> 요구 원문: *"Symbol & Legend 에 없어서 추출되지 않는 경우는 해당 Symbol 을
> 그냥 모든 PJT 에 적용될 수 있도록 해당 심볼을 저장한다. 매번 렌더링하지
> 않고."*

**이 회차는 등록 화면까지 만들고 실제 등록은 하지 않는다.**  그 심볼이
무엇인지 Claude 가 정하면 §2.1 ③("도면에 없는 낱말을 만들지 않는다")
위반이다.  그래서 아래 어디에도 "이것은 아마 XV 입니다" 가 없다.

---

## 1. 먼저 답한 것

### ⓐ "범례에 없어 판정 못 한 심볼" 을 지금 어디에 기록하나 — **어디에도 안 한다**

조사 결과가 이 회차의 첫 발견이다.

| 갈래 | 검출기가 내고 있었나 | 파이프라인이 받았나 |
| --- | --- | --- |
| 계기 · 사전에 없는 태그 | `ds.detect` 의 `unmapped` — **낸다** | 받아서 **버린다** |
| 계기 · 버블 기하 미검증 | `ds.detect` 의 `unverified` — **낸다** | 받아서 **버린다** |
| 밸브 · 몸체가 못 된 중공 도형 | **안 낸다** | — |

즉 두 갈래는 **이미 있었고 화면까지 가는 길이 없었다** (13·15·16회차와
같은 모양 — *없는 것을 만들기 전에 있는 것을 찾는다*).  세 번째만 새로
세는 함수가 필요했다.

### ⓑ 58장에 그런 심볼이 몇 개인가 — **236건 · 3갈래**

`out/round18/5_미판정심볼.csv` (전량).

| 갈래 | 건수 | 상위 표기 |
| --- | ---: | --- |
| 계기 · 사전에 없는 태그 | **89** | ZSO 11 · ZT 9 · PP 8 · ZSC 7 · YSR 5 · YSA 5 · HS 5 · ZS 5 · ZOCL 4 · AIT 4 |
| 밸브 · 분류되지 않은 몸체 후보 | **84** | 전부 `3선분 중공` · 24장 (p42 14 · p40 10 · p41 10 · p33 6 · p55 6 …) |
| 계기 · 버블 기하 미검증 | **63** | PIT · RO 등 |

**밸브 84건은 전부 삼각형 하나**다.  [E] 가 ANGLE(두 삼각형이 꼭짓점을
맞댄 것)을 구현한 **뒤에** 센 값이므로, 짝을 이루는 것들은 이미 빠져 있다.
남은 84개가 무엇인지는 **이 회차에서 정하지 않는다.**

### ⓒ 그 심볼의 무엇을 저장해야 다음 프로젝트에서 알아볼 수 있나 — **아직 모른다.  그래서 저장만 하고 쓰지 않는다**

이것이 이 회차에서 **스스로 좁힌 범위**다.

형상으로 알아보는 길은 §3 에 실패 기록이 둘 있다 — 범례 기기 형상으로
도면 기기 검출(펌프 **0개** · 잡음 161건) · 범례 STRAINER 형상으로 중간
심볼 검출(글자 외곽선만 매칭).  원인은 같다: **단일 축척이 없다**
(범례 40.5×38.5 ↔ p26 46.2×44.0, 비율 ×0.42~×2.00).  16회차가 같은
결론을 다시 냈다 — *"범례는 뜻을 정하지 축척을 정하지 않는다"*.

그래서 `signature` 칸은 **등록할 때 사람이 본 것을 그대로 담기만 한다**
(라벨 · 사유 · 좌표 · 사각형).  검출이 그것을 읽는 코드는 **없고**,
시험이 그것을 강제한다:

```
test_the_engine_never_reads_the_global_dictionary_to_decide
    app/engine/*.py 어디에도 global_symbols 가 없다
```

닿게 하면 **지문이 사람이 누른 것에 따라 달라진다** — 회귀 기준선이
성립하지 않는다.  다음 회차에서 "무엇으로 알아볼 것인가" 에 답이 서면
그때 잇는다.

## 2. 만든 것

| 자리 | 무엇 |
| --- | --- |
| `app/global_symbols.py` | 사전 파일 하나 — 담기 · 되읽기 · 지우기 · 끄기 · 우선순위 |
| `app/_data/global_symbols.json` | 저장 위치.  **소스 트리가 아니다** (갈음 때 사라지면 안 되고, 15회차 프로젝트 프로필이 같은 뿌리에 산다) |
| `detect_valves.unclassified_bodies` | 몸체가 못 된 중공 도형을 **세는** 함수.  `find_bodies` 는 부르지 않는다 |
| `pipeline` 의 `unjudged` | 세 갈래를 모아 `engine_json["unjudged_symbols"]` 로 남긴다 |
| `GET /jobs/{id}/unjudged` | 등록 화면이 읽는 목록.  **다시 세지 않는다** (58장 재독 3분) |
| `GET/POST /symbols/global` · `DELETE /symbols/global/{id}` · `POST /symbols/global/enabled` | 사전 API |
| 머리줄 `심볼 N` 버튼 → 등록 화면 | 목록 → 등록 폼 → 작성자 확인 → 저장 |

### 등록 절차 (요구 4단계 그대로)

1. **모아 보여준다** — 종류+표기로 묶어 건수·페이지와 함께.  같은 모양이
   24장에 나오면 한 줄이다 (사람이 같은 판단을 84번 하지 않게).
2. **사람이 지정한다** — 이름 · 종류 · TYPE · 산출물 배분 · 비고.
   **전부 빈 칸으로 연다.**  채워 두면 사람은 확인하지 않고 넘긴다.
3. **확인을 받는다** — 이름이 비면 화면이 막고, 서버가 또 막는다
   (`register()` 가 `ValueError`).  두 겹인 이유는 화면을 지나쳐도
   (curl 로도) 들어가면 안 되기 때문이다.
4. **누가 언제 남는다** — 13회차 작성자 기록(`askAuthor`)을 그대로 쓴다.
   자기신고이고 화면이 "자칭" 이라고 적는다.  **비우면 등록되지 않는다** —
   13회차의 편집 기록과 다른 점이 여기 하나다 (편집은 비워도 저장된다).

## 3. 지킨 금지 — 어떻게 지켰는지가 시험이다

| 금지 | 어떻게 막았나 |
| --- | --- |
| ★ 자동 등록 | `register()` 가 `author` 를 요구하고, **부르는 곳이 `app/main.py` 한 곳**임을 소스 검사가 강제 (`test_only_one_place_in_the_tree_registers_a_symbol`) |
| ★ 심볼의 뜻을 Claude 가 정하기 | 화면·서버 어디에도 기본값·추천값이 없다.  `unclassified_bodies` 의 `label` 은 `3선분 중공` — **모양을 세는 말이지 이름이 아니다** |
| 검출 로직 변경 | `unclassified_bodies` 를 `find_bodies` 가 부르지 않음 (소스 검사).  **지문 불변** |
| 표준 사전에 프로젝트 표기 혼입 | 끄는 스위치 하나로 전량 무시되고, 그때 결과는 사전이 없던 때와 **정확히 같다** (읽는 곳이 `active()` 하나) |
| 실 DB 열기 | 17회차 `conftest.py` 그대로.  시험은 `tmp_path` 에만 쓴다 |

**우선순위**: ① 그 프로젝트 범례(15회차 프로필) → ② 전역 사전.
`resolve(..., legend_has=True)` 는 `None` 을 돌려준다 — 범례는 그 문서의
약속이고 사전은 업계의 관행이라, 둘이 다르면 **그 문서가 이긴다**.

## 4. 하지 않은 것 (다음 회차 후보)

1. **사전이 검출에 닿는 길** — ⓒ 참조.  "무엇으로 알아볼 것인가" 에
   답이 서기 전에는 잇지 않는다.
2. **84건이 무엇인지** — 사용자가 등록 화면에서 지정할 몫이다.
   내가 정하면 §2.1 ③ 위반이고, 이 문서가 그것을 하지 않은 기록이다.
3. **계기 태그 89건의 사전 등록** — `anchors.type_map` 은 프로젝트
   config 이고 전역 사전과 층이 다르다.  ZSO·ZT·ZSC 계열이 어느 층에
   속하는지(업계 표준인가 이 발주처 표기인가)는 **실무 판단**이다 (§14.3).
