# [D] UAD 개정 0/32 → 23/32 — 개정 **표기의 모양**도 도면에서 읽는다

## 1. 예상과 실제가 달랐다

29회차 §5.3 은 *"REV 칸·이력 표가 SHX 라 글리프 사전이 비고, 비면 이름을
붙일 수 없다 — 24회차 TC2 와 같은 모양"* 이라고 적었다.  **틀렸다.**

실측 (UAD p19 · `rev_box` 는 이미 유도돼 있다 `[1148.0, 784.0, 1171.8, 807.0]`):

```
(791.0, 1150.0, 1158.0, 'SHX', '6')      ← REV 칸.  값이 활자로 있다
(783.0, 1148.0, 1160.0, 'SHX', 'REV.')   ← 그 칸의 캡션
이력 표 REV 열:  '2' 23.MAY.2025 / '1' 26.FEB.2025 / '0' 31.DEC.2024
```

즉 28회차의 SHX 경로는 **이미 REV 값을 낱말로 들여오고 있었다**.
자리도 맞았다 (`x0-2 <= 1150 <= 1171.8` · `y0-6 <= 791 <= 807`).

## 2. 진짜 원인 — 개정 **형식**이 외워둔 값이었다

```yaml
# config/project_alnouf1.yaml
formats:
  revision: '^[A-Z][0-9]?$'
```

`has_titleblock_text` 는 이 정규식으로 거른다.  **UAD 는 개정을 숫자로
매긴다** — `6` 은 이 식에 안 맞아 버려졌고, 글리프 경로로 흘렀다.
그 경로는 이력 행을 `A`·`B`·`C`… 로 **순서 이름**을 붙이므로(`rank`),
숫자로 매기는 문서에서는 구조적으로 틀린다 — 결과가 `G1` (32장 전부 LOW).

**§9-2 의 "외워둔 값" 이다** — AL NOUF1 에서 잰 것을 옮겨 적어 두고
`out/constants_by_source.md` 의 A~E 분류에 들어 있던 항목이다.

## 3. 고친 방법 — 이력 표가 그 문서의 개정 표기 목록이다

`derive_layout._history_rev_marks` + `_revision_pattern` (24회차가 이미
유도해 둔 `hist_rev_col`·`hist_date_col`·`hist_rule_y` 를 그대로 쓴다).

```
이력 표 REV 열의 낱말 중, **같은 행의 DATE 열이 날짜인 행**의 것만 받는다
  → UAD: 0 1 2 3 4 5 6 7      (모양이 전부 D1)
  → 유도값 formats.revision = ^[0-9]$
```

* **머리글 행을 섞지 않는 장치가 날짜다.**  머리글 행은 REV 열에 `REV.`,
  DATE 열에 `DATE` 를 찍는데 `DATE` 는 날짜가 아니다.  `formats.date`
  (`^\d{1,2}\.\s?[A-Z]{3}\.\d{4}$`)를 그대로 재사용했다 — UAD 의
  `23.MAY.2025` 가 그 식에 맞는다.
* **넓히지 않는다.**  읽은 표기의 모양이 하나뜻이면 그 모양만 받고
  (`D`→`^[0-9]$`), 여럿이면 읽은 표기를 그대로 나열한다.  읽지 않은 모양을
  추측으로 더하지 않는다 (§2.1 ③).
* **못 읽으면 유도하지 않는다.**  AL NOUF1·TC2·SADARA 는 이력 표 REV 열이
  **획으로 그려져** 낱말이 0개다 → 유도 항목이 없고 설정값이 그대로 쓰인다.
  사유를 `notes` 에 적는다.

### 같이 고친 것 — 정규식 셋을 다시 만든다

`formats.*` 세 정규식은 `extract_titleblocks` 가 **import 때 한 번**
compile 한다.  유도값을 config 에 얹어도 다시 만들지 않으면 옛 식이 계속
쓰인다 — 22회차가 `pidcache` 전역에서 겪은 함정과 같은 자리다.
`pipeline._rebind_config` 에 세 줄을 더했다 (`DWG_NO_RE`·`DATE_RE`·
`REV_TEXT_RE`).  뒤의 둘은 지금 유도되지 않으므로 값이 같다 — **덫만 없앤다**.

## 5. ⚠ 23/32 이고 32/32 가 아니다 — 남은 9장

| 장 | 상태 |
| --- | --- |
| p1 · p11~p15 · p17 · p18 · p22 | `page_kind: UNKNOWN` · 도면번호 빈칸 · GLYPH `71` MEDIUM |

이 아홉은 **표지·목록 시트**다 (그래서 도면번호도 비어 있고 행도 0이다).
그 장들의 타이틀블록은 P&ID 장과 형식이 달라 REV 칸에 값이 없고, 글리프
경로가 엉뚱한 두 글자를 읽어 `71` 을 낸다.  **행에 닿지 않는다**
(분석 대상이 아니다) 는 것을 확인했고, 축3 분모가 "전체 장" 이므로 점수에는
남는다 — **분모를 바꾸지 않는다** (§2.2 측정 정의 변경 금지).

다음 회차 후보: 표지·목록 시트에서는 개정을 **읽지 않았다고 말하는 것**
(`NONE`)이 `71` 보다 정직하다.  다만 그것은 "이 장이 도면인가" 판정에
매달리므로 별도로 잰다.

## 6. 이것도 "찾고 있는데 안 쓰던 것" 이었나

**반쯤 그렇다.**  SHX 낱말은 28회차가 이미 들여오고 있었고 자리도 맞았다 —
막은 것은 **형식 정규식 한 줄**이었다.  즉 *도면이 말하고 있었고 코드가
받기까지 했는데, 외워둔 형식이 그것을 버렸다.*
