## 스스로 뒤집은 판단

1. **"022·026·027 이 EXPLODE 됐다" → 아니다.**  020·022·027 은 엔티티의 82~88% 가 `PDF_*` 층에
   있다 — AutoCAD **PDFIMPORT** 로 다시 들여온 장이다 (026 만 진짜 풀린 기하).  그래서 그 장은 **글자가
   없다** (022 는 ISA 꼴 TEXT 0) — 폴백이 있어도 이름을 줄 수 없다.
2. **"두 체계" 는 셋이다.**  ① 블록+속성 (p6~p15 · p19~p31) ② `AS_INST` 블록만 + TEXT (p16~p18)
   ③ PDF 임포트/풀린 기하 (p8·p9·p20·p22·p26·p27).  ②의 블록은 범례에 없다 → 범례 계기 원과 같은
   반지름을 그린 블록으로 2급 (사유 `DXF_BLOCK_NOT_IN_LEGEND`).
3. **속성 역할 첫 판이 스코프 선을 계기로 만들었다** — `SCT`·`AG`·`UG` 가 ISA 글자로 풀린다.
   TYPE 역할은 **같은 블록에 태그 역할 속성이 짝으로 있을 때만** (범례 p4 의 ATTDEF 쌍 구조).
4. **캡션 첫 판이 옆 열 글자를 주웠다** ('Gate Valve' → `PLUGGED PIPE OR VALVE`).  심볼 중심을 품는
   줄 + **구획 머리말**로 바꿨다 — 그러자 밸브 15 · 액추에이터 9 · 계기 12 가 범례대로 섰다.
5. **프레임 80% 규칙이 6장을 놓쳤다** (틀 밖에 흘린 도형이 모델 범위를 4배로).  "가장 큰 블록" 으로.
6. **모델스페이스 ATTDEF 는 풀린 속성이다** — 보이는 글자가 태그 이름.  p8·p9·p21 의 `LIT`·`PDIT` 가
   거기 있었다 (p11 은 317개).
7. **ISA 표 succeeding 0 의 원인은 조각(tokens)이 아니라 표의 판이다** — UAD 범례는 `TYPICAL SYMBOL`
   머리줄 대신 `( ) AL`·`( ) K` 칸 한 줄을 찍는다.  PDF 경로 불변 게이트라 DXF 쪽에 두었다.

## DXF 에서도 막힌 것 — 무엇이 있으면 풀리는가

- **PDF 임포트 장 (020 · 022 · 027)** — 글자가 획이 됐다.  풀리려면 **원본 DWG** 로 다시 저장해야 한다.
- **p8 · p9 (연료가스 공급자 패키지)** — 계기 버블이 블록이 아니라 풀린 기하 + ATTDEF 글자.  폴백이
  5·4행을 냈고 PDF 는 18·16행 — 닫히지 않은 폴리라인/호로 그린 버블을 폴백이 못 센다 (다음 회차).
- **Description** — 배관·기기 라벨 읽기가 PDF 캐시 전제.  DXF 는 선분이 LINE/LWPOLYLINE 이라 오히려 쉽다
  — 정규 표현 층으로 PDF 를 옮기는 다음 회차 몫.
