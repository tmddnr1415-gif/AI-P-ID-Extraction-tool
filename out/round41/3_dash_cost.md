### UAD 도 SHX 인데 왜 TC2 만 느린가
| | UAD p6 | TC2 p2 | TC2 p10 |
| --- | ---: | ---: | ---: |
| 토막 | 11,354 | 20,926 | 22,656 |
| 끝점 | 22,708 | 41,852 | 45,312 |
| **유일점** | — | **8,283 (20%)** | **10,410 (23%)** |
| tol 이내 쌍 | (작음) | 22.8M | 39.1M |
| 장당 | 1.6초 | 18.9초 | 23.9초 |

★ TC2 의 SHX 획은 **꼭짓점을 공유**한다 — 끝점 41,852 중 유일점이 8,283 뿐이다.  같은 자리에 끝점이 수백 개
모이면 "tol 이내 쌍" 이 그 자리마다 k² 로 불어 22.8M 이 되고, 파이썬 union-find 가 그 쌍을 하나씩 훑는다.
UAD 는 토막이 절반이고 공유 꼭짓점이 적어 쌍이 적다.  40회차의 진단("SHX 획 22,640 토막")은 수는 맞았고
이유는 반만 맞았다 — 토막 수가 아니라 **공유 꼭짓점의 k²** 이다.

### 메모리 7.2 → 8.9G 의 1.7G
장당 최고 405~417MB(tracemalloc) 는 칸 거리 행렬(최대 칸 1,496점 × 이웃 ~10k점 × 8B ≈ 120MB)과
쌍 배열(22.8M × 8B × 2 = 365MB)이다.  장이 끝나면 놓지만 numpy 큰 배열의 반복 할당이 RSS 최고 수위를 올린다.

## B-2 고친 것 — 같은 답을 더 싸게
1. **유일점으로 접는다** (`_unique_endpoints`): 거리 0 인 끝점은 어떤 허용치에서도 이웃이므로 먼저 합쳐도 답이 같다.
   쌍 22.8M → **640k** (p2) · 39.1M → 1.1M (p10).
2. **잇기는 numpy 라벨 전파** (최솟값 + pointer jumping · `_link_pieces`) — 파이썬 union-find 를 없앤다.
3. 틈 최빈도 유일점으로 잰다 — 주인이 둘 이상인 점의 끝점은 다른 토막이 거리 0 에 있으므로 옛 계산과 같이 최빈에서 빠지고,
   주인이 하나인 점은 자기 토막의 반대쪽 끝점만 빼고 잰다 (옛 값과 같음을 시험이 본다).
