# hotfix50 — 부서 대시보드 안에 P&ID 분석 넣기

요구: *"입찰/실행 프로젝트를 누르면 하위 메뉴로 P&ID 분석이 뜨고 그 P&ID 분석은 내가 개발한
프로그램을 돌리고 싶다."*  (부서 대시보드 폴더 사진 · `DASHBOARD_ARCHITECTURE.md` 첨부)

**엔진 0줄.**  판정 · 지문 · 저장 · Excel 은 그대로이고 다시 분석할 필요가 없습니다.

## 1. 왜 대시보드 폴더에 넣지 않나

대시보드는 표준 라이브러리 Python + HTML 한 파일이고 pip 가 금지돼 있습니다.  `apps/` 는 정적 파일
자리라 이 프로그램(FastAPI · PyMuPDF · numpy)이 돌 수 없습니다.  그래서 이 프로그램은 같은 PC 에서
**따로 서버로 돌고**(포트 8000) 대시보드는 iframe 으로 보여 줍니다 (대시보드 문서 §7 방법 B).
**대시보드 운영 폴더에 넣을 파일은 없습니다.**

## 2. 막혀 있던 것 넷과 고친 것

| 막힌 것 | 고친 것 |
| --- | --- |
| `start.bat` · `run.sh` · exe 가 전부 `127.0.0.1` 에만 열림 → 다른 PC 의 iframe 은 빈칸 | `--lan` 이면 `0.0.0.0` (세 실행기 모두) · 다른 PC 가 들어올 주소를 PC 이름 · IP 로 출력 |
| exe 가 빈 포트를 골라 씀 → 대시보드가 주소를 적어 둘 수 없음 | 사내망 모드는 **8000 고정**, 쓰고 있으면 사유를 말하고 멈춤 |
| 사내망에 여는 순간 "루프백만" 제한이 사라짐 | `app/lan.py` 문지기 — 대시보드 서버와 **같은 규칙**(루프백 · 사설망 · 이 PC 의 /16 · `PID_ALLOW`), 그 밖은 403.  대역은 코드에 적지 않고 이 PC 주소에서 잰다 |
| 대시보드 메뉴 안에 이 화면의 메뉴가 또 들어감 | `?embed=1` — 왼쪽 메뉴를 숨기고 결과 탭을 결과 머리 아래 줄로 옮김 (`buildTabs` 그대로) |

같이 넣은 것 둘: `?user=이름`(편집 작성자 미리 채움) · `?mode=bid|epc`(새 프로젝트를 입찰/실행으로 시작 —
장부에 작성자와 함께 적힘 · 이미 있는 프로젝트는 안 건드림).

대시보드가 "P&ID 서버가 살아 있나" 를 물을 자리로 **`/version` 하나만** 출처를 가리지 않게 했습니다
(`Access-Control-Allow-Origin: *`).  버전 정보뿐이고 다른 경로에는 이 허용이 없어 대시보드가 이쪽 데이터를
읽어 갈 길은 열리지 않습니다 (시험이 `/projects` 에 그 머리말이 없음을 확인).

## 3. 운영 스크립트 (Windows · CRLF)

| 파일 | 하는 일 |
| --- | --- |
| `run_lan_service.bat` | 사내망 · 8000 으로 켜고, 멈추면 10초 뒤 다시 켬.  옆에 exe 가 있으면 exe, 없으면 `start.bat` |
| `install_autostart_lan.bat` | 작업 스케줄러에 로그온 시 시작 등록(이 사용자 · 관리자 불필요) + 지금 한 번 켬 |
| `uninstall_autostart_lan.bat` | 등록 해제.  **python 을 일괄 종료하지 않는다** — 대시보드 서버도 python 이다 |
| `open_firewall_8000.bat [대역]` | 관리자 권한 · TCP 8000 인바운드 (로컬 서브넷 · 사설망 + 인자로 준 대역) |

자동 시작 창에는 사람이 없으므로 exe 가 실패해도 Enter 를 기다리지 않는다 (`PID_NO_HOLD=1`).

## 4. 띄워서 확인 (`spike/ui_audit_embed.py` → `ui/`)

데이터 폴더 **사본**으로 서버를 사내망 모드(0.0.0.0 · `PID_LAN=1`)로 띄우고, 대시보드를 흉내 낸 페이지를
**file://** 로 열어(부서원 사본과 같은 출처 `null`) iframe 에 `http://192.0.2.2:<포트>/?embed=1&mode=bid&user=홍길동`.

| 확인 | 결과 |
| --- | --- |
| file:// 페이지의 `/version` fetch | `ok 1.0.0` (CORS 통과) |
| iframe 안 — 메뉴 숨김 · 왼쪽 여백 | 숨김 · `0px` · 가로 스크롤 없음 |
| 이름 · 도면 종류 · 안내 줄 | `홍길동` · `bid` · "입찰 프로젝트 메뉴에서 열림 — 새 프로젝트는 입찰로 시작합니다" |
| 결과 화면 | 1,133행 · 결과 탭 6개가 `#embed-tabs` 안 · 탭 누름 → `FIELD` |
| `← 첫 화면` 뒤 주소 | `?embed=1&mode=bid&user=…` 그대로 (예전 코드는 query 를 지웠다 — 고침) |
| 새 프로젝트 `EMBED_TEST` | 장부 `mode: bid · author: 홍길동` |
| 대시보드 없이 직접 열기 | 예전 그대로 (메뉴 보임 · embed 아님) |
| 페이지 오류 | 0 |

⚠ 첫 화면의 `NaN-NaN-NaN` 날짜는 **픽스처**(`spike/build_ui_db.py` 가 `created_at` 을 문자열 · `finished_at` 을 0 으로
적음) 때문이고 실제 분석 기록은 숫자라 안 생긴다.

## 5. 시험

* `tests/test_hotfix50_dashboard_embed.py` 10건 — 접근 규칙(허용/거절 16개 주소 · IPv4-mapped · 못 읽는 주소) ·
  `PID_ALLOW` 파싱 · 문지기는 사내망 모드에서만 · `/version` 만 출처 허용 + 사내망 모드에서 바깥 주소는 그것도 403 ·
  세 실행기의 `--lan` · 서비스 스크립트가 CRLF 이고 python 을 일괄 종료하지 않음 · EMBED 는 읽기만(대시보드로
  보내는 것 없음) · 첫 화면이 query 를 지키는가 · 새 프로젝트 모드 PATCH 순서 · 메뉴 숨김 CSS.
* 빠른 시험 780 → **790** 통과.

## 6. 못 잰 것

* **Windows 에서 bat 를 실제로 돌리지 못했다** (이 환경은 Linux).  `schtasks` · `netsh` 명령과 인용은 문서대로
  적었고, 처음 한 번은 회사 PC 에서 창 메시지를 보며 확인해야 한다.
* 회사망의 실제 주소(65.3.x.x)에서 403 이 안 나는지 — 같은 규칙을 시험에서 `65.3.30.234` 로 재현했다.
* 대시보드 쪽 `dashboard.html` 은 이 저장소 밖이라 고치지 않았다 — 프롬프트를 `docs/dashboard_embed.md` 에 두었다.
