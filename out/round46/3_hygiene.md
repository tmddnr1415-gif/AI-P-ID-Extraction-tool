# [B] 데이터 위생 경고 — 무엇이고, 무엇을 했나

## 1. 그 경고가 가리키는 것의 정의 (코드에서)

| 화면 문구 | 실제 조건 | 어디 |
| --- | --- | --- |
| 사람이 도면 값을 덮어쓴 칸 | `user_json[field] != ai_json[field]` | `audit.provenance` |
| **도면 근거 없는 행** | `item.added = 1` (removed·deleted 아님) | 〃 |
| 고아 업로드 | `uploads/` 의 파일 중 어떤 `job.pdf_path` 도 안 가리키는 것 | `audit.leftovers` |
| **고아 출력** | `outputs/rev<N>/` 인데 `revision` 표에 그 id 가 없음 | 〃 |
| 고아 진단 | `diagnostics/` 의 zip 중 대응 job 이 없는 것 | 〃 |

`added=1` 행이 생기는 길은 **둘뿐**입니다 — 예전 `＋행`(지점만 받던 것)과
44회차 **마크업**(사각형 · 제안값 · 작성자).  둘 다 `ai_json` 이 전부 `null`
이므로 *도면이 그 행을 대지 못한다*는 뜻이고, **결함이 아니라 사실**입니다.

## 2. 이 작업 환경에서는 재현되지 않습니다

읽기 전용으로 실 DB(`app/_data/app.db`)를 열어 셌습니다.

```
job 4개 · 산출 대상 2,547행 · added=1 행 0 · revision 0 · outputs/ 비어 있음
```

즉 화면 캡처의 값(`job 17개 · 10,702행 · 근거 없는 행 5 · 고아 출력 1 ·
DB 63.8MB`)은 **회사 PC 의 DB** 입니다.  여기서 그 다섯 행이 무엇인지
직접 볼 수는 없습니다 — **그래서 화면이 스스로 말하게 고쳤습니다.**

## 3. ★ 서버는 이미 답을 갖고 있었고 화면이 총계만 보였습니다 (19번째)

`audit.run()` 은 처음부터 **job 단위 개수**(`provenance.jobs[].hand_added_rows`)와
**고아 파일 이름**(`leftovers.orphan_outputs` 등)을 내고 있었습니다.
`summary()` 가 그것을 합계 두 줄로 접었고, 화면은 그 두 줄만 그렸습니다.

고친 것:

* `audit.hand_added(con)` — 그 행들을 **한 행씩** 냅니다:
  PDF · 프로젝트 · 장 · TYPE · SCOPE · **작성자 · 시각 · 분류 · 메모**.
  마크업으로 넣은 행이면 44회차가 남긴 `evidence.markup` 에서 그대로 읽고,
  옛 `＋행` 이면 **작성자 기록이 없다고 말합니다** (지어내지 않습니다).
* 화면(`auditDetail`)이 그 목록과 고아 파일 이름을 펼칩니다.
* **감사기는 여전히 아무것도 지우지 않습니다** — 시험이 소스에서
  `os.remove`·`rmtree`·`DELETE FROM` 이 없음을 강제합니다
  (⚠ 머리말이 "없다" 고 적고 있어 글자로 세면 자기 설명에 걸립니다 —
  44회차와 같은 함정이라 AST 로 문서 문자열을 빼고 셉니다).

## 4. 네 질문에 대한 답

1. **"도면 근거 없는 행 5" 가 무엇인가** — 회사 PC 에서 이제 화면이
   그 다섯 행을 이름으로 보여 줍니다.  44회차 [H] 17단계 검증은 **격리
   폴더(`PID_DATA_DIR`)에서** 돌았으므로 실 DB 에 흔적을 남기지 않습니다
   (그 단계의 sha256 대조가 그것을 증명합니다).  그러므로 **검토자 입력일
   가능성이 높지만, 단정하지 않고 화면이 작성자·시각을 보여 사람이 가릅니다.**
2. **"고아 출력 1"** — `outputs/rev<N>` 인데 그 revision 이 DB 에 없는 것입니다.
   분석을 지웠거나 리비전 대장이 갈린 경우이고, **결과에는 닿지 않습니다**
   (Excel 은 그때그때 다시 씁니다).  이름이 화면에 나옵니다.
3. **정리 절차** — 감사기에는 삭제가 없습니다(방침 `docs/db_hygiene.md` 의
   (가)만 승인).  파일을 지우는 길은 이번 회차 [C] 의 **프로젝트 삭제**뿐이고,
   그쪽은 무엇이 지워지는지 먼저 보이고 확인을 한 번 더 받습니다.
4. **회사 PC 에서도 뜨는가** — 뜹니다(그 캡처가 그것입니다).  이제 화면이
   *무엇을 해야 하는지*도 적습니다: 검토자가 넣은 행이면 그대로 두고(산출물
   REMARK 에 `사용자 추가` 로 나갑니다), 시험 흔적이면 그 분석에서 지웁니다.

**게이트**: 엔진 파일 0개 · 네 프로젝트 지문 불변 (읽기 전용 감사와 화면만).
