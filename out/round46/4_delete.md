# [C] 프로젝트 완전 삭제

## 1. 지금 무엇이 남았나 (고치기 전)

* 지우는 단위는 **분석 하나(job)** 뿐이었습니다 (17회차 [E]).  그것도
  미리보기 · 이름 확인 · `deletion_log` 를 이미 갖추고 있었습니다.
* **프로젝트 단위 삭제는 일부러 만들지 않았습니다.**  17회차가 주석에 그 이유를
  적어 두었습니다 — 프로젝트 폴더에 **안정 ID 장부**(`id_registry.json`)가 있고,
  그것이 사라지면 같은 이름으로 다시 만든 프로젝트가 번호를 1부터 다시 내어
  §7.3("Rev.A 에서 한 번만 부여 · 회수하지 않는다")이 **실제로 깨집니다**.
* 그래서 분석을 전부 지워도 **첫 화면의 프로젝트 항목은 남았습니다** —
  `GET /home` 이 `projects/<이름>/project.json` 을 읽기 때문입니다.
  사용자가 본 것이 이것입니다.

## 2. 고친 방법 — 불변식을 지키면서 사라지게

`DELETE /projects/{name}` (미리보기 `GET /projects/{name}/deletion_preview`)

| 대상 | 처리 |
| --- | --- |
| 분석 · 행 · 편집 · 마크업 · 검토 · 수정이력 · 리비전 스냅샷 | **지웁니다** (`db.delete_project` → 분석마다 `delete_job`) |
| 업로드 PDF | 다른 분석이 같은 파일을 쓰지 않을 때만 지웁니다 (분석 삭제와 같은 규칙) |
| 출력 폴더 `outputs/rev<N>` | 이제 어느 리비전도 안 가리키므로 **함께 지웁니다** — 남기면 [B] 고아 경고가 그대로 뜹니다 |
| 프로젝트 폴더 | 지웁니다 |
| **안정 ID 장부** | **`projects/_deleted/<이름>-<UTC시각>/` 로 옮깁니다** |

`_deleted/…` 에는 `project.json` 이 없으므로 `list_projects` 가 건너뜁니다 →
**첫 화면에서 사라집니다.**  같은 이름으로 다시 만들면 `create_project` 가
그 장부를 **이어받고**(`inherited_from` 에 무덤 이름을 적습니다) 번호가
이어집니다 — 시험이 `next_seq` 가 1 로 돌아가지 않음을 못박습니다.

## 3. 요구 대조

| 요구 | 한 것 |
| --- | --- |
| 첫 화면에서 사라진다 (새로고침 없이) | 삭제 뒤 `listHome()`·`loadProjects()`·`showAudit()` 를 다시 읽습니다 |
| 누르기 전에 무엇이 사라지는지 | 미리보기가 분석 수 · 행 · 고친 칸 · 수정이력 · 스냅샷 · 업로드 수를 냅니다 |
| 확인을 한 번 더 | 확인 대화 + **프로젝트 이름을 그대로 옮겨 적기** (서버도 `confirm` 을 검사) |
| 누가 언제 | 분석마다 `deletion_log` 한 줄 (13회차 자기신고 그대로) |
| 업로드 PDF 도 지울지 | **지웁니다** — 공유되지 않을 때만.  근거: 그 PDF 를 가리키는 분석이 없으면 열 길이 없고, [B] 의 고아 업로드가 됩니다.  공유되면 남깁니다 |
| 안정 ID 충돌 | 위 2번 — **장부만 남깁니다.**  대화에 그 사실을 먼저 적습니다 |
| 팀 공유 경고 | 그 프로젝트의 수정이력 작성자 중 **지금 사람과 다른 이름**이 있으면 대화 맨 위에 `⚠ 다른 사람이 만든 기록이 있습니다 — <이름>` 을 붙입니다.  **막지는 않습니다** (권한 체계가 없습니다) |

## 4. 게이트

* 분석 중이면 **거절**합니다 (409) — 먼저 취소해야 합니다.
* 삭제 뒤 `audit.leftovers` 의 고아 업로드·출력이 **0** (시험).
* 격리 폴더(`PID_DATA_DIR`)에서만 시험합니다 — 실 DB 를 열지 않습니다.
* 엔진 파일 0개 → 네 프로젝트 지문에 닿지 않습니다.
