# 21회차 [D] — 원인과 대책

## 0. 무엇이 확정이고 무엇이 아닌가

| | 상태 |
|---|---|
| 죽은 자리 (`_ink_mask` 의 `a.min()`) | **확정** — 원본 예외 · 코드 · 재현 |
| 죽는 조건 (clip 교집합이 빈 다섯 모양) | **확정** — 합성 PDF 로 전부 재현 |
| 스택이 가리킨 갈래 (이력 행) | **확정** — 원본 예외의 `:321` |
| **TC2 가 그 다섯 중 어느 모양인가** | **다섯 번째 (얇은 이력 행) — 줄 번호로 좁혀집니다** |
| 20회차 배포본에서 **원본 예외 재현** | **확정** — 파일·줄 번호까지 같음 (§3 문서 §2-2) |
| TC2 의 실제 괘선 간격 · 60장 구성 | **미확정 — 파일이 없습니다** |
| 이력 행 캐시가 문서 사이로 새는 것 | **확정** — 실측 재현 (별개 결함) |

**줄 번호가 원인을 좁혔습니다.**  `:321` 은 `build_glyph_library` 의 세 갈래
중 **이력 행** 갈래이고, 거기에 닿으려면 `history_rows` 가 비어 있지 않아야
합니다 — 그 함수는 `x0 < 1975 · x1 > 2320` 인 괘선만 받으므로 **TC2 의 종이는
최소 2320 x 1390pt 입니다.**  그러면 그 clip 의 가로 범위(1971~1988)는 반드시
종이 안이고, 0픽셀이 될 남은 길은 **세로 범위가 비는 것** 하나 —
곧 **이력 행 높이가 `2 x hist_row_inset`(2.4pt) 이하** 입니다.

20회차 배포본에 A1 종이 + 괘선 간격 2.0pt 짜리 합성 PDF 를 올려
**원본 예외를 파일·줄 번호까지 그대로 재현**했습니다 (§3 문서 §2-2).

프롬프트의 (a)(c)(d)는 그래도 TC2 의 양식 자리를 알아야 고를 수 있습니다.
**(b) 만 무조건이므로 (b) 만 했습니다.**

## 1. (b) 0픽셀에 `.min()` 을 부르지 않는다

`app/engine/extract_titleblocks.py` `_ink_mask`

```python
if a.size == 0:
    return None
darkest = int(a.min())
```

**이 자리에서 사유를 말하지 않습니다.**  `_ink_mask` 는 *한 칸*을 읽는 함수이고
한 칸이 비는 것은 정상입니다(빈 REV 칸, 글자 없는 이력 행).  여기서 문장을
쓰면 그것이 곧 조용한 폴백이 됩니다.  문서 **전체**가 안 읽히는 경우만 시끄럽게
멈춰야 하고, 그 판단은 파이프라인이 합니다 — §2.

## 2. 조용히 행 0개로 성공하던 길을 끊었습니다

고치기 전 흐름:

```
타이틀블록 칸이 안 맞음
  → parse_drawing_no 가 전 장에서 None
  → classify_page 가 한 장도 PID 가 아님
  → targets = []
  → 시트 루프가 아예 돌지 않음
  → 행 0개로 "성공" 저장
```

`_ink_mask` 만 고치면 예외 대신 **이 길**로 갑니다.  15회차 [B]2 가 잰
`unit_multipliers` 와 같은 모양의 조용한 폴백입니다 — 그래서 예외를 막는 것과
사유를 만드는 것을 **함께** 했습니다.

- `pipeline.TitleBlockUnreadable` — `LegendUnavailable` 과 같은 자리.
  **예외를 바꿔 쓴 문장이 아니라** 파이프라인이 직접 검사한 조건이고
  문장도 거기서 씁니다 (`_frame_reason`).
- 문턱이 없습니다 — **0** 입니다.  한 장이라도 읽히면 나머지는 지금까지처럼
  장마다 사유가 붙어 `skipped` 로 세어집니다.
- 사실은 `tb.frame_report` 가 재고 **문장은 저장하지 않습니다**
  (15회차 `compare_note` — 저장된 문장은 고칠 수 없습니다).

실제 문장 (A3 3장 합성 PDF 로 파이프라인을 돌려 받은 것):

```
이 PDF 의 3장 어디에서도 도면번호를 읽지 못했습니다. 도면번호 칸의 자리를
[1950.0, 1560.0, 2384.0, 1600.0] 로 보고 있는데 3장 전부에서 종이 밖입니다
(이 문서의 쪽 크기: 1191.0x842.0pt 3장). 이 자리는 도면에서 유도되는 값이
아니라 프로젝트 설정 `title_block` 에 적는 상수입니다 — 이 회사 양식의
타이틀블록 좌표를 재서 프로젝트 설정에 넣어야 합니다.
```

### 검사는 두 자리입니다 — 판정은 하나

| 자리 | 무엇을 잡나 | 비용 |
|---|---|---|
| `open_pdf` 직후 | 도면번호 칸이 **모든 장에서 종이 밖** | 쪽 크기 비교 몇 번 |
| `titleblocks` 뒤 | 종이 **안**인데 한 장도 못 읽음 | 이미 읽은 결과를 셈 |

이른 검사는 **판정을 바꾸지 않고 자리만 앞으로 당깁니다.**  종이 밖이면
`parse_drawing_no` 가 보는 낱말이 0개이므로 늦은 검사가 반드시 걸리기
때문입니다.  두 자리가 같은 문장(`_frame_reason`)을 씁니다.

**실측 — 빨리 실패하게 한다**: A3 60장 합성 PDF (괘선 100줄/장)

```
고치기 전  선분 캐시 예열 + 치수 계산을 다 지난 뒤 죽음
고친 뒤    0.21초 만에 사유와 함께 멈춤 (진행 보고 1건: opening the document)
```

## 3. ⚠ 같이 고친 것 — 이력 행 캐시의 문서 간 누수

`history_rows` 의 캐시가 모듈 전역 dict 이고 키가 `page_no` 하나였습니다.
지우는 곳이 없어 서버 프로세스 안에서 문서 사이로 샙니다 (§3 문서 §6 에 실측).

`_rects`·`_segments` 와 같은 자리로 옮겼습니다 — 캐시를 **그 쪽 객체 자신**이
들면 문서 사이로 샐 길이 없습니다.

```python
cached = getattr(pd, "_hist_rows", None)
if cached is None:
    ...
    pd._hist_rows = cached
return cached
```

한 문서만 도는 프로세스에서는 값이 정확히 같으므로 **AL NOUF1 기준선은
움직이지 않습니다** ([F] 회귀로 확인).

**보고된 실패의 원인은 아닙니다** — 재현이 끝났고 고치는 값이 명백해서
같이 넣었습니다.  아니었다면 다음 회차로 넘겼을 것입니다.

## 4. 하지 않은 것

| 후보 | 왜 안 했나 |
|---|---|
| (a) `tb.LAYOUT` 을 런타임에 유도 | **TC2 가 없어 유도 규칙을 세울 근거가 없습니다.**  근거 없이 만든 규칙은 §2.2 위반이고, 이 규칙은 AL NOUF1 · SADARA 두 양식만 보고 만들면 세 번째 양식에서 또 막힙니다 |
| (c) 글리프 라이브러리 없이 진행 | 그러면 REV 를 못 읽는 채로 끝까지 갑니다 — 조용한 폴백을 하나 더 만드는 것입니다 |
| 임계값(`hist_row_inset` 등)을 넓혀 TC2 를 통과시키기 | 이 PDF 하나를 위한 특례는 다음 프로젝트에서 또 막힙니다 (프롬프트 금지) |
| `title_block` 좌표를 추정해 config 에 넣기 | 도면을 보지 않고 좌표를 적는 것은 지어낸 값입니다 (§2.1 ③) |
