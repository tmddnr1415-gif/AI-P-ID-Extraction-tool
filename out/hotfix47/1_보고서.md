# hotfix47 — 같은 도면에 새 태그와 사라진 태그가 함께 남으면 전부 '수정'(MOD)

## 0. 요구

- 사진 1 (QFE p89 `1A1Y-20PGD10-M05-0002`): *"이 PI 는 Tag number 도 이전과 최신이 같다.  변경된 것은 단순 pdf 에서의
  위치이다.  이런 사항은 변경으로 표기하지 않는다."*
- 사진 2 (QFE p41 `1A1Y-30GKC10-M05-0203` ↔ Rev.A p40 `-0003`, 추가 4 · 삭제 34): *"이런 사항들은 tag 가 변경된 것이다.
  하지만 tag 변경인지, 삭제 추가인지 확인이 어려우니 이런 사항들은 모두 MOD 로 변경으로만 표기한다."*

## 1. 사진 1 — 두 판의 PDF 가 다르다 (코드 아님)

두 PDF(`QFE_260112.pdf` · `QFE_260326.pdf`)의 p89 낱말을 셌다.

| 태그 머리 | Rev.A (260112) | Rev.B (260326) |
| --- | --- | --- |
| `20PGD41/42/43/51/52/53` | 있음 | 있음 |
| `20PGD46*` · `20PGD56*` | **0개** | `20PGD46CP501/502` · `20PGD56CP501/502` · `20PGD56CT501/502` |

같은 태그를 든 열여덟 행(PI 12 · TI 6)은 자리가 247pt 움직였어도 **전부 변경 없음**이다 (hotfix46 — 짝은 태그로만).
ADD 는 46·56 열의 여섯뿐이고, 그 여섯은 Rev.A 도면에 인쇄돼 있지 않으므로 **추가가 맞다**.  회사 PC 화면이 같은 태그
행에 ADD 를 보였다면 hotfix46 이전의 옛 판정이 DB 에 남은 것이다 → 결과 화면 오른쪽 위 `대조 다시`.

## 2. 사진 2 — 규칙

`revisions._leftovers` — 한 도면에서 (TYPE, 태그)로 짝이 안 선 **태그 있는** 행(새 태그)과 기록(사라진 태그).

| 남은 것 | 판정 |
| --- | --- |
| 새 태그만 | 추가 (예전 그대로) |
| 사라진 태그만 | 삭제 후보 (예전 그대로) |
| **둘 다** (`ambiguous`) | 새 태그 행 → **수정** (basis `AMBIGUOUS`) · 사라진 기록 → **수정 (이전 태그)** (`deleted_candidates[].state = MODIFIED`) · 추가 0 · 삭제 후보 0 |
| 그중 같은 TYPE 이 하나씩 | 태그가 바뀐 **한 항목**으로 잇는다 (basis `TYPE` · 안정 ID 유지 · `changed` 전 → 후) |

위치는 어디서도 보지 않는다 — `_leftovers` 에 `rect`·`anchor`·`radius`·`nearest`·`dist` 가 없음을 시험이 못박는다.
같은 태그에 TYPE 만 다른 쌍(p41 `LS 31GKC41CL104` ↔ `LSLL 31GKC41CL104`)은 잇지 않고 사유에
*"같은 태그가 Rev.A 에서는 LS 로 있었습니다 (표기가 바뀐 것일 수 있음)"* 을 붙인다 (`same_tag_now`).
