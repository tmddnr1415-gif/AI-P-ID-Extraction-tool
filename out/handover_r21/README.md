### ⚠ 결함 1건 — 나중에 다시 연 실패 화면은 단계를 말하지 않습니다

API 는 `stopped_stage = "reading title blocks"` 를 갖고 있는데 화면은
`도면을 한 장도 읽기 전에 멈췄습니다` 만 씁니다 (단계가 빠짐).

**원인**: 그 값이 **두 경로**로 흐르는데 한쪽에만 실려 있습니다.

| 경로 | `stopped_stage` |
|---|---|
| 실패하는 것을 **보고 있을 때** (`_emit` → SSE) | 실림 ✔ |
| 나중에 그 분석을 **다시 열 때** (`/jobs/{id}/events` 의 첫 replay) | **안 실림 ✘** |

`app/main.py` 의 `events()` 가 재접속자에게 현재 상태를 한 번 보내는데
(`progress` · `message` · `status` · `page_count` · `sheets_done` ·
`sheets_total` · `sheet_plan` · `elapsed_s`), 21회차에 늘어난
`stopped_stage` 가 그 목록에 안 들어갔습니다.

**데이터는 멀쩡합니다** — `job.stopped_stage` 에 원문이 저장돼 있고
`GET /jobs/{id}` 도 그것을 냅니다.  화면에 닿는 길 하나가 비어 있을 뿐입니다.

**고치지 않았습니다** — 이 회차는 포장과 검증이고 코드 수정이 금지입니다.
21회차 캡처(`out/round21/6_캡처/`)의 "타이틀블록을 읽는 중 단계에서
멈췄습니다" 는 **라이브 경로**로 찍은 것이라 그때는 맞았습니다.

실무 영향: 20분짜리 분석을 걸어 두고 자리를 비운 사람이 돌아와서 화면을
다시 열면 **사유는 보이지만 단계는 안 보입니다.**  사유 문장이 이미 무엇을
하면 되는지 말하므로 막히지는 않습니다.

이것은 12회차가 남긴 교훈(`근거 패널만 고치면 행을 누른 사람에게만 말한다`)과
같은 모양입니다 — **같은 사실이 두 길로 가는데 한 길에만 실린 것**입니다.
