PID_hotfix34 — 첫 화면 오른쪽 아래에 "어느 업데이트가 적용돼 있는가"  (2026-10-01)
=================================================================================

이 꾸러미는 hotfix1~33 누적 위에 hotfix34 를 얹은 것입니다.  저장소 HEAD 와 바이트 대조 0.

무엇이 달라지나
  1. 첫 화면(모든 화면) 오른쪽 아래 바닥줄에 적용된 꾸러미를 적습니다:
       업데이트 hotfix34 (rev 34) · PID_hotfix34_2026-10-01.zip · 생성 2026-10-01 HH:MM  |  v1.0.0 · …
     마우스를 올리면 기준 커밋(꾸러미를 만든 시점의 저장소 커밋)과 브랜치가 보입니다.
  2. 값은 꾸러미 안의 app/_update.json 그대로입니다 — 꾸러미 생성기가 만들 때 적습니다.
     이 파일이 없는(hotfix33 이전) 서버에서는 "업데이트 기록 없음 (hotfix34 이전 꾸러미)" 라고
     적습니다.  지어내지 않습니다.
  3. 바닥줄이 보이지 않거나 옛 값이면 브라우저 캐시입니다 — 새로고침(Ctrl+F5).  바닥줄의
     `화면 <딱지>` 가 56회차부터 그것을 가릅니다.

확인한 것
  - 빠른 시험 통과 · 화면 자기검증 out/hotfix34/ui/ (딱지 있음/없음 두 상태 · 오른쪽 아래 위치)
  - 엔진·판정 코드 0줄 (app/version.py · main.py /version · app.js 바닥줄 · 꾸러미 생성기).

적용
  저장소 뿌리에서 풀어 덮어쓰기 → 서버 재시작 → 브라우저 새로고침.  app/_data/ · data/ 는 없습니다.
