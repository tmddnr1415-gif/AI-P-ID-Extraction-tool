# hotfix54 — 서버가 켜지다 죽던 것 (로그 파일의 cp949)

**현장**: `install_autostart_lan.bat` 등록 뒤 서비스 창이 `Server stopped … Restarting in 10 seconds` 를
되풀이했고 `check_pid_server.bat` 은 "서버가 떠 있지 않습니다"(포트 8000 프로그램 0 · 10061 거부).

## 원인 — hotfix52 가 만든 결함

hotfix52 가 서버 출력을 창 대신 `logs\server.log` 로 돌렸다 (콘솔 '선택' 모드 멈춤을 막으려고).  한국어
Windows 의 파이썬은 **파일로 돌린** 표준 출력을 cp949 로 쓰고, cp949 에는 `—`(U+2014)가 없다.
`main._audit_on_start` 는 `import app.main` 때 감사 줄을 출력하는데, **손으로 더한 행이 있는 DB**
(회사 DB 는 46회차가 본 다섯 행)에서는 `… 들어갑니다 — 검토자가 …` 한 줄이 더 붙는다 →
`UnicodeEncodeError` → uvicorn 이 앱을 못 읽고 끝남 → 서비스가 10초 뒤 다시 켬.

재현 (같은 조건 — 손으로 더한 행 하나 · `PYTHONIOENCODING=cp949` · 파일로 돌림):

```
File "app/main.py", line 3545, in _audit_on_start
UnicodeEncodeError: 'cp949' codec can't encode character '\u2014'
```

hotfix51 까지는 창(콘솔 API)에 써서 드러나지 않았고, 이 환경의 시험 데이터에는 손으로 더한 행이 없어
hotfix52 시험이 놓쳤다.

## 고친 것

| | |
| --- | --- |
| `run_lan_service.bat` · `check_pid_server.bat` | `set PYTHONUTF8=1` (서비스는 `PYTHONIOENCODING=utf-8` 도) — 글자가 산다 |
| `app/console.py` `safe_stdio()` | 표준 출력·오류가 `strict` 면 `replace` 로 — 인코딩은 그대로, 못 쓰는 글자는 `?`.  `app/main.py` import 앞 · `desktop.main` · `lan_check.main` |
| `app/desktop.py` `_Tee` | 창 쓰기에서 `UnicodeError` 도 잡아 바꿔 쓴다 (exe 경로 — 옛 코드는 `ValueError/OSError` 만 잡았다) |
| `app/lan_check.py` `tail()` · `--tail` | 서비스가 멈출 때 창에 로그 끝을 보인다.  마지막 `Traceback` 부터 · 줄마다 UTF-8 → cp949 (옛 로그가 섞여 있다) |

## 확인

* 재현 조건 그대로 `uvicorn` 기동 → `Uvicorn running` · `/version` 응답 · 감사 줄은 `?` 로 기록.
* `PYTHONUTF8=1`(서비스의 길) → 로그에 `—` 그대로.
* `tests/test_hotfix54_log_encoding.py` 5건 — 하위 프로세스로 cp949 + 파일 + 손으로 더한 행에서
  `import app.main` 이 0 으로 끝나고 그 줄이 실제로 찍혔는지 · `safe_stdio` · exe `_Tee` · bat 순서 ·
  섞인 로그의 `tail`.  빠른 시험 **808 통과**.
* 엔진 0줄 — 지문·회귀에 닿을 길이 없다.
* ⚠ Windows 에서는 못 돌렸다.  현장 사진(14:08) 은 메모장으로 넣은 `set PYTHONUTF8=1` 한 줄로
  서버가 정상(hotfix53 · `/home` 0.3초 · 사내망 주소 응답)임을 보여 준다 — 원인 진단과 맞는다.
