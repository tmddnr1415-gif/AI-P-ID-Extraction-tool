# hotfix38 — QFE 260112(Rev.A) → 260326(Rev.B) 개정 대조: 추가·삭제를 정확히 가른다

사용자 요구: *"QFE 프로젝트를 첫 화면에 생성하고, 시간순으로 260112 를 분석한 뒤 260326 을
넣으면 이전 대비 무엇이 삭제되고 추가됐는지 확인하고 싶다.  삭제는 List 에서 삭제 표기 +
remark (필터), 추가는 식별 표기 위에 add 라벨 + 리스트 표기.  스스로 QFE 모든 페이지를 돌려
검증하고 다른 프로젝트에서도 되게 질을 높여라."*
추가 지시: *"하나의 가지에서 PIT·PI 가 있으면 PIT 가 물리적 계기이고 PI 는 시그널이니 PIT 를
식별해야 한다.  TIT·TI, PDIT·PDI 모두 마찬가지다."*

## 1. 있는 것을 먼저 찾았다 — 스물한 번째

리비전 대조는 13회차부터 있었다 (`app/revisions.py` · 안정 ID 장부 · `revision_state` ·
삭제 후보 · 화면의 링 · Excel 음영).  없던 것은 넷이다:
① 짝을 **기하로만** 지었다 (같은 TYPE · 반경 안 최근접) — 태그가 인쇄된 1급 문서에서
태그를 쓰지 않았다.  ② 도면번호가 바뀐 장을 알아보지 못했다.  ③ 장부에만 있는
도면(이번 분석 행 0)은 아예 돌지 않아 삭제 후보가 올라오지 않았다.  ④ 같은 리비전을
다시 대조하면 직전 대조가 만든 ID 가 살아 있어 "추가" 가 "변경 없음" 으로 둔갑했다.
화면에는 ADD 글자 · 개정 열 · 개정 필터 · 삭제 Remark 가 없었다.

## 2. 태그가 곧 이름이다 (`revisions._tag_matches` · `_pairs_within` · `pair_renumbered_sheets`)

1. **(TYPE, 태그)** 가 그 도면 안에서 양쪽에 하나씩이면 짝 — 거리를 안 본다 (옮겨도 같은
   항목 · `moved_pt` 기록).  TYPE 을 함께 보는 이유는 hotfix35 — PI 와 PIT 가 한 태그를 든다.
2. 같은 태그가 둘 이상(UAD p30 꼴)이면 기하로 넘긴다 (`tag_duplicates`).
3. 남은 것은 예전 그대로 상호 최근접 → 거리순.  **둘 다 태그인데 다른 쌍은 맨 뒤** —
   QFE 실측 `00GHC36CF001` → `10GHC42CF101` 이 같은 좌표(0.0~1.7pt)에 있다.  그것은
   "수정 (tag_no)" 이고 안정 ID 가 이어진다 (§7.3 — ID 는 그 자리의 항목, 태그는 값).
4. **도면번호가 바뀐 장**: 장부에만 있는 번호 ↔ 이번에만 있는 번호 사이에서 공유 태그
   둘 이상 · 작은 쪽 절반 이상 · 상호 최선.  기록을 새 번호로 옮기고 ID 는 그대로.
   제목은 근거가 못 된다 (네 장이 같은 제목).
5. 태그 없는 행(AL NOUF1 · TC2 · SADARA 전부)은 한 글자도 안 바뀐다 — 기하 그대로.
6. 근거: 행마다 `basis`(TAG|GEOMETRY) · 추가 `reason` · 삭제 후보 `tag_no` ·
   `tag_elsewhere`(다른 도면에 섰으면 옮김일 수 있다) · `tag_changed` · `sheets`.

- 목록: **개정** 열(추가 · 수정 · 삭제 후보 · 삭제 확정 — 필터·검색) · 개정 필터

  도면번호 바뀐 장 N · 새 장 N · 빠진 장 N`.

## 4. 눈 확인 크롭이 잡은 것 — 버블 안의 버블 (#40)

삭제 후보 `LIT 10LCM10CL001B`(p51)를 A·B 크롭으로 보니 **둘 다 있다**.  B 분석이 그 행을
못 낸 것이다 — 260326 은 탱크 외곽을 둥근 사각형(296×801pt · 호 캡 둘 + 곧은 옆면)으로
그려 `bubble_outlines` 가 버블로 세웠고, 안의 LIT·LIT·LI 낱말이 "버블 2개에 걸림" 으로
미판정이 됐다.  고침: 낱말이 여러 윤곽에 들면 **다른 윤곽을 품는 윤곽은 그 낱말의 버블이
아니다** (`detect_symbols._innermost` · 관계만 · 상수 0 · 크기 창은 37회차대로 두지 않는다).
전수(중첩 윤곽): QFE 260326 **489**(p42 68 · p39 8 · p51 5 · 범례 장 408) · 260112 409 · AL NOUF1 **2**(p16 · 6×17pt 안의 6×3pt 조각 — 검출 불변을 직접 확인) · TC2 는 메모리가 겹쳐 못 셌다(회귀 지문으로 대신).  고친 뒤 p51 LIT·LIT·LI 가 Rev.B 에 서고 `10LCM10CL001B` 는 **변경 없음**이다.

## 5. 한 가지의 전송기 (#39 · `pipeline._bubble_links` · `_fold_readouts(links=)`)

hotfix31 은 "한 라인" 을 같은 태그로만 읽었다.  QFE Rev.A 실측(`spike/readout_link_probe.py`):
태그 없이(p6 PI/PIT · TI/TIT 4) · 태그를 달리 찍고(p23 `CL002`↔`CT002` · p49·p50

포함하지 않아 안 접히던 짝 4 (p42).  **AL NOUF1 0 · TC2 0.**
규칙(순회 없음 · 상수 0): 한 축으로 겹치는 두 버블의 틈이 **버블 긴변 이하**이고 그 띠의
축 방향 잉크가 틈의 절반 이상이면 "이어 그린 선".  이기는 쪽은 그 표가 TRANSMITTER 로 읽는
글자를 가진 기능(`PIT`·`PT`·`FT`) 또는 포함 관계(`PIC` ⊃ `PI`).  표시기는 접혀 전송기 행의
근거·REMARK 에 남는다 (`basis: LINK · how: 이어 그린 선 (세로 틈 15.5pt · 덮임 0.82)`).
⚠ **한계**: p59 `PI 11LAB10CP901` 처럼 두 PIT 에서 **꺾인 파선**으로 들어오는 표시기는
선분 하나로는 못 읽어 접지 않는다 (§2.3) — 렌더 `out/hotfix38/branch/p59_PI_0.png`.
