# 18회차 [E] — 미검출 · 심볼 단위 게이트

## ★ 원인은 `actuator NONE` 이 아니었다.  17회차 [B] 는 다른 것을 재고 있었다

17회차 [B] 는 네 안을 쟀고 전부 `actuator NONE` **정책**을 완화하는 것이었다.
지목된 건들의 실제 원인은 **몸체 기하**다.  그 게이트 결과는 이 건들에
대해서는 무의미했다.

## 원인 사슬 — p10 XV 실측

```
1. 범례 p2 가 ANGLE 을 정의한다 — 직각으로 꼭짓점을 맞댄 두 중공 삼각형
     (GATE = 중공 나비, GLOBE = 나비 + 검은 원, ANGLE, THREE-WAY 와 나란히)
2. 검출기의 몸체 어휘에 ANGLE 이 없다
     GATE · GLOBE · BUTTERFLY · BALL · CHECK · DIAPHRAGM
   → 삼각형 **하나만** `CHECK` 로 읽는다
        진짜 도형  (718.7, 797.5, 733.4, 812.8)  6선분 중공 · 14.7 x 15.3
        읽은 것    (719.0, 807.6, 728.8, 812.8)  ← 왼쪽 삼각형만
3. 그 rect 중심 x = 723.9 가 **진짜 스템축 x = 728.7 에서 4.86pt** 어긋난다
4. 공압 실린더는 **제대로 찾고 있다**
        (721.7, 827.4, 735.8, 841.5)  = 범례 p3 `PNEUMATIC CYLINDER DOUBLE-ACTING`
5. `act_offaxis = 0.83pt` 가 off = 4.86 을 거부한다  (stem 검사는 **통과**)
6. actuator = NONE  →  `deliverable_class` 첫 줄  →  EXCLUDED
```

**꼭짓점에서 재면 off = 0.04pt 다.**  허용치를 늘릴 일이 아니라 **재는 점이
틀린 것**이다 — 16회차 벤더 별표와 같은 종류의 오류다
("허용치는 건드리지 않고 읽는 사각형만 바꿨다").

### 두 값의 분리가 명확하다

```
rect 중심에서 잰 off   4.86 · 4.86 · 4.86 · 4.88 · 4.94 · 4.99 · 5.01 · 5.02
꼭짓점에서 잰 off      0.01 · 0.04 · 0.07
허용치                 0.83  (범례에서 유도된 값 · 건드리지 않는다)
```

## ★ p20 미상 심볼의 답 — 범례 안에 있었다

세 회차 동안 "심볼 미지정"이던 p20 의 그 형상은:

```
범례 p2  ANGLE                                  (직각으로 맞댄 두 중공 삼각형)
범례 p3  PNEUMATIC DIAPHRAGM WITH POSITIONER    (반원 돔 + I/P 상자)
도면     VS · NOTE3
```

**범례가 이미 답하므로 [D] 전역 심볼 사전 대상이 아니고, 내가 뜻을 정하는
것도 아니다** (§2.1 ③).  "범례에 있는데 못 읽는 것" 과 "범례에 없는 것" 을
가르라는 지시가 정확히 이것을 잡아냈다.

## 게이트 — ★ 통과하지만 **자동 통과**다.  그대로 적는다

12행(도형 10개)은 전부 액추에이터가 `PNEUMATIC` 이다.
`deliverable_class` 는 PNEUMATIC 을 태그에 따라 `XV` 또는 `CV` 로 보내고,
둘 다 **PNEUMATIC 탭(CZF)** 으로 간다.

```
축1 (전량)   FIELD · MOV · BFV 에 더해지는 행 0  →  99.3% / 70.5% 불변
축2 (SCT)    같음                              →  99.3% / 89.1% 불변
```

**⚠ 이 통과는 "맞아서" 가 아니라 "채점되지 않는 곳이라서" 다.**  17회차가
"전부 PNEUMATIC 탭은 통과가 아니다" 라고 적은 것과 같은 구조다.  다만
**다른 점이 하나 있다**: 17회차는 내가 배분을 *골랐고*, 여기서는 **범례가
정한다** — 공압 액추에이터가 달린 밸브는 제어 밸브이고 제어 밸브는 CZF 로
간다.  고를 여지가 없다.

그래서 이 건의 근거는 정밀도가 아니라 셋이다.

```
① 범례 p2 가 그 형상을 ANGLE 로 정의하고, 범례 자신의 그림이 같은 정의에 걸린다
② 사용자가 그 좌표를 정확히 지목했다 (p10 XV · p21 FCV · p20)
③ 꼭짓점 off 0.01~0.07 ↔ rect 중심 off 4.86~5.02 — 우연이 아니다
```

**CZF 정답지를 받으면 그때 채점된다.**  그때까지 이 12행은 "도면과 범례가
말하는 것" 이지 "발주처가 확인한 것" 이 아니다.

## [G] AIT — 검출을 늘리는 것은 게이트 불통과

```
현재 출력       AT · AIT 는 `anchors.type_map` 에 없어 앵커가 아니다 → **0행**
도면 낱말       AT 12회/9장 · AIT 4회/1장 · 그 중 버블 안 6개 (p14 AT 2 · p16 AIT 4)
ISA 근거        범례 p3 문자표가 A → ANALYSIS 를 유도한다 (실측)
표기층          `description.type_display_names` 에 AT·AIT → Analyzer 가 이미 있다
                행이 생기는 순간 적용된다.  `type_internal` 은 안 바뀐다
```

**★ 발주처 CZE 정답지에 AT·AIT 가 0행이다** (TYPE 분포 실측:
FE 18 · FIT 30 · FS 3 · LI 10 · LIT 28 · LS 22 · PDIT 47 · PI 109 ·
PIT 104 · RO 18 · TI 59 · TIT 99 — A 로 시작하는 것 없음).

```
6행을 앵커로 추가하면  축2 정밀도 89.1% → 88.3%  (595/674)
게이트 88.4% 불통과 → **구현하지 않는다**
```

표기 규칙은 이미 자리에 있으므로, 발주처가 AT·AIT 를 계상하기로 하면
앵커 한 줄로 켜지고 표기는 그때 바로 `Analyzer` 로 나간다.
