## ★ 시작하자마자 스스로 뒤집은 것 — SADARA PDF 는 있었다

18·19회차가 **"이 작업 환경에 `sadara_1A46.pdf` 가 없다"** 고 적었다.
그것은 `data/sadara_1A46.pdf` **한 자리만** 봤기 때문이다.  실제로는

```
app/_data/uploads/2391ee0f1ea6_sadara_1A46.pdf
  sha256 7e10923a048889a3815b5bc5f2781bcbf1adbd35498948053e494c145cd60f71
```

에 있었다 (업로드된 원본).  **"없다" 를 두 회차 연속으로 적은 것이 틀렸다.**
교훈은 §8 에 이미 있던 것과 같다 — *없는 것을 만들기 전에 있는 것을 찾는다*.
실 DB 를 건드리지 않기 위해 **읽기 전용으로 사본을 떠서** 분석한다.
