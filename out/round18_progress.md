## 절대 어기지 않는 것

- 페이지 번호 · 도면번호 · 특정 태그명으로 분기하는 코드 금지
- 고칠 때마다 58장 전수 영향을 센다.  지목 안 된 장의 변화가 발견이다
- 임계값은 범례 또는 런타임 측정에서 유도.  근거를 함께 적는다
- 실 DB(`app/_data/`) 를 어떤 이유로도 건드리지 않는다 (17회차 A-2 로 막았다)
- 실무 판단이 필요하면 후보와 근거만 내고 결정하지 않는다
- **측정축(축1·축2) 정의를 건드리지 않는다** — [B] 는 출력 필터를 끄는 것이지
  측정이 아니다
- **전역 심볼 사전에 자동 등록 금지** — 사람이 확인한 것만 들어간다
- **심볼의 의미를 스스로 정하지 않는다** — 등록 화면까지만 만든다 (§2.1 ③)

- (18-0) 진행 기록 생성.  HEAD `4365a30` · 실 DB sha256
  `643748dc0efe16816cb1b723941cb0fc6af1de9e183c15eab6d5dba726ecd40a`.

  Description F1 **68.7** · 식별 **41.6%** · 완전일치 19 ·
  scope SCT **769** / 빠지는 **260**.  **[0] 의 값과 한 칸도 다르지 않다.**
- (18-A) **축2 재현율은 99.3% 다.**  16회차 보고가 옳고 17회차 프롬프트 [0] 의
  99.2 는 16회차 *이전* 값이었다 (17회차 A-1 이 같은 확인을 했다).
- (18-A) 발주처 양식 4종 실측 — FIELD 885→**656** · MOV 76→**66** ·
  PNEUMATIC 45→**25** · BFV 23→**22** (MASTER 144→113).  합 1029→**769**.
- (18-A) 분석 시간 — 여기 **298초**, 회사 PC 1,189초(19분 49초).  단계 프로파일이
  `layout` 60.9% + `valves.actuators` 14.3% 로 **순수 파이썬 기하 계산에 몰린
  단일 스레드 CPU 부하**다.  알고리즘 차이가 아니라 CPU 클럭·IPC 차이로 보이나
  **회사 PC 를 잴 수 없으므로 이것은 추론이고 실측이 아니다.**
- (18-B) 발주처 양식 전량 — `excel_out.form_scope_mode()` **하나**가 판정하고
  화면(`scopeFacts`)·완료 화면(`_scope_summary`)·산출(`write_all`)이 그것을
  읽는다.  **11회차 코드는 지우지 않았다** — `scope_filter: sct` 한 줄로
  656/66/22 로 돌아가고, 시험이 **두 모드를 다 지킨다**.
  실측: all 885/76/23(+45 미수령) = 1029 · sct 656/66/22(+25) = 769 · 빠진 행 0.
  Excel 결정성 51,514칸 중 다른 칸 **0**.
- (18-B) **두 사실이 갈렸다** — "양식에 나가는가"(`in_client_scope`)와 "누가
  공급하는가"(`scope_state`).  전량 모드에서 벤더 260행은 **둘 다 참**이다.
  한 함수로 묶여 있었으면 완료 화면이 260행을 "빠집니다"라고 거짓말한다.
  `_scope_summary` 가 `delivered/held` 와 `vendor` 를 따로 센다
  (실측 delivered 1029 · held 0 · vendor 260 · legacy 0).
- (18-C) **★ 16회차 전수 검사가 뚫려 있었다 — 답은 (a).**  "별표가 있는가" 를
  `read_vendor_mark` 에게 물었고 그 함수는 `find_marks` 가 준 마크만 본다.
  `find_marks` 는 그 장 범례 별표 크기 ±0.6pt 밖을 **이미 버렸다** — 버려진
  별표는 검사에도 안 보이므로 검사는 **언제나 0** 을 낸다.
- (18-C) 진짜 원인은 **범례가 축척을 정하지 않는다**는 것.  27장 실측: 26장은
  정의줄 크기 = 도면 크기, **p35 만 4.0 ↔ 7.8**.  §3 의 범례 형상 실패
  (비율 ×0.42~×2.00)와 같은 이야기다.
- (18-C) p35 의 7.8 이 `**` 인지 **획으로 확정**: 여덟 반쪽 획이 한 점
  (1377.06, 206.44)에서 만난다 — **별표 하나**다.  같은 별표를 장마다 다른
  획 분해로 그린다(p6 관통 · p49 네 path · p35 여덟 반쪽).
