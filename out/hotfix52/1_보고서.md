# hotfix52 — 서버는 떠 있는데 페이지가 끝없이 로딩만 하던 것

현장(회사 PC): hotfix51 서비스 창에 `Uvicorn running on http://0.0.0.0:8000` 이 떴는데
`http://localhost:8000/?embed=1&mode=bid` 가 열리지 않고 로딩만 했다.

**엔진 0줄 · 판정 · 지문 · 저장 · Excel 무관.**  바뀐 것은 실행 스크립트와 사내망 문지기뿐이다.

## 1. "떠 있다" 와 "응답한다" 는 다른 사실이다 — 멈추는 길 셋

| 길 | 무엇이 일어나나 | 막은 것 |
| --- | --- | --- |
| ① 콘솔 '선택' 모드 | 서버 창을 마우스로 누르면 Windows 가 그 창을 '선택' 모드로 두고, 그 창에 글을 쓰는 프로그램은 **쓰는 순간 멈춘다**.  uvicorn 은 요청마다 한 줄을 쓰므로 첫 요청에서 서버 전체가 멈춘다 (창 제목이 "선택 …").  이전 사진에 그 제목이 찍혀 있었다 | 서비스 창은 서버 글을 쓰지 않는다 — `>> logs\server.log 2>&1` (exe 도 같다) |
| ② 8000 을 두 프로그램이 잡음 | 예전에 켠 서버(옛 `start.bat` — `--reload` 는 SO_REUSEADDR 로 묶는다)가 남아 있으면 요청이 멈춘 쪽으로 갈 수 있다 | 켜기 전에 묻는다 (`python -m app.lan_check --preflight`): 0 비어 있음 → 켬 · 3 이 서버가 이미 응답 → 기다림 · 4 잡혔는데 응답 없음 → 말하고 기다림.  1·2 는 파이썬 자체 실패와 겹쳐 쓰지 않는다 (그때는 그냥 켜서 오류가 로그에 남게) |
| ③ 문지기가 첫 요청에서 DNS | `lan.Gate` 가 첫 요청 때 이 PC 이름을 DNS 로 풀어 대역을 쟀다 — 이벤트 루프 안이라 막히면 **localhost 요청까지** 기다린다 | 루프백 · 사설망은 대역을 재기 **전에** 받는다 (`client_allowed(host, nets)` 의 `nets` 가 함수일 수 있다) |

## 2. 점검 파일 — `check_pid_server.bat`

더블클릭하면 `python -m app.lan_check` 가 ① 포트 8000 을 잡은 프로그램(주소 · PID · 이름) ② `/version` ③ 첫 화면 자료 `/home`
④ 이 PC 사내망 주소의 `/version` 을 재고 판정을 한국어로 말한다.  같은 글이 `logs\lan_check.txt` 에 남는다.
**아무것도 끄지 않는다** — 둘 이상이면 `taskkill /PID n /F` 명령을 보여 줄 뿐이다 (대시보드 서버도 python 이다).

## 3. 확인

* 시험 `tests/test_hotfix52_lan_hang.py` 9건 — 서비스가 창에 쓰지 않음 · 켜기 전에 물음 · 연결은 받고 말이 없는 서버를
  `BUSY` 로 15초 안에 가름 · 이 서버/남의 웹 서버 구분 · 둘 이상일 때 PID 별 명령 · 응답 없을 때 Esc 안내 · 점검 파일은
  보기만 · 루프백/사설망은 대역을 안 잼 · 문지기가 localhost 에 대역을 안 잼.
* 실제 서버(사내망 모드 · 0.0.0.0:8000)로: 켜기 전 `--preflight` 0 · 켠 뒤 3 · 점검 결과 `/version 9 ms · /home 0.0 초 ·
  사내망 주소 4 ms · 서버는 정상`.
* 빠른 시험 801 통과.

  결과가 말해 준다.
