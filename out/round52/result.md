**한 줄**: 요구하신 20종을 도면에서 실제로 뽑았는지 **전수로 세어** 13종 출력 ·

## 1. r50 의 오보를 바로잡았습니다

| | r50 안내문 | 그 코드의 실제 | 이 꾸러미 |
| --- | ---: | ---: | ---: |
| AL NOUF1 행 | 1069 (계산값) | **1037** | **1069 (실측)** |
| Q'ty | — | 1931 | **2022** |
| 지문 | — | `fb85b039` | **`117b2d61`** |

50회차는 PDF 가 없어 저장된 결과와 ISA 표로 **계산**했고, 그 자리에서 실제로
틀렸습니다.  유도는 발동하고 있었는데(32건 · 내역이 예측과 글자 그대로 같음)
**그 32건이 한 행도 되지 않았습니다.**  원인 둘:

1. **같은 질문에 답하는 곳이 둘이고 갈렸습니다.**  `detect()` 는 그 도면 표에
   물어 답했는데, 파이프라인이 행을 만들 때 보는 `excel_type_under()` 는 사람이
   적은 사전만 보고 `None` 을 냈습니다.  `None` 이면 행이 되지 않습니다.
2. **ISA 표의 글자가 알파벳을 거의 덮어** 평범한 도면 낱말까지 분해됩니다
   (`DN` 129 · `GT` 112 · `VS` 96 · `HRSG` 84 …).  행은 안 되지만(버블 0)
   사람이 보는 미판정 목록이 87 → 1164 로 불어납니다 → **유도된 낱말은 버블이
   섰을 때만** 세도록 고쳤습니다.

**계산은 검증이 아닙니다.**  이번에는 PDF 를 받아 719초 · 4.9GB 로 실제 돌렸습니다.

## 2. 요구 20종 — 실측 전수 (AL NOUF1 1069행)

**출력 13종**

| 종 | 행 | 종 | 행 | 종 | 행 |
| --- | ---: | --- | ---: | --- | ---: |
| PI | 255 | LS | 58 | TW | 15 |
| PIT | 138 | MOV | 48 | AIT | 4 |
| TIT | 135 | FIT | 38 | PCV | 2 |
| LIT | 61 | FE | 23 | | |
| TI | 59 | XV | 18 | | |

`MOV`·`XV`·`PCV` 는 TYPE 열에 `MOV(GLOBE)`·`XV(ANGLE)`·`PCV(GLOBE)` 꼴로 나갑니다
(내역: MOV GLOBE 25 · GATE 16 · BUTTERFLY 6 · BALL 1 / XV GLOBE 12 · ANGLE 6).
`AIT`·`AT` 는 요구대로 **`Analyzer` 6행**입니다.

**미출력 7종 — `TG · PG · SG · PV · LV · TV · FV`**

도면이 그 글자를 인쇄하지 않습니다.  세 채널로 확인했습니다:

| 채널 | 결과 |
| --- | ---: |
| 네 프로젝트 버블 안 낱말 목록 | **0건** |
| AL NOUF1 인쇄 낱말 19,322개(종류 618) | **0건** |
| `PV-101` 처럼 붙여 쓴 꼴 | **0건** |

이 도면들은 게이지를 `PI`·`TI` 로, 제어 밸브를 `PCV`·`LCV`·`TCV`·`FCV` 로 씁니다.
**없는 것을 만들지 않았습니다.**

⚠ `PV = PCV` 규칙은 **넣지 않았습니다** — 발동할 자리가 0건이라 검증할 수 없는
규칙이 됩니다.  다음 도면이 `PV` 로 인쇄하면 **검출은 이미 됩니다**(범례 문자표가
`P`·`V` 를 둘 다 설명합니다).  남는 것은 TYPE 열 표기뿐이고 자리도 이미 있습니다
(`description.type_display_names` 두 줄).  산출물 탭은 표기가 아니라 **액추에이터**가
정하므로 한 줄도 안 바뀝니다.  **어느 이름으로 낼지는 정해 주셔야 합니다.**

## 3. AIT 가 나오는 근거

검출 실패가 아니었습니다 — 버블도 찾고 글자도 읽었는데 **사람이 적은 24항목
사전에 없어** 미판정으로 빠졌습니다.  이제 **그 도면의 범례 ISA 문자표**가 그
판정을 합니다.  행마다 근거가 붙습니다:

```
AIT → {"rule": "ISA_TABLE", "page_no": 3,
       "first": "A = ANALYSIS",
       "succeeding": ["I = INDICATOR", "T = TRANSMITTER DEVICE"]}
```

낱말 목록을 코드에 적은 것이 아닙니다 — `NOTE`(N 이 표에 없음) ·
`VBV`·`SSV`(V·B 가 없음) 는 **표가 스스로 거부해** 그대로 미판정입니다.

새로 서는 32행: `AIT` 4(p16) · `AT` 2(p14) · `PP` 8(p7·p16) · `ZSC` 7(p21) ·
`ZT` 6(p21·p28) · `ZS` 5(p16·p20).  **사라진 행 0** 이고, 기존 1037행 중 움직인
칸은 `needs_review` 8개뿐입니다(p11 FIT·FE — 문서 단위 문턱이 옮겨간 것이고
이미 알려진 감도입니다).

## 4. 새 축 — "도면에 인쇄된 것 중 얼마를 뽑았나" (축4)

정답지 없이 잽니다.  분모는 **버블이 선 계기 태그 + 그 도면이 버블에 인쇄한
밸브 태그**입니다.

| | 값 |
| --- | ---: |
| 축4 — 계기 | **98.8%** (917 / 928) |
| 축4 — 밸브 | 45.2% (84 / 186) |
| 종합 | **89.9%** |

밸브 태그별: `PSV 0/68` · `MOV 48/59` · `XV 18/21` · `TCV 8/13` · `HV 4/7` ·
`PCV 2/6` · `FCV 3/6` · `LCV 0/3`.

**미달 102 중 68이 PSV** 입니다 — 자력식 안전밸브라 발주처 산출물 범위 밖이고,
도면이 인쇄했으므로 분모에서 빼지 않고 그대로 갈라 적습니다.  **진짜 미검출은
32건**이고 그 안에 물어보신 제어 밸브가 있습니다 (`PCV` 4 · `FCV` 3 · `LCV` 3).
원인은 **낱말이 없어서가 아니라 밸브 몸체를 못 잡아서**입니다 — 다음 회차 대상.

## 5. 발주처 리스트와의 대조를 "참고" 로 내렸습니다 (52회차 · 사용자 확정)

*"발주처 xlsx 와 달라도 된다"* 를 반영했습니다.

| | 전 | 후 |
| --- | --- | --- |
| 도면 전수 추출(`derive_from_isa`) | 열린 판단 | **켬으로 확정** |
| 회귀 게이트 | 행·지문·Q'ty·축3 **+ 축1·축2** | 행·지문·Q'ty·축3 |
| 축1·축2 | 같지 않으면 실패 | **참고 지표** — 바닥 85% 만 |

**축을 지우지 않았습니다.**  축2 는 *발주처 리스트와 얼마나 다른가* 를 재는
유일한 자이고, 지우면 다음 회차에 도면을 잘못 읽어 무너져도 알 길이 없습니다.
가르는 것은 **원인**입니다 — 발주처가 안 세는 항목을 더 넣어 내려가는 것은
실패가 아니고, 도면을 잘못 읽어 무너지는 것은 실패입니다.  바닥값은 뒤엣것만
잡습니다.

되돌리려면 `config/project_alnouf1.yaml` 의 `anchors.derive_from_isa: false`
한 줄이면 49회차 값(1037 · `fb85b039` · 1931 · 축3 94.2)으로 **정확히** 돌아갑니다.
