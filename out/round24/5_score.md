# 24회차 [D] — 유도값이 손입력값을 재현하는가 · REV 가 읽히는가

도구는 `spike/hist_verify.py` 다.  세 경로를 나눠 잰다 — 설정값 그대로 ·
이력 칸만 유도값으로 · 유도값 전체를 얹고(낯선 양식에서 `_fit_layout` 이
실제로 하는 것).

## 1. AL NOUF1 — 유도가 손입력을 재현한다

| 칸 | 손입력 | 유도 |
| --- | --- | --- |
| `hist_rule_y` | [1200.0, 1390.0] | **[1249.1, 1383.2]** |
| `hist_rule_x0_max` | 1975.0 | **1979.3** |
| `hist_rule_x1_min` | 2320.0 | **2310.2** |
| `hist_rev_col` | [1971.0, 1988.0] | **[1970.7, 1988.0]** |
| `hist_date_col` | [1992.0, 2070.0] | **[1990.4, 2043.7]** |

숫자는 다르지만 **가리키는 것이 같다** — 손입력은 넉넉한 상자이고 유도값은
괘선에 붙은 상자다.  이력 칸만 유도값으로 바꿔 전 장을 다시 읽으면:

```
설정값 그대로       글리프 사전 {'1':116,'A':51,'B':42,'C':23,'D':7} · 이력 행 7 · REV 58/58
이력 칸만 유도값으로 글리프 사전 {'1':116,'A':51,'B':42,'C':23,'D':7} · 이력 행 7 · REV 58/58
```

**한 칸도 다르지 않다** (REV 분포도 B19 A15 C16 D7 A1:1 로 같다).

⚠ **파이프라인은 AL NOUF1 에 이 값을 얹지 않는다.**  `_fit_layout` 은
프로필이 그 문서의 것이고 기하를 적고 있으면 유도값을 **하나도** 쓰지
않는다.  그러므로 지문 `fb85b039` 는 구조적으로 안전하고, 위 대조는
"파이프라인이 그렇게 했다" 가 아니라 **"규칙이 맞다"** 를 잰 것이다.

## 2. TC2 — REV 0/60 → 60/60

```
설정값 그대로          글리프 사전 비어 있음 · 이력 행 0 · REV 0/60
유도값 전체를 얹고     글리프 사전 {'A': 60} · 이력 행 7 · REV 60/60 'A' HIGH
```

★ 원인은 하나였다 — **이력 행을 못 찾으면 글리프 사전이 비고, 사전이 비면
REV 칸을 읽어도 이름을 붙일 수 없다.**  TC2 의 REV 칸에는 개정 문자가
실제로 인쇄돼 있다 (연한 획 글꼴의 `A`).  이력 표를 찾자 그 문자에 이름이
붙었다.

⚠ **신뢰도 HIGH 는 이 경우 정보가 아니다.**  `classify` 는 사전에 문자가
하나뿐이면 2위가 없어 비율을 `inf` 로 낸다 — 무엇을 읽어도 HIGH 다.
그 값이 맞다는 근거는 신뢰도가 아니라 **도면 두 곳이 같은 말을 한다**는
것이다: REV 칸의 `A`(렌더 확인) · 이력 표 맨 아랫 개정 행의 `A` + `26.08.21`
+ `FOR INTERNAL USE`.

## 3. SADARA — 이력 행 0 → 7, REV 는 원래 읽히고 있었다

```
설정값 그대로          이력 행 0 · REV 1/9 (글리프 · 값 '11')
유도값 전체를 얹고     이력 행 7 · REV 9/9 (TEXT · A 4 · B 1 · D 4 · HIGH)
```

SADARA 의 타이틀블록 REV 칸은 **진짜 텍스트**라 글리프 사전을 쓰지 않는다
(`has_titleblock_text` 가 먼저 답한다).  즉 이번 변경은 SADARA 의 REV 에
닿지 않는다 — 축3 의 개정 지표가 9/9 로 그대로인 것이 그 증거다.

## 4. ★ SADARA·TC2 는 REV 칸에 개정 삼각형을 그린다 — 글리프 층의 문제

두 문서는 이력 표의 REV 칸마다 **개정 삼각형**을 그리고 그 안에 문자를 쓴다.
비어 있는 행에도 삼각형은 있으므로, 유도된 열(칸 전체)로 읽으면 빈 행에서도
"문자 하나"가 나온다.  SADARA 를 이력 칸만 유도값으로 읽으면 사전이
`A~G` 로 차는데 그 일곱은 전부 삼각형이다.

실제 파이프라인에서는 문제가 되지 않는다 — SADARA 는 TEXT 로 읽고, TC2 는
삼각형 안의 문자가 획으로 그려져 사전에 `A` 하나만 남는다.  그러나
**규칙으로서는 약한 자리**이므로 그대로 적어 둔다.  손으로 적은 SADARA 값
`[2740.0, 2755.0]` 은 삼각형 안쪽만 집는 좁은 띠였고, **도면은 그 좁은 띠에
대해 아무 말도 하지 않는다** (캡션 `REV.` 2735.7~2757.9 도 삼각형만큼 넓다).
문자와 그림을 가르는 것은 이력 표의 기하가 아니라 **글리프 층의 일**이다
(다음 회차).

## 5. 축3 — 예측 +16.7 대 실측 +17.2

| 프로젝트 | 23회차 | 24회차 | 움직인 지표 |
| --- | ---: | ---: | --- |
| AL NOUF1 | 94.8 | **95.0** | 파라미터 23/25 → 28/30 |
| SADARA | 74.8 | **75.3** | 파라미터 21/25 → 26/30 |
| TC2 | 64.8 | **82.0** | **개정 0/60 → 60/60** · 파라미터 19/23 → 24/28 |

23회차 로드맵은 이력 표에 **+16.7** 을 걸었다.  개정 지표는 여섯 중 하나이고
가중이 1/6 이므로 0 → 만점이 정확히 +16.67 이다 — **예측대로 맞았다.**
남은 **+0.5** 는 로드맵이 세지 않은 몫이다: 이력 표 다섯 칸이 이제
"그 도면에서 잰 파라미터" 로 세어져 파라미터 지표가 함께 올랐다.
같은 이유로 AL NOUF1 과 SADARA 도 각각 +0.2 · +0.5 올랐다.

**TC2 는 AL NOUF1 대비 68% → 86% 가 되었다.**
