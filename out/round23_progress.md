5. 빠른 시험 **213 통과**.
6. **★ UI 스위트 실패 — 데이터였다.**  실 DB 에 SCOPE 있는 분석이 없다.
   `spike/build_ui_db.py` 로 저장된 결과에서 다시 세웠다 (재분석 없음).
   첫 시도에 `pdf_path` 를 비워 둬 step7 이 실패하고 넷으로 번졌다 — 픽스처 결함.
7. 실 DB sha256 `643748dc0efe…` — 전 과정 불변.
8. **★ 대기 셸 셋이 8시간 40분 헛돌았다 (사용자가 중지).**  원인은 `pgrep -f` 자기참조 —
   조건문에 적은 `"pytest -q -m ui"` 가 **자기 셸의 명령줄에 걸린다** (재현: pytest 가
   0개인데 자기 셸 3개가 잡힘).  셋 다 자기 자신을 기다렸고, 그중 하나가 통과하면 UI 를
   띄울 셸이라 **UI 전량이 시작조차 되지 않았는데 "도는 중" 으로 보였다.**
   판정 근거는 로그 mtime 이다 — `slow.log` 14:33(14 passed) ↔ `ui.log` **14:08**(DB 고치기
   전 실행에서 멈춤).  규칙을 CLAUDE.md 에 박았다: 상한 `timeout 900` · 표식 파일로 기다림 ·
   `pgrep` 패턴을 자기 명령줄에 적지 않음 · 상한에 걸리면 실패로 적음.
