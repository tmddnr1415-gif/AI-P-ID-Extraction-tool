# 31회차 UI 자기검증 — 띄워서 누르고 글자를 읽었다

방법은 열 회차 넘게 같은 것이다: **저장된 결과로 임시 DB 를 세우고 서버를 띄워
실제로 눌러 보고, 화면이 한 말을 글자로 읽는다** (실 DB 는 열지 않는다 — 17회차 격리).
스크립트는 첫 화면 → 결과 화면 → 승수 패널의 **네 상태**를 지난다.

| 캡처 | 상태 |
| --- | --- |
| `A_지정전.png` | 지정 전 (적용 범위 · 사유 · 전/후 미리보기) |
| `B_작성자줄.png` | 작성자 확인 줄 (13회차 자기신고) |
| `C2_안내.png` | 저장 직후 안내 |
| `D_지정후.png` | 지정된 뒤 |
| `E_프로젝트없음.png` | **프로젝트에 안 묶인 분석** |

## 잡은 것 넷 — 전부 "코드는 도는데 화면이 다른 말을 한다"

### ① 마크다운 별표가 글자 그대로 보였다

안내가 `유닛 10 → x4 지정했습니다 — **다시 분석하면** 82행에 적용됩니다` 로 떴다.
`editNotice` 는 `textContent` 다.  같은 문제가 **사유 문장**에도 있었다 —
`_USER_MULTIPLIER` · `unit_multipliers.REASON` 의 `**사람이 지정한 값**` 은
REMARK 열과 근거 패널에 그대로 나간다.  이웃 사유(`_BORROWED_MULTIPLIER`)는
처음부터 맨 문장이라 **한 열에 두 문체가 섞이는** 상태였다.

→ 셋 다 맨 문장으로. 시험 `test_reason_text_carries_no_markdown_into_the_grid` ·
`test_edit_notice_arguments_carry_no_markdown` (호출만 세고 정의는 뺀다).

### ② ★ 화면이 "이미 반영된 것처럼" 읽혔다

지정한 뒤 패널에 남는 것은 `지정됨 x4 …` 와 `Q'ty 0 → 328` 뿐이고, *다시 분석해야
적용된다*는 사실은 **4.9초 뒤 사라지는 안내 줄에만** 있었다.  그리드의 82행은
그대로 빈칸인데 패널만 328 을 말한다 — 15회차가 `adopt_legend_profile` 에서
정한 규율(**바꿨다고 말하면서 바꾸지 않으면 화면이 거짓말을 한다**)의 위반이다.

→ 패널에 **상주하는** 한 줄(`.mpending`): `아직 이 결과에는 반영되지 않았습니다 —
다시 분석하면 82행에 적용됩니다`.  미리보기도 `→` 하나로 끝내지 않고
`지금 Q'ty 0 · 다시 분석하면 328 (82행 x 4)` 로 바꿨다.

### ③ 프로젝트에 안 묶인 분석에 **눌러도 안 되는 버튼**이 있었다

승수는 프로젝트의 사실이라 `job.project` 가 비면 저장할 자리가 없다.  그런데
패널은 폼을 그대로 내고, 누른 **뒤에야** 400 으로 사유를 말했다.

→ 폼 대신 사유를 낸다 (`E_프로젝트없음.png`):
`이 분석은 프로젝트에 묶여 있지 않아 승수를 저장할 자리가 없습니다 —
프로젝트를 고르고 다시 올리면 지정할 수 있습니다`.
**문장은 저장 함수가 쥔 것과 같은 사실**이고 두 벌을 두지 않는다.

### ④ 유닛코드를 못 읽은 묶음에도 폼이 있었다

키가 없으면 저장할 수 없다(`유닛코드가 비어 있습니다`).  같은 처리 —
`이 장들의 도면번호에서 유닛코드를 읽지 못해 지정할 열쇠가 없습니다`.

## 잡지 **않은** 것 — 제품이 아니라 픽스처였다

첫 화면이 이 분석을 `프로젝트에 묶이지 않은 분석` 으로 분류했다.  `GET /home` 은
**프로젝트 장부**(`revisions.list_projects`)를 읽는데 검증 픽스처가 `job.project`
열만 채우고 장부를 만들지 않았기 때문이다.  14회차의 규율 그대로 —
**제품이 틀렸나 가정이 틀렸나를 먼저 가른다.**  대신 그 덕분에 ③을 실제 화면에서
재현할 수 있었다.
