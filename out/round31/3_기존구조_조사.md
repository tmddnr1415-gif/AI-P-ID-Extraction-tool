# [B-0] 있는 것을 먼저 찾는다 — `axis_overrides` · 전역 심볼 사전

**§9-3 ①**: 새로 만들기 전에 ① 그 정보가 이미 있는가 ② 코드가 이미 그것을
찾고 있는가 ③ 찾고 있는데 쓰지 않는 것인가.  **답을 적고 시작한다.**

## 1. 두 구조는 각각 어디에 어떻게 저장되는가

| | `axis_overrides` (6회차) | 전역 심볼 사전 (18회차) |
| --- | --- | --- |
| **자리** | `{data_dir}/projects/{프로젝트}/axis_overrides.json` | `{data_dir}/global_symbols.json` |
| **범위** | **프로젝트 하나** | **모든 프로젝트** |
| **키** | **안정 ID** (`10LBA10-001`) — 행 하나 | `signature_key` — 심볼 모양 하나 |
| **값** | from · to · 출처 · type · sentence · confirmed_at · origin_job | kind · name · signature · registered_by · 일시 |
| **작성자** | `origin_job` 은 있으나 **사람 이름은 없다** | **`author` 없이 등록 불가** (13회차 자기신고) |
| **끄기** | 없음 | `enabled: false` 한 줄 — 사전이 없던 때와 **정확히** 같아진다 |
| **우선순위** | 사용자 확정이 이긴다 (`user_values`, `ai_values` 를 덮지 않음) | **범례가 이긴다** (`resolve(..., legend_has=True)` → None) |
| **파이프라인** | `main.py` 가 읽어 행에 얹는다 | 파이프라인은 **읽기만** 한다 |
| **리비전** | 안정 ID 로 **자동 승계** | 해당 없음 (프로젝트 무관) |

세 번째 이웃도 같은 뿌리에 있다 — **범례 프로필**(15회차)
`{data_dir}/projects/{프로젝트}/legend_profile.json`.

## 2. 승수에 그대로 쓸 수 있는 것은 어느 쪽인가 — **둘 다 아니다**

승수의 성질을 먼저 적는다.

```
· 프로젝트 하나의 사실이다 (그 플랜트에서 유닛 10 이 몇 벌인가).
  업계 관행이 아니다 → 전역 사전의 범위는 틀리다
· 키는 **유닛코드**(`10`)이지 행이 아니다.  SADARA 는 유닛 하나에 82행이다
  → axis_overrides 의 키 알갱이는 틀리다 (82개를 써야 한다)
· 도면이 말하지 않아서 사람이 답하는 값이다 → 범례가 이겨야 한다
· 팀이 공유한다 → 누가 넣었는지 남아야 한다
```

| 후보 | 범위 | 키 | 작성자 | 범례 우선 | 끄기 | 결론 |
| --- | --- | --- | --- | --- | --- | --- |
| `axis_overrides` 확장 | ✔ 프로젝트 | ✘ 행 단위 | ✘ 없음 | ✘ 사람이 이긴다 | ✘ | **부적합** |
| 전역 심볼 사전 확장 | ✘ 전 프로젝트 | ✘ 심볼 | ✔ | ✔ | ✔ | **부적합** |
| 범례 프로필에 섞기 | ✔ | ✔ | ✘ | — | ✘ | **부적합** (아래 3) |

## 3. 범례 프로필에 섞으면 안 되는 이유

15회차 [4]가 못박아 둔 것이다 — 프로필은 **범례가 말한 것**만 담는다.
사람 값을 같은 파일에 섞으면 *"프로필이 범례 값을 정확히 담았는지 확인할 길"*
이 사라진다 (그 회차가 `source` 를 안 바꾼 이유와 같다).
**범례가 말한 것과 사람이 답한 것은 다른 파일에 둔다.**

## 4. 그래서 — **새 파일이되 새 개념은 없다**

두 구조에서 **각자 옳은 반쪽**을 가져온다.

```
자리·범위   ← axis_overrides   {data_dir}/projects/{프로젝트}/unit_multipliers.json
모양·규율   ← 전역 심볼 사전     author 필수 · 읽는 곳 하나 · 범례가 이긴다 · enabled 스위치
```

**새로 만드는 것은 파일 하나와 그것을 읽는 한 줄뿐이고, 규율은 전부 재사용이다.**

## 5. "찾고 있는데 안 쓰던 것" 이 있었는가 — **반쯤 있었다 (열두 번째)**

`_note_factor`(27회차)는 이미 **§9 의 읽는 순서를 구현해 둔 함수**다:

```python
① 범례 → ② NOTES → ③ 프로젝트 설정 폴백 → ④ 빈칸
```

즉 **③ 자리에 넣을 값이 없었을 뿐, 넣을 자리는 이미 있었다.**  이번 구현은
그 함수에 인자 하나를 더하는 것이고, 두 호출부(`_field_rows` · `_valve_rows`)가
이미 같은 함수를 쓰므로 **읽는 곳이 하나**라는 규율도 이미 지켜져 있다.

`_BORROWED_MULTIPLIER` 사유 문구(26회차)도 이미 있다 — *"이 도면의 범례가
아니라 프로젝트 설정에서 왔습니다 … 확인 필요"*.  **확인해 달라고 적어 두고
확인할 자리를 안 만든 것**이 지금까지의 상태다.

## 6. 파이프라인이 파일을 읽지 않는다 — 15회차 방식 그대로

`analyse(..., legend_profile=...)` 와 **같은 모양**으로
`analyse(..., unit_multipliers=...)` 를 받는다.

* `main.py` 가 프로젝트 폴더에서 읽어 넘긴다 (프로젝트에 안 묶인 분석은 `None`).
* `spike/analyse_one.py`(회귀 하네스)는 **아무 것도 넘기지 않는다** → `None`.
  **그래서 게이트 1(사람 값 없을 때 네 프로젝트 불변)이 구조적으로 보장된다.**
