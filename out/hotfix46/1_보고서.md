# hotfix46 — 개정 대조는 태그로만 · 실행 프로젝트만 (위치로는 비교하지 않는다)

사용자: *"나란히 대조는 실행 프로젝트만 해당되며 tag 위주로 비교한다.  동일 tag 와 abbreviation 기준
(TIT 등).  PDF 상의 위치 좌표로는 비교하지 않는다."*

**엔진 0줄 · 네 프로젝트 기준선 불변** — 바뀐 것은 분석 **뒤** 단계(`revisions.compare` · `_run_comparison` ·
`/revision` · 화면)뿐이고 지문·행·Q'ty 에 닿는 코드가 없다.  빠른 시험 742 → **752**.

## 1. 규칙

| | hotfix38~45 | hotfix46 |
| --- | --- | --- |
| 짝의 열쇠 | (TYPE, 태그) 유일 → **상호 최근접 → 거리순 → 태그 다른 쌍**(반경 안) | **(TYPE, 태그) 유일 하나** |
| 같은 자리의 다른 태그 | 자리로 이어 "수정 (tag_no)" | **삭제 후보 + 추가** (같은 항목이라고 도면이 말한 적 없다) |
| 태그 없는 행 | 반경 안 같은 TYPE 과 기하로 짝 → 변경 없음/추가/삭제 후보 | **대조 안 함 (`NOT_COMPARED`)** — 추가도 삭제도 아니다 |
| 같은 태그가 둘 이상 | 기하로 | 대조 안 함 |
| 입찰 프로젝트 | 기하로 전부 대조 | **대조하지 않는다** (`compare_basis: NONE` · 나란히 버튼 없음) |
| 실행/입찰 판정 | — | `_mode_facts(job).effective` 하나 (화면 띠가 읽는 것과 같은 함수) |

`PI` 와 `PIT` 가 같은 태그를 들어도 다른 항목이다 (abbreviation 기준 · hotfix35).  태그가 같으면 종이 한 장을
가로질러 옮겨도 변경 없음이고 거리는 `moved_pt` 로 **기록만** 된다.  삭제 후보의 `anchor` 는 이전 도면 위에
표식을 그리는 자리일 뿐 판정이 아니다 — 반경·최근접 칸은 더 이상 내지 않는다 (옛 대조가 남긴 값만 "옛 대조" 로 보인다).

## 3. 화면

* 나란히 버튼·자동 켜짐은 `compare_basis === "TAG"` 일 때만.  입찰 프로젝트는 버튼 대신 *"입찰 프로젝트 — 태그가
  없어 개정 대조(나란히)를 하지 않습니다"*.  머리줄은 `짝 태그 N · 대조 안 함(태그 없음) N` (기하 칸은 옛 대조에만).
* 근거 패널 — 대조 안 한 행은 `대조 안 함 — Rev.A 대비 · 태그 없음`(또는 "같은 태그가 둘 이상").  삭제 후보 패널에서
  반경·최근접 줄은 옛 대조 값이 있을 때만 "(옛 대조)" 로.
* 기능 자기검증(`out/hotfix46/ui_func/` · hotfix40 도구 그대로): p41 변경 38 (＋4 －34 · 수정 0) · MOD 고리 **0** ·
  ADD 유령 4 · ▶ 로 두 창 동기 · 삭제 항목 선택 · 직전에만 있는 장 · Excel 200 · 끔 뒤 목록 복귀 · 페이지 오류 0.

## 4. 영향과 한계

* **입찰 프로젝트의 편집 승계(13회차 `_carry_edits`)는 리비전 사이에 이어지지 않는다** — 짝이 안정 ID 인데 태그 없는
  행은 매 리비전 새 ID 를 받는다.  위치로 잇는 것이 곧 위치 비교이므로 두지 않았다.  실행 프로젝트의 태그 있는 행은 그대로 승계된다.
* 태그 없는 옛 기록은 장부(`id_registry.json`)에 `active` 로 남는다 — 지우지 않는다 (ID 회수 금지 §7.3).
* 이미 대조해 둔 결과에는 옛 판정이 남는다 — `대조 다시`(hotfix44) 한 번이면 새 규칙으로 바뀐다 (QFE 8.6초).
* ⚠ 못 잰 것 — SADARA·UAD PDF · Excel 양식 (이 환경에 없음).  네 프로젝트 지문은 구조적으로 불변 (분석 뒤 단계).
