# [E] 결론 — 32회차

**이 회차는 구현하지 않았다.  엔진 코드는 0줄이고, 회귀 넷이 시작과 끝에서
같다** (AL NOUF1 `fb85b039`·1037·1931 · SADARA `0767ba79`·82 · TC2
`c0a2d29d`·607 · UAD `db1a77d1`·149 · 축3 95.1 / 75.4 / 89.1 / 83.0 ·
빠른 시험 **266 통과** · 실 DB sha256 `643748dc…` 불변).

닫는 측정은 **순서 시험 여덟 번**이다 — 한 프로세스에서 네 문서를
`AL NOUF1 → SADARA → TC2 → UAD` 와 **그 역순**으로 돌렸고 행·지문·Q'ty 가
여덟 번 다 같다.  ⚠ 다만 **메모리는 안 돌아온다** (한 프로세스 최대 RSS 가
TC2 를 지나면 7.4GB 로 올라가 그대로다) — 이어 분석하는 실제 사용 형태는
회귀 하네스의 자식 프로세스 보호를 못 받는다.

## 1. AL NOUF1 처럼 표시되는가 — **자리는 그렇다.  색은 아니다**

* **자리는 넷 다 같다.**  28장을 같은 조건(맞춤 배율)으로 찍었고 오버레이가
  어긋난 장이 **없다**.  세 단계 확대 캡처가 A3 `/Rotate 270` 에서도 상자가
  버블 **윤곽**에 맞는 것을 보여 준다.  범례 네 칸의 합 = 그려진 상자 수 =
  그리드 행 수가 28장 전부에서 맞는다.
* **색은 둘에서 없다.**  `pipeline.py:930` 한 줄이 **검토 사유를 SCOPE 보다
  먼저** 읽는다.  SADARA 82/82 · UAD 149/149 가 검토 필요라 도면 위가 전부
  빨강이고, 범례는 `SCT 공급 범위 0` 이라고 적는다 — **그 행들은 SCT 인데.**
  원인은 31회차가 만든 승수 사유이고, 사람이 승수를 한 번 답하면 사라진다.
  즉 **"값이 안 들어온 상태" 가 표시까지 덮는다.**
* TC2 는 8장 중 5장에서 SCOPE 색이 보인다 — 같은 규칙의 반대 증거다.

**한 줄로: 넷 다 "AL NOUF1 처럼" 그린다.  그런데 둘은 그린 것을 한 색으로 덮는다.**

## 2. 다섯째 프로젝트가 들어오면 되는가 — **돈다.  다만 두 자리에서 멈출 수 있다**

* **아무것도 안 채워도 돈다.**  SADARA·TC2·UAD 세 기준선이 전부 프로젝트
  설정 없이(AL NOUF1 config 로) 나온 값이다.  그 문서에서 **25항목 중 23**이
  유도돼 얹힌다 (SADARA 실측).
* **손으로 할 것 — 8개.**  `formats.drawing_no` · `title_block.hist_row_inset`
  · 유닛 승수 · `excel.*` 열 매핑 · `description` 어휘 · `revision.document_rule`
  · `client_form.scope_filter`/`scope.exclusion_rules` · `project.code`/`name`.
  ★ **`state_and_roadmap` §7 과 `new_form_checklist` §3 과 API 가 아직 "이력 표
  여섯 칸" 이라고 적는데, 24회차가 다섯을 유도로 바꿨다.  지금 이력 표에서
  손으로 잴 것은 `hist_row_inset` 하나다** (세 자리 다 고쳐야 한다).
* **멈출 자리 — 2개.**  `LegendUnavailable` · `TitleBlockUnreadable`.
  합성 도면 여섯 개가 실제로 그 둘에 걸렸고 **조용한 0행은 한 번도 없었다.**
  문장도 구체적이다(무엇을 하면 되는지까지).
* **★ 죽는 자리 — 1개 (새로 찾았다).**  태그가 **밸브 사각형 안**에 인쇄된
  1급 도면이 오면 `AttributeError` 로 끝난다 (`pipeline.py:1042` 가 dict 를
  기대하는데 `:3139` 이 문자열을 넣는다).  UAD 가 안 죽는 것은 **밸브 3행에
  태그가 하나도 안 붙은 우연**이다.  사유 있는 정지가 아니라서 화면에는
  일반 문구가 간다.
* **조용히 폴백할 자리 — 3개** (`mark_above`/`mark_side` · 액추에이터 기하 ·
  `description` 어휘).  범례 여덟 항목은 **시끄럽다**(띠가 `유도 실패 N` 을
  적는다: SADARA 2 · TC2 2 · UAD 3) — 다만 *누구의 값으로 대신했는지* 는
  안 말한다.  `brk_max_mark` 는 **재고 있고 사유까지 기록되는데 화면이 안
  말한다**(결과 json 안에만 있다).  그리고 **틀린 말을 하는 자리가 하나** —
  도면번호를 못 읽은 장을 화면이 `도면이 아님 (UNKNOWN)` 이라고 적는다
  (TC2 4장).

### 축3 예상 — **75 ~ 89, 승수가 갈린다**

여섯 지표를 같은 무게로 재므로 산술이 그대로 답한다.  네 실측에서
**수량 지표가 0 이냐 1 이냐가 ±16.7점**이다:

| 경우 | 계산 | 예상 |
| --- | --- | ---: |
| 승수를 도면이 말한다 (TC2·UAD 꼴) | 나머지 다섯이 .70~1.0 | **83 ~ 89** |
| 승수를 도면이 말하지 않는다 (SADARA 꼴) | 수량 0/N | **66 ~ 75** |
| 사람이 승수를 한 번 답한다 (31회차 경로) | SADARA 75.4 → 92.0 실측 | **+16.7** |

**도면번호 형식이 다르면 이 계산 자체가 성립하지 않는다** — 한 장도 못 읽으면
`TitleBlockUnreadable` 로 멈춘다 (그것이 맞는 동작이다).

## 3. 이 회차에 스스로 뒤집은 것 — **다섯**

1. 배율 합성이 낱말을 잃는다 → **쪽 번호를 잘못 맞춘 내 실수**.  실제로 잃는
   것은 회전된 원본 장 하나뿐이다 (378→378 · 658→658).
2. ⑦ 이력 표를 클립으로 없앴다 → **클립도 가리기만 한다**.  띠 안 도형이
   248 → 744 로 늘었다.  ⑦ 은 아무 것도 증명하지 못한다.
3. ⑧ 을 A4+태그로 만들었다 → **두 축을 한꺼번에 바꿨다**.  ⑧b 를 따로 만들었다.
4. "이력 표 여섯 칸을 손으로 잰다" → **다섯은 이미 유도된다** (문서가 사실보다
   나쁘게 적고 있었다).
5. `brk_max_mark` 는 유도 코드가 없다 → **있다.  재고 나서 안 쓰기로 한 것**이고
   사유도 기록돼 있다.
