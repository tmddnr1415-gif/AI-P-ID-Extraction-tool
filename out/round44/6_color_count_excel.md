# [E] 색 · 카운팅 · Excel · 측정

## E-1 색 규칙 — (b) 색은 SCOPE, 마크업은 표식

세 안 중 **(b)** 를 골랐다.  이유는 33회차와 같다: "누가 공급하는가" 와 "누가 표시했는가"
는 다른 축이고, 한 테두리가 두 축을 말하면 하나가 다른 하나를 덮는다.
(a)(마크업 색 + SCOPE 테두리)는 SCOPE 색을 잃고, (c)(마크업 색 + SCOPE 라벨)는 라벨을
읽어야 색이 뜻을 갖는다.  (b) 는 색 + 형태(점선 · 모서리 표식) + 라벨(범례 문장) 셋이
같이 실린다 (§7.2).

| 축 | 어디 | 무엇 |
| --- | --- | --- |
| SCOPE | 테두리 **색** | 파랑 SCT · 주황 VENDOR · 보라 판정 없음 (그대로) |
| 종류 | 테두리 파선 | 밸브 `5 3` (그대로) |
| 개정 | 바깥 링 | ADDED · MODIFIED (그대로) |
| 검토 필요 | **오른쪽 위** 붉은 ● `!` | 33회차 그대로 |
| **사용자 추가** | 테두리 **점선 `1.5 2.5`** + **왼쪽 위** 초록 ● `+` | 44회차 |
| **오검출 표시** | 상자 흐리게(opacity .55) + **오른쪽 아래** 회색 ● `×` | 44회차 |

세 표식이 **서로 다른 모서리**라 겹치지 않는다 (검토 ● 와 충돌 금지 요구).  각 표식은 범례에서
따로 끌 수 있고 상자와 같은 키로 클릭이 통한다.

## E-2 범례 카운팅 — 후보 A, 등식 불변

`buildOverlayLegend` 는 `overlayItems(page)` 를 `itemScope` 로 세 색 칸에 세고, `needs_review`

→ **세 색 칸 합 = 상자 수 = 그리드 행 수(+EXCLUDED 마크)** 그대로.  UI 시험

## E-3 Excel — REMARK 앞머리 · 새 열 없음 · 결정성

* 나가는 행: `db.snapshot` → `write_all` → `in_client_scope(row)` — 추가 행은 **자기 SCOPE
  값**으로 같은 필터를 지난다 (`scope_source=USER` 여도 값으로 판정).  오검출 `exclude=true`
  면 `removed=1` 로 스냅샷에서 빠지고, `exclude=false` 면 그대로 나간다.
* 표시: `_remark` 앞머리 `사용자 추가 · <작성자>` / `사용자 표시: 오검출 의심 (메모) · <작성자>`.
  후보 셋 중 이것만 남았다 — 행 칠하기는 §7.1 "Rev.A 무음영" 과 충돌, 별도 시트는 양식 변경.
  `MANUAL_*` 코드는 사유 목록에서 뺀다 ("→ 미처리" 로 읽히지 않게).
* 결정성: 시각을 적지 않는다.  `_remark` 순수 함수 · 정렬은 `excel_no`/(system,page,key).
  시험 `test_remark_marks_markup_rows_without_a_timestamp` (같은 입력 두 번 = 같은 문장 · 네
  자리 숫자 없음).  마크업 없으면 `_remark` 결과가 예전과 같다 (`None`).
* 게이트: 마크업 0 → 885 / 76 / 23 (17단계 검증 s9) · 마크업 1 → 886 (s16 실측 — 값은
  `out/round44/verify/state.json`).

### 축5(마크업 정답지) — 판단

**지금은 더하지 않는 것이 맞다.**  근거 셋:
1. **표본이 아직 없다.**  축은 정의만으로 서지 않는다 — 발주처 리스트(축1·2)는 557행, 축3 은
   도면이 인쇄한 것 전부가 분모다.  마크업 정답지는 사람이 본 **장**만 분모이고, 오늘 그 장은
   0 장이다.  최소 표본은 "한 프로젝트에서 사람이 전 장을 본 것" 이어야 장 단위 편향(쉬운 장만
   본다)을 피할 수 있다 — AL NOUF1 이면 52 장.
2. **정의가 축2 와 겹친다.**  마크업이 ㉡ 미검출 · ㉢ 오검출을 세면 그것은 곧 재현율·정밀도이고,
   AL NOUF1 에서는 축2 가 이미 그것을 발주처 리스트로 잰다.  둘이 다른 값을 내면 어느 쪽이
   정답인지 또 물어야 한다.  축5 의 자리는 **정답지가 없는 프로젝트**(SADARA · TC2 · UAD)다.
3. **피드백 zip 이 곧 표본 축적이다.**  `feedback.json` 의 `items` 가 (장, 종류, 사각형, 값)
   을 갖고 있어 나중에 축5 를 정의할 때 다시 모을 것이 없다.  먼저 모으고, 표본이 한 프로젝트
   전 장을 채우면 그때 정의를 낸다.

넣게 된다면 정의 후보: 사람이 본 장 집합 P 에 대해 `재현율 = 검출행 / (검출행 + 미검출 표시)` ·
`정밀도 = (검출행 − 오검출 표시) / 검출행`, 분모에 마크업 행을 넣지 않는다(마크업 행은 정답
이지 검출이 아니다).  **결정은 사용자 몫.**
