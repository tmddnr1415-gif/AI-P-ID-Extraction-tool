## 1. ★ 주원인 — 정의줄 획수 게이트가 본문 별표를 버린다

`detect_symbols.star_marks` 의 세 조건 중 하나:

```python
defn = definition_star(pc, lay, maxlen)
if defn:
    groups = [g for g in groups if g[1] == defn[0]]   # 획 수가 정의줄과 같아야 한다
```

p6 실측 — 별표는 **찾고 있었다**:

| 단계 | 개수 |
| --- | ---: |
| ① `star_groups` 획 뭉치 | 12 |
| ② 그중 버블 마크 창 안 | **9** |
| ③ 정의줄 획 수 통과 | **0** ← 여기서 죽는다 |
| ⑤ `star_marks` 결과 | 0 |

**정의줄의 별표는 2획(1.8×1.7pt), 본문의 별표는 4획(2.9×2.9pt)** 이다.
같은 문서가 같은 기호를 두 가지로 그린다.

전 문서 (`spike/star_recall.py`):

| 문서 | ②버블 마크 자리의 별표 | ⑤마크가 된 것 | 게이트가 버린 것 |
| --- | ---: | ---: | ---: |
| TC2 | **254** | 71 | **174 (68.5%)** |
| AL NOUF1 | 278 | 2 | 274 |

**게이트가 걸리는 장은 정의줄이 있는 장이고, 통과하는 장은 정의줄이 없는 장**이다
(TC2 에서 마크가 나온 9장은 전부 `정의줄 없음`).  즉 **별표의 뜻을 아는 장에서만
별표를 버린다** — 규칙의 방향이 뒤집혀 있다.

AL NOUF1 이 멀쩡했던 이유는 게이트가 옳아서가 아니다.  그 문서는 별표를 **한 path
에 획 여섯**으로 그려서 옛 경로(`_glyph_clusters`)가 이미 전부 잡고 있었고, 버려진
274개는 **같은 별표를 획으로 다시 본 것**이라 `existing` 중복 제거에 걸릴 것들이었다.

## 3. 둘째 원인 — 정의줄 `* By SE` 를 사전으로 못 읽는다

`read_mark_dictionary` 는 정의줄의 별표를 `_glyph_clusters` 로만 찾는다.  TC2 는 그
별표도 획을 따로 그리므로(2획 1.8pt) 뭉치가 안 되고, **p6 의 사전은 `{}`** 다.
그래서 게이트를 고쳐도 그 행들은 `VENDOR(SE)` 가 아니라 **이름 없는 `VENDOR`** 가 된다
(`_scope_of` ③ — 이름을 지어내지 않는다).

25회차는 `find_marks` 쪽만 획으로 읽게 고쳤고 **사전 쪽은 그대로 두었다.**
`definition_star` 가 이미 그 별표를 획으로 읽고 있으므로(2획 1.8×1.7 을 냈다)
**코드가 찾고 있는데 사전이 쓰지 않는다** — §9 3③ 의 여덟 번째 사례다.

## 4. 셋째 원인 — 화면이 전부 빨강인 것은 별표와 무관하다

사진 1의 범례는 `SCT 0 · VENDOR 0 · 판정 없음 0 · 검토 필요 15` 다.
오버레이 색은 `needs_review` 가 **먼저** 이긴다 (`pipeline._layers`).
p6 15행은 전부 검토 필요이고 사유는 하나다:

```
unit code '31' is not in the legend's UNIT IDENTIFICATION NUMBERS table,
so no multiplier
```

전 문서 607행 중 **351행**이 검토 필요이고 그중 **261행이 이 승수표 사유**다.
즉 **별표를 고쳐도 이 장의 오버레이는 계속 빨강**이다 — 표의 SCOPE 열에서는
갈리지만 그림에서는 안 갈린다.  이것은 23회차 로드맵의 **승수표** 항목이다.

## 5. 왜 25회차가 못 잡았나 — 같은 함정 세 번째

25회차는 **정밀도만 쟀다** — "더한 71개가 전부 별표인가" (접촉 시트로 확인, 맞다).
**재현율은 재지 않았다** — "그 장이 인쇄한 별표 중 몇 개를 냈는가".
접촉 시트는 **찾은 것만** 보여 주므로 못 찾은 것을 드러낼 수 없다.

19회차가 이미 두 질문(*알아봤는가* · *붙었는가*)을 못박아 두었는데, 그 감사기는
AL NOUF1 전용(`tests/test_vendor_mark_audit.py`)이고 **TC2 의 새 규칙에는 같은 질문을
걸지 않았다.**  16 → 18 → 19 회차와 같은 모양이다.

## 6. 남는 판단

* 게이트는 **두 문서 모두에서 거짓**이다 (정의줄 2획 ↔ 본문 4획).  빼는 것이
  맞아 보이지만, 뺀 뒤에는 세 프로젝트 회귀(약 25분)와 AL NOUF1 지문
  `fb85b039` 확인이 필요하다.  측정으로는 붙음이 336 → 336 이라 움직이지 않을
  것으로 보이나 **밸브·패키지 상자 경로는 이 측정이 보지 않았다.**
* 사전(§3)과 승수표(§4)는 별표와 **다른 축**이다.  셋을 한 회차에 섞을지,
  별표만 먼저 고칠지는 실무 판단이다.
* 고친 뒤에는 **재현율 감사**를 시험에 박아야 같은 일이 네 번째로 반복되지 않는다.
