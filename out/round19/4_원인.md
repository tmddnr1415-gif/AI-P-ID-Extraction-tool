# 19회차 [C] — 왜 두 번이나 못 잡았는가

이 회차의 목표는 "고쳤다" 가 아니라 **원인 규명**이다.  같은 지적이 세 번
반복됐다.

```
2차 피드백   별표 있는데 SCT — 여러 장
16회차       "58장 전수 0건" → 거짓.  검사가 판정 함수에게 되물었다
3차 피드백   같은 지적
18회차 [C]   p35 5행 수정.  "범례는 뜻을 정하지 축척을 정하지 않는다"
             ★ 그리고 이때 **검사기 자체를 검증하는 시험**을 만들었다
4차 피드백   같은 지적.  이번엔 p25 · p27 · p30
```

**18회차가 검사기를 검증했는데도 못 잡았다.**  이 문장이 이 회차의 출발점이다.

---

## 원인은 넷이다

### ① 마크 자리 창이 "버블 **위**" 하나뿐이었다

`in_mark_window` 이전의 식은 세 곳에 같은 모양으로 베껴져 있었다:

```
rect.x0 - mark_x_slack <= x <= rect.x1 + mark_x_slack      (6.0)
rect.y0 - mark_above   <= y <= rect.y0                     (25.0)
```

이 식은 **"별표는 버블 위에 찍힌다"** 를 가정한다.  근거는 11회차의 p6
실측 하나였다 (별표 y=526 · M 원 y0=534.4 → 8.4pt 위).

그런데 이 문서는 별표를 **옆에도** 찍는다.  실측 — 마크 646개를 유클리드
최근접 버블에 붙여 가로 간격을 세면:

| 가로 간격 | 개수 |
| --- | ---: |
| 0.00 ~ 8.58pt | **386** (8.49~8.58 에만 63개 — 옆자리 무리) |
| **8.58 ~ 10.59** | **0** ← 빈 띠 |
| 10.59 | 1 |
| 14.10 ~ 14.13 | 3 |
| 20.28 이상 | 나머지 |

문턱을 그 빈 띠 안 어디에 두어도 결과가 같으므로 `mark_side = 10.0` 은
임의값이 아니다 (17회차 C-4 · 16회차 `brk_max_mark` 와 같은 논법).

**더 나쁜 것은 크기 축으로 번진 것이다.**  `drawn_mark_sizes` 가 같은
창으로 "마크 자리에 있는 글리프"를 세어 크기를 배우므로, 옆에 찍힌 별표는
**크기조차 인정되지 않아** `find_marks` 단계에서 이미 떨어졌다.  18회차가
고친 크기 축이 자리 축에 의존하고 있었다.

**창을 사각형 하나로 합쳤다.**  두 갈래로 쪼개 놓았더니 p52 에서 걸렸다 —
별표가 버블 위 테두리선에 정확히 걸쳐 찍혀서 중심이 `y0` 보다
**0.00002pt** 위에 있었고, 그것이 "위" 도 "옆" 도 아니게 됐다
(`k.y = 239.0201187` ↔ `b.y0 = 239.0201416`).

**아래는 넣지 않았다 — 이번엔 근거가 있다.**  25pt 안에서 버블 아래에 찍힌
마크를 **전부 렌더로 확인**했더니 한 개도 그 버블의 것이 아니었다:

| 장 | 아래 간격 | 실제 주인 |
| --- | ---: | --- |
| p7 | +8.4pt | PCV·MOV 의 **액추에이터**(돔 · M 원) — 11회차 [B] 가 이미 세는 자리 |
| p33 | +7.2pt | LG 버블이 아니라 옆 **사각 심볼** |
| p20 | +17.1pt | 오른쪽 **밸브** |
| p26·p27 | +49.6pt | 액추에이터 스템 **해칭** (마크가 아니다) |

아래를 8pt 열면 이 다섯 장에서 18건이 붙고 **그중 옳은 것은 0** 이다.

### ② ★ 감사도 "자리" 축을 판정기와 공유하고 있었다

18회차의 `tests/test_vendor_mark_audit.py` 는 이렇게 독립을 주장했다:

```
크기 축   find_marks 를 안 부른다              → 독립  ○
자리 축   b.y0 - mark_above <= cy <= b.y0      → 공유  ×
          x ± mark_x_slack                       (판정기와 똑같은 식)
```

그래서 감사는 **판정기와 같은 눈**으로 봤고, 옆에 찍힌 별표는 양쪽 어디에도
안 보였다.  변이 시험도 **크기만** 흔들었지 자리는 흔들지 않았다.

16회차가 "검출기에게 되물어" 거짓 0 을 낸 것과 **같은 실패의 다른 축**이다.
16회차는 한 축을 공유했고, 18회차는 그 축을 고치면서 **다른 축을 그대로
물려받았다.**

고친 것 둘:

- `glyphs_near_bubbles` — 판정기의 창을 **쓰지 않는다**.  방향을 가리지 않고
  가장 가까운 버블에 붙인다 (반경 25.0, 판정기의 어느 창보다 넓다)
- 변이 시험을 **자리 축으로도** 만든다 (`..._made_blind_sideways`) — 마크
  창을 18회차의 것(위 하나)으로 되돌리면 감사가 반드시 잡아야 한다

### ③ 마크 소유자를 가로 간격 하나로만 갈랐다

16회차의 `_x_gap` 은 가로만 봤다.  그때는 창도 가로로만 애매해서 충분했지만,
①로 창이 세로로 뻗자 **세로로 쌓인 버블**을 못 가르게 됐다.  p9 은 버블
5개가 한 줄로 서고 가로 간격이 전부 5.64pt 로 같아서, 각 버블이 자기 `**` 와
위 버블의 것을 합쳐 **3★·4★** 가 됐다 (그 장 NOTES 는 1★·2★ 만 정의).

**체비쇼프(max)로도 안 된다** — 두 경우가 서로 반대를 요구한다:

| 장 | 갈리지 않는 축 | 갈리는 축 |
| --- | --- | --- |
| p25 | 세로 5.67 ↔ 5.67 | 가로 **0.09 ↔ 2.85** |
| p9 | 가로 5.64 ↔ 5.64 | 세로 **0.0 ↔ 21.9** |

`max` 는 각 경우에서 **갈리는 축을 버린다** → 무승부 → 둘 다 가져간다.
유클리드는 두 축을 다 쓰므로 둘 다 맞는다.

| 소유자 metric | 전 도면 UNDEFINED | p25 PT | p9 |
| --- | ---: | --- | --- |
| 가로만 (16회차) | 20 | 1★ ○ | 3★ × |
| 체비쇼프 | 16 | 2★ × | 2★ ○ |
| **유클리드** | **15** | **1★ ○** | **2★ ○** |

렌더가 정답을 준다: p25 는 버블마다 `*` 하나(왼쪽 위 모서리), p9 은 버블마다
`**`(오른쪽, 세로로 두 개).

### ④ 밸브는 액추에이터 하나만 봤다

11회차는 밸브의 별표를 **액추에이터 심볼**에서만 찾도록 정했다.  근거는 p6
GATE 실측 하나였고 그 실측은 맞다.  **그러나 한 장의 실측이었다.**

| 장 | 별표 | 몸체까지 | 액추에이터까지 |
| --- | --- | ---: | ---: |
| p6 GATE | y=526 | 37.5pt (밖) | **8.4pt** |
| p27 BFV | x=480.5 | **8.1pt** | 30pt (밖) |

그래서 4차 피드백 9p 가 지목한 p27 의 BFV 세 행이 별표를 갖고도 SCT 로
남았다.  고친 방법은 허용치가 아니라 **보는 사각형**이다 —
`read_vendor_mark(also=)` 로 두 창을 다 보되 `marks` 를 한 번만 훑으므로
두 창에 다 들어와도 한 번만 세어진다.

## 되풀이된 진짜 이유

세 회차가 전부 **"판정에 쓰는 축을 검사도 쓰고 있었다"** 는 한 가지 실패다.
축이 여럿이면 축마다 따로 물어야 한다.

| 회차 | 검사가 독립이었던 축 | 공유하던 축 | 결과 |
| --- | --- | --- | --- |
| 16 | — | 크기 · 자리 | 거짓 0 |
| 18 | 크기 | **자리** | 거짓 0 |
| 19 | 크기 · 자리 | — | 112건이 보였다 |

그리고 **한 장의 실측으로 규칙을 정한 것**이 ①(11회차 p6 → 위)과 ④(11회차
p6 → 액추에이터)에서 똑같이 반복됐다.  같은 회차, 같은 도면, 같은 함정이다.
