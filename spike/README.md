## 1. 타이틀블록 파싱

```bash
pip install pymupdf numpy
python spike/extract_titleblocks.py --pdf data/pid_total.pdf \
                                    --out out/titleblocks.csv \
                                    --rev-sheet out/rev_cells.png
```

`--rev-sheet` 는 58개 REV 셀을 판독 결과와 함께 한 장으로 붙인 PNG를 만듭니다.
REV 는 대부분의 페이지에서 텍스트 레이어와 대조할 수 없는 유일한 필드라
육안 검증용으로 붙였습니다.

### 결과

| 필드 | 성공 | 비율 |
|---|---|---|
| `drawing_no` | 58/58 | 100% |
| `drawing_title` | 58/58 | 100% |
| `unit_code` | 58/58 | 100% |
| `rev` | 58/58 | 100% (전부 HIGH) |
| `rev_date` | 9/58 | 15.5% (아래 §설계 영향 참조) |

파싱 실패 페이지 **없음**.

### 설계 영향 — 설계안 수정이 필요한 실측 발견

**① 타이틀블록이 두 가지 변종으로 섞여 있다.**
58페이지 중 10페이지만 타이틀블록 소문자 텍스트(라벨·REV·리비전 이력)가
실제 텍스트 레이어입니다. 나머지 48페이지는 **모노라인 CAD 스트로크 폰트로
플롯되어 텍스트가 전혀 없는 벡터 폴리라인**입니다.
도면번호·제목·프로젝트명은 전 페이지 Arial 텍스트라 영향 없습니다.

`docs/design.md` §17 은 "대상 PDF가 100% 벡터이므로 OCR 미구현"이라고
적었는데, 그 결론 자체는 맞지만 근거가 한 단계 어긋납니다. 벡터라서 OCR이
불필요한 게 아니라, **벡터 도형을 문서 자체에서 부트스트랩한 글리프 템플릿과
매칭**해서 읽어야 합니다. 이 스크립트가 쓰는 방식입니다:

- 글자 템플릿 ← 리비전 이력 REV 칸 중 **1글자짜리 칸**. 이력 행은 아래에서
  위로 A, B, C… 순으로 채워지므로 행 순서가 곧 라벨입니다.
- 숫자 `1` 템플릿 ← SHEET 칸. 전 도면이 `1/1` 이고, 텍스트 변종 페이지에서
  그 값이 확인됩니다.
- 글리프는 잉크 바운딩박스로 크롭 후 고정 격자로 면적평균 → 위치·크기·선
  굵기에 무관. 문자당 템플릿을 **평균 내지 않고 리스트로 보관**해 서로 다른
  서체(스트로크 / Arial / 페이지 48의 굵은 서체)를 함께 인식합니다.

**② 리비전 이력 행 수로 Rev 를 추론하면 안 된다.**
페이지 7·9·20 은 이력 행이 A·B 두 줄인데 정작 REV 칸은 **A** 입니다.
원본 도면 자체가 불일치합니다. 행 수 기반 추론은 이 3페이지에서 틀립니다
(10개 정답 페이지 중 3개 오답 = 30%). 따라서 REV 칸은 **추론하지 않고 판독**
합니다.

**③ Rev 가 항상 한 글자가 아니다.**
페이지 48 은 Rev **`A1`** 입니다. REV 칸을 단일 글리프로 보지 않고 문자
단위로 분할해야 합니다.

**④ 페이지 48 은 다른 프로젝트 도면이다.**
EMPLOYER `PDP GEN TWO SDN BHD`, PROJECT NAME `PORT DICKSON 1400MW CCGT`
(나머지 57페이지는 `AL NOUF1 PROJECT`), Description 도 `FOR PROPOSAL`
(나머지는 `FOR INTERNAL USE`). 유입 경위 확인이 필요합니다.

**⑤ 도면번호가 중복된다.** `pid_page` 를 `drawing_no` 로 키잉하면 깨집니다.

| drawing_no | 페이지 | 제목 |
|---|---|---|
| `D00P-00GHC10-M05-0001` | 46 / 47 | DESAL. WATER SUPPLY / DEMINERALIZED WATER DISTRIBUTION (1 OF 2) |
| `D00P-00GMA10-M05-0001` | 52 / 55 | CHEMICAL WASTE WATER TRANSFER / WASTE WATER TRANSFER (SEA WATER / STORM WATER) |
| `D00P-10LBG10-M05-0001` | 12 / 15 | AUXILIARY STEAM SYSTEM GROUP 10 / GT FLASH PIPE SYSTEM UNIT 11 |

서로 다른 도면인데 번호가 같으므로 페이지 번호를 포함한 키가 필요합니다.
§11 중복 판정 로직과는 **별개 사안**입니다(같은 기기의 중복이 아니라 채번 오류).

**⑥ 2페이지가 270° 회전 저장되어 있다** (7, 48). `page.rotation_matrix` 로
동일 좌표계에 매핑하면 나머지 56페이지와 같은 규칙이 그대로 적용됩니다.
전 파이프라인이 이 변환을 거쳐야 합니다.

**⑦ `rev_date` 는 9/58 만 추출됩니다.** 날짜 역시 48페이지에서 스트로크
폰트라 글자 단위 판독이 필요한데, 숫자 0·2·5·9 와 월 약어 템플릿을
부트스트랩할 근거가 문서 안에 없습니다(SHEET 칸이 `1` 만 제공).
`rev_date` 는 필수 필드가 아니라 CSV에 공란으로 두고 실패로 잡지 않았습니다.
필요해지면 텍스트 변종 페이지에서 날짜 템플릿을 라벨링하는 작업이 별도로
필요합니다.

### 검증 방법

- 텍스트 레이어가 있는 10페이지에 대해 판독 결과와 텍스트를 대조 → **10/10 일치**.
- 나머지 48페이지는 `--rev-sheet` 산출물로 육안 확인 → **58/58 일치**.
- `unit_code` 는 `drawing_no` 에서 재유도해 교차 검증 → 불일치 0.

### 산출물

- `out/titleblocks.csv` — 58행. 필드별 값과 함께 `rev_method`(TEXT/GLYPH),
  `rev_confidence`, `rev_detail`(매칭 거리·마진), `status`, `issues` 를 같이
  기록합니다. 설계안 §4 의 "근거 없는 값은 저장하지 않는다" 원칙에 맞춘 것으로,
  그대로 `pid_page` + `item_evidence` 에 적재할 수 있습니다.
- `out/rev_cells.png` — REV 셀 58개 육안 검증 시트.

## 2. 단일 페이지 심볼 검출

```bash
pip install pymupdf numpy openpyxl
python spike/detect_symbols.py --pdf data/pid_total.pdf --page 6 \
       --compare data/CZE_Field_Instrument.xlsx \
       --json out/detect_page006.json --png out/detect_page006.png
```

대상은 **page 6 (`D00P-10LBA10-M05-0001`, HP Steam System Group 10) 한 장**입니다.
LLM·OCR 미사용, 텍스트 앵커 + 지오메트리 검증 (design.md §6.1).

### 결과 — Excel 12행과 정확히 일치

| TYPE | 검출 | Excel | 차이 |
|---|---|---|---|
| PIT | 2 | 2 | 0 |
| TIT | 10 | 10 | 0 |
| **합계** | **12** | **12** | **0** |

**재현율 12/12 = 100%** (목표 90%), **정밀도 12/12 = 100%**.

앵커 42개 전부 지오메트리 검증 통과 (`geometry-unverified: 0`).
버블은 이 도면에서 원이 아니라 **68.0 × 22.6 pt 스타디움**이고, 캡(원호) 2개가
56.6 pt 간격으로 짝을 이룹니다. 인접 버블 간격이 25.5 pt뿐이라 "근처 원호를
전부 합집합"하면 이웃끼리 뭉치므로 **캡을 정렬·간격으로 짝지어야** 합니다.

| 둘 다 (기본) | 100% | 100% | 0 |

| 규칙 | 잡아내는 심볼 | 단독으로만 잡는 것 |
|---|---|---|
| `SCT_SUPPLIER_SCOPE` | 10 | 0 |
| `VENDOR_MARK` | 20 | 6 |
| `NOT_FIELD_INSTRUMENT` (TW/FE/FT) | 10 | 6 |
| `VALVE` (MOV) | 4 | 4 |

### 설계 영향 — 요청받은 SCT 규칙에 대한 실측 정정

**① 이 도면의 SCT 스코프는 "박스"가 하나뿐이고, 나머지 둘은 박스가 아니다.**
지시받은 대로 SCT 텍스트 주변 벡터 도형을 찾은 결과 두 가지 형태가 나왔습니다.

- `SCT SUPPLIER` (1곳) — **닫힌 사슬점선 사각형** `(1183,162)-(1910,484)`.
  터빈(HP/IP/LP)을 감싸며, 지시대로 박스 내부 제외를 적용합니다.
  다만 **이 박스 안에는 TT·PT 앵커가 하나도 없어 실제 제외 기여는 0건**입니다.
- `SCT HRSG` (2곳) — **사각형이 아니라 배관 위의 스코프 브레이크**입니다.
  배관 자체가 `x=633.3` 까지 점선(= not in contract), 그 이후 실선으로 그려져
  있고, `SCT` 텍스트의 x 시작점이 정확히 633.3 으로 브레이크 지점과 일치합니다.
  그래서 "박스 내부"가 아니라 **계기의 드롭라인이 점선 구간에 닿는지**로
  판정했습니다. 이 판정이 브레이크 바로 왼쪽 5개(제외)와 바로 오른쪽 2개(포함)를
  정확히 갈라줍니다 — 단순 좌표 밴드로는 이 구분이 안 됩니다.

**② SCT 규칙만으로는 목표를 못 맞춘다. 벤더 마크 규칙이 필수다.**
지시하신 "y≈469 / y≈1006 라인의 TT·PT"는 SCT 규칙으로 정확히 10건 걸립니다.
그런데 그것만으로는 **정밀도 66.7%** 에 그칩니다. 터빈 주변 우측 계기 6건
(TT 3 + PT 3, 좌표 `(1191,768)` `(1339,768)` `(1339,811)` `(1191,896)`
`(1191,938)` `(1339,938)`)이 남기 때문입니다. 이들은 SCT 브레이크의 **오른쪽**,
즉 SCT 배관 스코프 안에 있지만 **기기 자체는 ST 공급자 납품**입니다.

근거는 이 페이지 NOTES 에 있습니다(design.md §10.1 페이지 스코프 마크 사전):

```
*    DENOTES EQUIPMENT WILL BE SUPPLIED BY HRSG.
**   DENOTES EQUIPMENT WILL BE SUPPLIED BY ST SUPPLIER.
```

마크는 텍스트가 아니라 **4×4 pt 벡터 도형**이라 `get_text` 로는 안 잡힙니다.
버블 위 마크 **개수**를 세고 그 개수를 NOTES 의 정의에 대응시켜 해석합니다.
좌측 5개 묶음은 `*`(HRSG), 우측 터빈 계기는 `**`(ST SUPPLIER)입니다.

즉 **배관 스코프(SCT 브레이크)와 기기 공급자(마크)는 별개 축**이고, Field
Instrument 리스트에서 빠지는 기준은 후자입니다. 이 도면에서는 벤더 마크 규칙이
SCT 규칙을 완전히 포함합니다(`SCT_SUPPLIER_SCOPE` 단독 검출 0건).
SCT 규칙은 지시대로 유지했고 교차 검증용으로 유효하지만, **MVP 필수 규칙은
벤더 마크 쪽**입니다.

**③ 불일치 0건.** 대조 결과 TYPE별 개수가 정확히 일치해 원인 추정이 필요한
건이 없습니다. 참고로 `Q'ty` 는 Excel 12행 모두 2인데, 이는 심볼 개수가 아니라
NOTES 1 `THIS P&ID IS FOR GROUP#10, CONFIGURATION IS IDENTICAL FOR GROUP#20`
에서 오는 승수입니다(design.md §8). 스파이크 3의 검증 대상이라 여기서는
심볼 개수만 대조했습니다.

## 2b. 전수 확장 — p6 규칙은 어디서 깨지는가

```bash
python spike/detect_all.py --pdf data/pid_total.pdf \
       --compare data/CZE_Field_Instrument.xlsx \
       --titleblocks out/titleblocks.csv \
       --json out/detect_all.json --failures out/failure_report.md
```

**새 규칙을 추가하지 않고** p6 에서 검증한 규칙을 `analysis_scope=true` 인
P&ID 52페이지(49개 도면번호)에 그대로 적용했습니다. Field Instrument 만 대상,
Q'ty 는 제외하고 행 수만 비교합니다. Excel 563행 중 `P&ID No.` 가 있는 557행이
조인 대상입니다(나머지 6행은 SPARE).

결과: **재현율 81.9% (456/557), 정밀도 73.5% (456/620)**.

### 핵심 질문의 답 — 벤더마크가 SCT 를 포함하는가

| 활성 규칙 | 검출 | 정답 | 일치 | 재현율 | 정밀도 |
|---|---|---|---|---|---|
| 둘 다 끔 | 759 | 557 | 461 | 82.8% | 60.7% |
| SCT 만 | 727 | 557 | 459 | 82.4% | 63.1% |
| 벤더마크 만 | 622 | 557 | 458 | 82.2% | **73.6%** |
| 둘 다 | 620 | 557 | 456 | 81.9% | 73.5% |

**p6 의 관찰이 전 계통에서 성립합니다.** 벤더마크를 켠 상태에서 SCT 를 추가로
켜면 검출이 622 → 620 으로 **단 2건** 줄고, 그 2건은 Excel 이 유지하는 행이라
일치 수가 458 → 456 으로 **줄어듭니다**. 즉 SCT 규칙이 단독으로 잡아내는 것은
전 도면에서 2건뿐이고 그 2건은 모두 오제외입니다
(`D00P-11LAB00-M05-0001` p20 의 `RO` 2건, 좌표 `(1118.5, 809.4)` `(1118.5, 1300.0)`).

SCT 단독으로만 올바르게 걸리는 계통은 **없습니다**. SCT 규칙은 유지하되
MVP 필수 규칙에서는 빼고, 교차검증용으로만 두는 것이 맞습니다.

### 경고했던 두 가지 — 둘 다 실제로 문제였음

**① 버블 치수는 p6 기준이 아니다.** 하드코딩했으면 절반을 잃었습니다.

| 스타디움 | 개수 | 페이지 수 |
|---|---|---|
| 68.0 × 22.6 (p6) | 558 | 29 |
| **85.1 × 28.4** | 361 | 20 |
| 50.0 × 16.6 / 54.5 × 18.2 등 | 19 | 4 |

p6 치수는 전체 1,179개 버블 중 558개만 덮습니다. 그래서 치수 상수를 버리고
**"원호 캡 2개 + 그 사이를 잇는 직선 변 2개"** 라는 순수 기하 조건으로 바꿨습니다.
이웃 버블에서 온 캡 쌍은 사이에 변이 없어 자동으로 탈락하므로 크기를 몰라도 됩니다.
p6 결과는 12/12 그대로입니다(회귀 없음).

**② 벤더마크 표기가 페이지마다 다르다.** 이게 최대 오검출 원인입니다.

| 표기 방식 | 페이지 | 규칙 적용 |
|---|---|---|
| 벡터 글리프 (p6 방식) | 19 | 가능 |
| **텍스트 `(*)` / `(**)`** | 7 (26,27,28,32,46,49,51) | **불가 — 규칙이 못 봄** |
| 마크 없음 | 26 | 해당 없음 |

p6 은 NOTES 범례의 마크를 **벡터 글리프**로 그립니다. 그런데 7개 페이지는
`4. (*) SYMBOL INDICATES COMPONENTS FURNISHED BY SEAWATER INTAKE FACILITY SUPPLIER`
처럼 **문자 `(*)`** 로 씁니다. 마크 사전 파서가 글리프만 찾으므로 이 페이지들은
사전이 비고, 도면 안의 `(**)` 텍스트 마크도 못 봐서 **제외가 하나도 일어나지
않습니다**.

부작용으로 `VENDOR_MARK_UNDEFINED` 가 0건입니다. 마크를 아예 못 보니 "정의 없는
마크" 상태에 도달하지 못합니다. 분류 체계는 있으나 현재 계측기로는 트리거되지
않는다는 점을 명시해 둡니다.

### 실패 유형별 집계

| 유형 | 케이스 | 행 수 |
|---|---|---|
| `OVER_DETECT` | 38 | **164** |
| `TYPE_MAPPING_MISS` | 19 | 58 |
| `NO_ANCHOR` | 15 | 32 |
| `AMBIGUOUS_GEOMETRY` | 5 | 6 |
| `SCOPE_CONFLICT` | 3 | 5 |
| `VENDOR_MARK_UNDEFINED` | 0 | 0 |

`TYPE_MAPPING_MISS` 58행의 내역이 특히 중요합니다.

- **FE 18행** — p6 에서 "FE 는 Field Instrument 비대상"으로 확정했는데, 전체
  Excel 에는 FE 가 18행 있습니다. **p6 에서 검증한 규칙이 틀렸습니다.**
  p6 의 FE 2건이 마침 대상 외였을 뿐입니다.
- **LSH / LSHH / LSL → LS 16행** — 앵커 사전에 없는 태그.
- ZS/ZSC 8행, LG 11행, DPIT 등 — 앵커 사전 미포함.

### 가장 많이 틀린 계통: `PAB` (Seawater Intake System)

오차 총량 기준 최악입니다 — 4개 도면에서 **검출 50 vs Excel 14, 정밀도 24.0%**.

**원인 가설 (근거 확보됨):** 이 계통의 벤더 스코프가 **p6 규칙이 볼 수 없는
형태로만 표현**되어 있습니다.

1. p26 은 검출 29건 중 **벡터 마크를 가진 것이 0건**입니다. 도면 안의 마크는
   전부 텍스트 `(**)` (7개)이고, 범례도 `4. (*) SYMBOL INDICATES ...` 형태의
   문장입니다. → 마크 사전 비어 있음 → 제외 0건.
2. NOTES 1 이 `AUTOMATIC AIR RELEASE VALVE AND PRESSURE GAUGE WILL BE SUPPLIED
   BY CWP SUPPLIER` 라고 **산문으로만** 선언합니다. p26 의 `PI` 7건이 여기
   해당하는데, 심볼에는 아무 마크도 붙어 있지 않습니다.
3. Excel 의 `00PAB10-M05-0001` 5행은 전부 `PIT` — "CIRCULATING WATER PUMP
   DISCHARGE PRESSURE" 뿐입니다. 즉 취수 설비의 `LIT` 10건·`PI` 7건은 통째로
   SCT 스코프 밖입니다.

→ **마크 기반 제외만으로는 이 계통을 못 잡습니다.** 다음 단계에서 필요한 것은
(a) 텍스트형 마크 `(*)`/`(**)` 파싱, (b) NOTES 산문의 공급자 선언을 심볼 종류
(PRESSURE GAUGE → PI)에 연결하는 규칙입니다. (b) 는 §10.1 이 예고한 "페이지
스코프 마크 사전"의 확장이며, 자연어가 개입하므로 설계안 §2 기준으로 LLM 을
쓸 수 있는 몇 안 되는 지점입니다.

### 지표를 왜곡하는 조인 문제 (별도 계상 필요)

- Excel 에만 있고 PDF 에 없는 도면 **5건 / 21행** — 검출 불가인데 재현율 손실로 계상.
- PDF 에만 있고 Excel 에 없는 도면 **14건 / 검출 31행** — 전부 정밀도 손실로 계상.
- 도면번호 공유 **3건** — 1:N 조인이라 서로 다른 도면의 검출이 합산됩니다.
  `00GHC10-M05-0001` 은 p46(Desal.)+p47(Demin.) 이 합쳐져 검출 54 vs Excel 16 인데,
  Excel 의 SYSTEM 값이 `Demineralized Water Distribution System` 이므로 그 16행은
  **p47 것**이고 p46 의 20건은 순수 조인 오염입니다. `10LBG10-M05-0001` 도 동일
  (Excel SYSTEM = `Aux. Steam System` = p12, p15 는 오염).

이 세 요인을 걷어내면 실제 규칙 성능은 위 수치보다 높습니다. 다음 단계 측정
전에 조인 기준을 페이지 단위로 확정할 필요가 있습니다.
