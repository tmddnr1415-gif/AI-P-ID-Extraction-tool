# 계장 설계 도구 사용 설명서

계장 설계 부서가 함께 쓰는 도구 모음입니다.  서버 PC 한 대에서 프로그램을 켜 두면, 부서원은 각자 PC 의 브라우저(Edge)로
`http://<서버 PC 주소>:8000/` 에 들어와 씁니다.  부서 대시보드 안에서 열어도 같은 화면입니다.

이 설명서는 화면 오른쪽 위 **?** 단추 → **설명서** 에서도 열 수 있습니다.  처음이면 [설치와 처음 켜기](#설치와-처음-켜기) 부터 읽으세요.

| 화면 | 주소 | 하는 일 |
| --- | --- | --- |
| P&ID 리스트 추출 | `/` | P&ID 도면(PDF)에서 계기·밸브 리스트를 뽑고 검토 |
| LOGIC 검토 | `/logic` | Logic 도면 한 벌을 읽어 블록·신호·From-To 검토 |
| LOGIC 작도 | `/logic/draw` | 표준 블록으로 Logic 을 그리고 돌려 보기 |
| 신호 처리 | `/logic/signal` | 필터·지연·비교 블록의 시간 변화 그려 보기 |
| 시운전 | `/logic/commission` | 시운전 단계별로 살아야 할 신호·블록 확인 |
| 블록 시험 | `/logic/test` | 블록 묶음에 입력을 넣어 출력 시험 |
| 판넬 공간확보 | `/space` | 판넬 치수·수량으로 전기실·계기실 면적 계산 · 배치 · 3D |
| DCS 그래픽 | `/dcs` | P&ID · Logic 자료로 DCS 운전 화면 초안 만들기 |
| 계장 도서검토 | `/books/` | 사내 계장 도서 찾기 · 필요한 부분 번역 |

모든 화면 위쪽 띠에서 다른 화면으로 옮겨 가고, **이름 단추**로 내 이름을 정합니다.  고친 내용과 기록에는 그 이름이 남습니다.

## 화면별 사용법

화면마다 "처음 할 일 · 결과를 보는 곳 · 자주 막히는 것" 만 적었습니다.  자세한 안내는 각 화면의 **?** 단추에 있습니다.

### P&ID 리스트 추출

처음 할 일
1. 왼쪽 메뉴에서 프로젝트를 고르거나 새로 만듭니다.
2. P&ID PDF 를 화면에 끌어다 놓습니다.  분석은 장수에 따라 몇 분 걸립니다 (58장에 약 3~4분).  분석 중에도 다른 화면은 그대로 씁니다.
3. 결과 표에서 값을 확인하고 고칩니다.  고친 값은 누가 언제 바꿨는지와 함께 남습니다.

결과를 보는 곳
- 가운데 **결과 표**: 한 줄이 계기·밸브 하나입니다.  줄을 누르면 오른쪽에 **근거**(도면의 어느 글자·기호에서 읽었는지)와 도면 그림이 보입니다.
- **Excel 출력**: 발주처 양식 Excel 리스트를 받습니다.  리비전 사이에 달라진 것은 **변경 내역 Excel** 로 받습니다.

자주 막히는 것
- 값이 비어 있는 칸: 도면에 없는 값은 일부러 비워 둡니다 (지어내지 않습니다).  근거 칸에 이유가 적혀 있습니다.
- 스캔한 그림 PDF 는 읽지 못합니다 — CAD 에서 내보낸 PDF 여야 합니다.
- 분석이 '실패' 로 남으면 같은 파일을 한 번 더 올리고, 그래도 안 되면 **의견 보내기** 로 알려 주세요.

화면 캡처(결과 표 · 근거 칸)는 준비 중입니다.

### LOGIC 검토

처음 할 일
1. 프로젝트를 고르고 Logic PDF 묶음을 넣습니다.
2. 왼쪽 장 목록에서 장을 고르면 가운데에 도면, 오른쪽에 읽어 낸 블록·신호가 보입니다.
3. 머리의 메뉴로 **LOGIC 작도 · 신호 처리 · 시운전 · 블록 시험** 화면에 갑니다.

결과를 보는 곳: 오른쪽 칸(블록·From-To) · 내려받기(PDF / Excel).

자주 막히는 것: 장 목록이 비어 있으면 위에서 프로젝트를 먼저 골랐는지 확인하세요.

### LOGIC 작도

1. 왼쪽 블록 모음에서 블록을 끌어다 놓습니다.
2. 블록의 입·출력을 선으로 잇고 이름을 적습니다.
3. 저장하면 LOGIC 검토 화면에서도 같은 도면을 봅니다.

자주 막히는 것: 저장할 때 "다른 사람이 먼저 저장했습니다" 가 뜨면, 내가 연 뒤 다른 사람이 같은 도면을 저장한 것입니다.
**새로 고침**(그 사람의 판을 받기) 또는 **내 판으로 덮기** 중 하나를 고르세요.

### 신호 처리

블록 종류(필터 · 지연 · 비교)와 매개변수를 고르고, 입력 파형을 정해 돌리면 출력이 그래프로 보입니다.

### 시운전

LOGIC 검토에서 분석한 묶음을 고른 뒤 단계를 고르면 그 단계에 관련된 신호·블록이 표시됩니다.  확인한 내용은 기록으로 남습니다.

### 블록 시험

LOGIC 검토에서 분석한 묶음을 고르고, 시험할 그룹과 입력 값을 정해 돌립니다.  결과는 Excel 로 받습니다.

### 판넬 공간확보

처음 할 일
1. 프로젝트를 고르거나 새로 만듭니다.
2. 판넬 종류·치수·수량을 적습니다.
3. 배치를 끌어 맞추고 **3D 보기**(`/space?view=3d`)로 확인합니다.

결과는 저장되며 Excel 로 받을 수 있습니다.

자주 막히는 것: 실수로 지운 프로젝트·룸은 버려지지 않고 휴지통 폴더(`app\_data\space\_trash\`)로 옮겨집니다 — 관리자가 그 폴더를 원래 자리로 옮기면 돌아옵니다.

### DCS 그래픽

1. 출처(분석한 P&ID 또는 예시)를 고릅니다.
2. 전체 화면에서 심볼을 옮기고 태그를 잇습니다.
3. 그림(PNG / SVG)으로 내려받습니다.

### 계장 도서검토

1. 검색창에 낱말을 적으면 문서와 쪽을 찾아 줍니다.
2. 문서를 열어 필요한 부분을 고르면 번역할 수 있습니다.
3. 문서 폴더와 번역 설정(API 키)은 운영자(서버 PC)만 바꿉니다.  키는 화면에 다시 보이지 않습니다.

## 설치와 처음 켜기

서버 PC 한 대에만 설치합니다.  부서원 PC 에는 아무것도 깔지 않습니다.

1. **Python 3.11** 을 설치합니다 (3.12 · 3.13 아님).  설치할 때 "Add python.exe to PATH" 에 표시합니다.
   인터넷이 막힌 PC 는 `docs\offline_setup_windows.md` 의 순서대로 설치 파일과 `wheels\` 폴더를 옮겨 옵니다.
2. 프로그램 폴더(예: `C:\Claude\PID`)에서 **`setup.bat`** 을 더블클릭합니다.
   전용 파이썬 폴더(`.venv`)를 만들고 필요한 꾸러미를 설치한 뒤 점검까지 합니다.  마지막에 "Setup done" 이 보이면 끝입니다.
3. **`run_lan_service.bat`** 을 더블클릭해 서버를 켭니다.  작게 떠 있는 검은 창이 서버입니다 — 닫으면 서버가 꺼집니다.
4. **`check_pid_server.bat`** 으로 확인합니다.  "정상" 과 접속 주소가 보이면 됩니다.
5. 다른 PC 에서 들어오려면 방화벽을 한 번 열어야 합니다: **`open_firewall_8000.bat`** 을 마우스 오른쪽 → **관리자 권한으로 실행**.

이 PC 에서만 잠깐 쓸 때는 `start.bat` 을 더블클릭해도 됩니다 (다른 PC 에서는 못 들어옵니다).

## 자동 시작

**`install_autostart_lan.bat`** 을 한 번 더블클릭하면, 이 PC 에 **이 사용자로 로그온할 때마다** 서버가 저절로 켜집니다.

- PC 를 켜기만 하고 로그온하지 않으면 서버가 뜨지 않습니다 (부팅 때가 아니라 로그온 때 켜집니다).
  서버 PC 는 **자동 로그온 + 화면 잠금**으로 두거나, 적어도 **절전 모드를 끄는 것**을 권합니다.
- 등록됐는지 보기: 명령 창에서 `schtasks /Query /TN PID_Extract_LAN`
- 그만두기: `uninstall_autostart_lan.bat`

## 끄기 · 다시 켜기 · 상태 보기

| 하고 싶은 것 | 방법 |
| --- | --- |
| 끄기 | 서버 창(검은 창)을 닫습니다.  창을 찾기 어려우면 **개발 폴더(`C:\Claude\PID_dev`)의** `stop_pid_server.bat` — 포트 8000 에서 도는 서버(운영 서버)를 끕니다 (다른 포트면 `stop_pid_server.bat 9000`).  서비스 창이 열려 있으면 그 창도 닫아야 합니다 (그대로 두면 10초 뒤 다시 켭니다) |
| 다시 켜기 | `restart_pid_server.bat` — 분석 중이면 먼저 물어봅니다.  서비스 창이 10초 뒤 새로 띄웁니다 |
| 켜기 | `run_lan_service.bat` |
| 상태 보기 | `check_pid_server.bat` · 또는 브라우저로 `http://<서버 주소>:8000/version` (제품 이름이 보이면 켜져 있음) |
| 지금 분석 중인 것 | `http://<서버 주소>:8000/running` |

서버 창 안을 마우스로 누르지 마세요.  창이 '선택' 상태가 되면 서버가 잠시 멈춘 것처럼 보일 수 있습니다 (그럴 때는 Esc).

## 자료가 있는 곳

모든 화면의 자료는 프로그램 폴더 안 **`app\_data\`** 에 있습니다.

| 폴더 · 파일 | 담긴 것 |
| --- | --- |
| `app.db` | P&ID 분석 결과 · 고친 값 · 기록 (가장 중요) |
| `uploads\` | 올린 P&ID 도면 원본 |
| `projects\` | 프로젝트 · 리비전 정보 |
| `logic\` | LOGIC 검토 · 작도 자료 (도면 원본 포함) |
| `space\` | 판넬 공간확보 자료 (`_trash\` 는 지운 것) |
| `hmi\` · `dcs\` | DCS 그래픽 자료 |
| `books\` | 도서검토 설정 · 색인 |
| `outputs\` · `page_cache\` · `work\` | 다시 만들어지는 임시 자료 (지워도 됨) |
| `backups\` | 서버가 매일 떠 두는 `app.db` 사본 (7일치) · 백업 도구의 기본 자리 |

그 밖에 `voc\`(의견 보내기로 받은 글) 와 `logs\`(로그) 가 프로그램 폴더 바로 아래에 있습니다.

**주의: `app\_data` 폴더를 지우기 전에 꼭 백업하세요** ([백업과 복구](#백업과-복구)).  지우면 모든 화면의 자료가 사라집니다.

**자료 폴더(`app\_data`)는 옮기지 마세요** — 옮기면 이전 분석이 올린 도면 원본을 찾지 못합니다.  다른 드라이브에는 백업을 두세요 ([백업과 복구](#백업과-복구)).

## 로그

| 파일 | 내용 |
| --- | --- |
| `logs\server.log` | 서버가 남기는 글.  20MB 를 넘으면 `server.log.1` ~ `.3` 으로 밀려나 전체가 80MB 를 넘지 않습니다 |
| `logs\lan_service.log` | 서비스 창이 서버를 켜고 다시 켠 시각 |
| `logs\lan_check.txt` | 마지막 `check_pid_server.bat` 결과 |

`server.log.1` ~ `.3` 과 `server_<시각>.log` 는 지워도 됩니다.  문제를 알릴 때는 `logs\server.log` 끝부분과 `logs\lan_check.txt` 를 보내 주세요.
접속 기록(누가 어떤 주소를 열었는지)은 남기지 않습니다.

## 업데이트

업데이트는 zip 꾸러미 하나로 옵니다.  순서는 꾸러미 안 `1_먼저읽기.txt` 에도 적혀 있습니다.

1. **zip 을 전부 풉니다.**  zip 안에서 바로 실행하면 "압축을 먼저 푸세요" 로 멈춥니다.
2. `apply_to_PID_dev.bat` — 개발 폴더(`C:\Claude\PID_dev`)에 먼저 얹습니다.  다른 폴더면 `apply_to_PID_dev.bat D:\폴더` 처럼 적습니다.
3. `apply_to_PID_ops.bat` — 운영 폴더(`C:\Claude\PID`)에 얹습니다.  "다시 띄울까요?" 에 Enter.
4. 화면을 새로 고쳐 오른쪽 위(또는 아래)의 **업데이트 번호**(예: `버전 1.0.0 · 업데이트 132 · 2026-11-05`)가 바뀌었는지 봅니다.
5. 문제가 있으면 `rollback_PID_ops.bat` — 이 꾸러미가 바꾼 파일만 원래대로 돌립니다.  그 뒤에 손으로 고친 파일은 건드리지 않고 목록으로 알려 줍니다.

- 얹는 도중 실패하면(파일이 잠김 · 디스크 부족) **자동으로 원래대로 되돌리고** 멈춥니다.  원인을 없앤 뒤 같은 bat 를 다시 실행하세요.
- 운영 폴더에는 `app\` 와 `config\` 만 바뀝니다.  `backup_pid_data.bat` · `stop_pid_server.bat` 은 **개발 폴더(PID_dev)에서 실행**합니다 — 운영 폴더로 복사하지 마세요 (운영 폴더의 옛 도구로는 동작하지 않습니다).  이 두 bat 는 PID_dev 에서 실행해도 운영 서버 · 운영 자료를 다룹니다.

## 백업과 복구

서버는 매일 한 번 `app.db` 만 떠 둡니다.  올린 도면 · LOGIC · 판넬 · DCS · 도서검토 설정까지 모두 지키려면 **`backup_pid_data.bat`** 을 씁니다.

`backup_pid_data.bat` 은 **개발 폴더(`C:\Claude\PID_dev`)에서 실행**합니다.  어느 자료를 다루는지는 이렇게 정합니다:
운영 자료 `C:\Claude\PID\app\_data` 가 있으면 그것, 없으면 bat 이 든 폴더의 `app\_data`.  **실행하면 맨 처음에 자료 폴더를 보여 주니 꼭 확인하세요.**
다른 자료 폴더는 `--data` 로 적습니다 (예: `backup_pid_data.bat D:\pid_backup --data C:\Claude\PID_dev\app\_data`).

백업하기
1. `backup_pid_data.bat D:\pid_backup` 처럼 **다른 드라이브**를 적어 실행합니다 (같은 디스크면 디스크 고장 때 함께 잃습니다).
   목적지를 늘 같게 하려면 환경 변수 `PID_BACKUP_DIR` 에 적어 두고 그냥 더블클릭합니다.  둘 다 없으면 자료 폴더 안 `backups\` 에 만듭니다.
2. `D:\pid_backup\pid_backup_<날짜_시각>_<식별>\` 폴더가 생깁니다 (식별 = 자료 폴더를 가리키는 짧은 글자 — 여러 폴더가 같은 목적지를 써도 서로 섞이거나 지워지지 않습니다).
   안의 **`manifest.json`** 에 `"integrity": "ok"` 가 있으면 정상 백업입니다.
3. 같은 자료 폴더의 판이 7판을 넘으면 오래된 것부터 지웁니다 (`--keep 14` 로 바꿈).  `backup_pid_data.bat --list D:\pid_backup` 으로 목록을 봅니다.
4. 서버가 켜져 있어도 백업할 수 있습니다.  주 1회 이상, 업데이트 전에는 꼭 한 번 권합니다.

백업에 넣지 않는 것: 다시 만들어지는 임시 자료(`outputs\` · `page_cache\` · LOGIC 장 그림) 와 **도서검토 API 키** (보안 때문 — 복구할 때 지금 쓰는 키를 옮겨 줍니다).

복구하기
1. 서버를 끕니다 — 서버 창과 서비스 창을 닫거나 `stop_pid_server.bat`.  포트 8000 의 서버가 켜져 있으면 복구를 거부합니다 (다른 포트로 켠 서버는 `--port 9000` 처럼 알려 줍니다).
2. `backup_pid_data.bat --restore D:\pid_backup\pid_backup_20261105_0930_1a2b3c` — 백업과 **같은 규칙의 자료 폴더**(맨 처음에 보여 줌)에 복구합니다.  먼저 `--dry-run` 을 붙이면 무엇이 바뀌는지만 보여 줍니다.
3. 지금 자료 폴더는 지우지 않고 **폴더째** `app\_data_before_restore_<시각>\` 으로 이름을 바꿔 둡니다.  서버를 켜고 화면이 정상이면 그 폴더는 지워도 됩니다.
4. 자료 폴더의 파일을 다른 프로그램이 쓰고 있거나(탐색기 · Excel · 다른 포트의 서버) 디스크가 모자라 도중에 실패하면, 원래대로 되돌리고 멈춥니다 — 그 프로그램을 닫고 다시 실행하세요.

무엇을 잃으면 무엇을 다시 해야 하나

| 잃은 것 | 다시 해야 할 일 |
| --- | --- |
| `app.db` | 서버의 매일 사본(`app\_data\backups\`)이나 전체 백업으로 복구 — 없으면 모든 P&ID 분석 · 고친 값을 처음부터 |
| `uploads\` | 도면 PDF 를 다시 올리고 분석 |
| `logic\` | Logic PDF 를 다시 넣고 검토 · 작도한 것은 다시 그림 |
| `space\` · `hmi\` · `dcs\` | 그 화면에서 만든 것을 다시 입력 |
| `outputs\` · `page_cache\` | 없음 — 저절로 다시 만들어짐 |

## 자주 생기는 문제

| 증상 | 할 일 |
| --- | --- |
| "Python 3.11 is not installed" | Python 3.11 을 설치하고 `setup.bat` 을 다시 실행 |
| "Missing packages" | `setup.bat` 을 다시 실행 |
| "port 8000 is held by another program" | 이미 다른 서버가 켜져 있습니다.  `check_pid_server.bat` 으로 누가 잡고 있는지 보고, 옛 서버 창을 닫습니다 |
| "The server fails to start" (다섯 번 연달아 실패) | `check_pid_server.bat` 을 실행하고 `logs\server.log` 를 보내 주세요 |
| 다른 PC 에서만 안 열림 | `open_firewall_8000.bat` 을 관리자 권한으로 실행했는지 · 서버 PC 가 로그온돼 있는지 · 절전 모드가 아닌지 |
| 아침에 서버가 안 떠 있음 | 자동 시작은 로그온 때만 켜집니다 — 자동 로그온 설정 또는 로그온 후 확인 |
| 디스크 부족 | `outputs\` · `page_cache\` · 오래된 `logs\server.log.*` 를 지웁니다.  `backups\` 는 지우기 전에 다른 곳으로 옮기세요 |
| 업데이트 뒤 화면이 이상함 | 브라우저에서 Ctrl+F5 · 그래도 이상하면 `rollback_PID_ops.bat` |

## 용어

| 낱말 | 뜻 |
| --- | --- |
| 프로젝트 | 도면과 검토 결과를 묶는 가장 큰 단위.  공사(현장) 하나가 보통 프로젝트 하나 |
| 리비전 | 같은 도면의 개정판.  새 리비전을 넣으면 이전 판과 달라진 것을 비교 |
| 묶음 | 한 번에 분석한 Logic PDF 한 벌 |
| 분석 번호 | 분석 한 번마다 붙는 짧은 번호.  결과를 다시 열거나 다른 사람에게 알릴 때 씀 |
| 근거 | 결과 값이 도면의 어느 글자·기호에서 왔는지 보여 주는 칸 |
| SCOPE | 공급 범위 — 우리 공급(SCT)인지 업체 공급(VENDOR)인지 |
| Typical | 도면이 "여기와 같다" 고 가리키는 표준 상세 |
| From-To | 신호가 어디서 나와 어디로 가는지 적은 표 |
| 업데이트 번호 | 화면 오른쪽 위(또는 아래)의 `업데이트 132` 같은 번호.  지금 얹힌 업데이트를 뜻함 — 업데이트할 때마다 커집니다 |
| 절전모드 | 서버가 꺼져 있어도 이 PC 에 보관된 화면과 자료로 계속 보고 고치는 상태.  서버가 켜지면 고친 것을 되보냄 |
