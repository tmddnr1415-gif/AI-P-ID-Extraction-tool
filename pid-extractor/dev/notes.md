### 발견 1 — "300 DPI" 는 달성할 수도 없고 기준도 아니다

CLAUDE.md §4 는 `300DPI 렌더 → 3×3 타일` 이라고 적었으나 둘 다 성립하지 않는다.

- A1 가로(841×594mm)를 300DPI 로 통째로 그리면 9933×7016px = 약 280MB 다.
  브라우저 캔버스가 못 버틴다.
- 더 중요한 것은, **모델이 이미지를 장변 1568px 로 줄여서 본다**는 점이다.
  타일 하나가 시트의 12.2인치를 덮으므로 1568/12.2 ≈ **128 DPI** 가 모델이 보는 실효
  해상도다. 렌더를 300DPI 로 하든 1000DPI 로 하든 이 값은 그대로다.

따라서 의미 있는 조절 손잡이는 DPI 가 아니라 **분할 수**다.

| 분할 | 모델이 보는 해상도 | 도면당 호출 |
|---|---|---|
| 3×3 | 약 128 DPI | 10 |
| 4×4 | 약 170 DPI | 17 |
| 5×4 | 약 213 DPI | 21 |

**조치:** 전체 시트를 그린 뒤 자르지 않고 타일 영역을 직접 렌더한다(메모리 안전).
화면에 `모델이 보는 해상도` 를 실측해 띄워서, 분할을 올릴지 사람이 판단하게 했다.
3×3 · 128 DPI 에서 위 목록이 다 읽히므로 **기본값은 3×3 을 유지**한다.

### 발견 2 — `*` 표기는 텍스트가 아니라 그림이다

이전 접근(텍스트 레이어 파싱)에서는 `*` 를 아예 못 봤다. PDF 텍스트 조각으로
존재하지 않고 벡터 도형으로 그려져 있다. 벡터에서 기하학적으로 찾아보려 했으나
도면 한 장에 작은 도형이 9000개 가까이 있어 오검출이 심했다.

**Vision 으로는 선명하게 보인다.** 이것이 이 도구가 Claude Vision 을 쓰는 핵심
이유다. 요구사항 2·4(공급 역무 분리)는 Vision 경로에서만 성립한다.

### 발견 3 — 레퍼런스 파일이 CLAUDE.md 기술과 다르다

| CLAUDE.md | 실제 파일 |
|---|---|
| `PID_Total.pdf` 41장 | **58장** |
| `example_instrument_list.xlsx` 572행 | **563행** |

받은 파일 기준으로 진행한다. §10 Phase 2 의 완료 기준(HP Steam 8~19행, PIT 2 + TIT 10,
총 12행)은 실제 정답 파일에서 **일치를 확인했다** — 6쪽 `D00P-10LBA10-M05-0001` 의
정답은 PIT 2행 + TIT 10행 = 12행, Q'ty 는 전 행 2다.

### 발견 4 — 텍스트 레이어는 버리지 않는다

Vision 이 판독의 주체지만, 텍스트 레이어에서 결정적으로 나오는 것이 있다.

- 도면번호 · 도면 제목 (타이틀블록)
- NOTES 전문 — `CONFIGURATION IS IDENTICAL FOR GROUP#20` 에서 Q'ty 가 나온다
- 계기 문자 후보 개수 — 판독 대상 도면을 고르는 데 쓴다 (58쪽 중 계기 있는 도면 45쪽)

NOTES 는 **우상단(x ≈ 0.83)** 에 있다. 좌표를 고정하지 않고 `GENERAL NOTES` / `NOTES :`
글자를 찾아 그 아래·오른쪽을 딸려 오도록 했다. 이 블록을 놓치면 Q'ty 와 공급 역무
각주를 통째로 못 본다.

### 발견 5 — §4 의 중복 제거 규칙이 틀렸다 (수정함)

`±2% 이내 + 동일 TYPE 이면 동일 계기` 를 그대로 구현했더니 **드레인 온도계 8개가
4개로 줄었다.** 이중화 계기는 같은 배관에 세로로 나란히 붙고 실측 간격이 페이지의
**1.7%** 밖에 안 된다. ±2% 로 훑으면 서로 다른 두 계기를 하나로 합친다.

세 가지를 바꿔 12/12 가 됐다.

1. **같은 타일 안에서는 합치지 않는다.** 한 응답에 따로 적혔으면 따로다.
2. 반경 안에서 아무거나 잡지 않고 **가장 가까운 것**만 짝으로 본다.
3. 반경을 **2% → 1%**. 같은 지점을 두 타일에서 본 좌표 오차보다는 크고, 세로로
   붙은 서로 다른 계기의 실측 간격(1.7%)보다는 작아야 한다.

중간 경과: 원래 규칙 8행 → 1·2 적용 10행 → 3까지 적용 12행.

### 발견 6 — 타일당 계기 8개 상한을 넘는다

`max_tokens: 1000` 은 계기 8개 분량인데, 3×3 에서 실제로는 타일 하나에 **10~13개**가
들어온다 (r0c0 10개, r1c0 13개, r1c1 10개). 공급 역무 계기까지 세기 때문이다.

지금은 스텁이라 안 잘렸지만 **실호출에서는 응답이 잘린다.** 대응이 필요하다.
`stop_reason: max_tokens` 를 잡아 예외로 올리도록은 해 뒀다(실패 타일 목록에 남는다).
분할을 4×4 로 올리면 타일당 5~7개로 떨어진다.

### 발견 7 — position 에 `DRAIN` 이 필요하다

§7.4 의 위치 허용값에 `BODY DRAIN` 은 있는데 그냥 `DRAIN` 이 없다. 정답은
`UNIT #11 HP STEAM DRAIN TEMPERATURE` 다. 허용값에 `DRAIN` 을 추가했다.

### 발견 8 — SYSTEM 은 도면 제목을 그대로 쓰면 안 된다

도면 제목은 전부 대문자(`P&ID FOR HP STEAM SYSTEM GROUP 10`)인데 정답의 SYSTEM 은
`HP Steam System` 이다. 머리글자만 대문자로 바꾸되 계통 약어(HP IP LP CCW HRSG …)는
대문자로 남기도록 했다.

### 발견 9 — 행 순서는 정답과 다르다 (그대로 둠)

정답은 UNIT #11 → #12 → #10 순인데 이 도구는 도면 위치순(§4)이라 #12(위) → #11(아래)
순으로 나온다. 내용은 같고 순서만 다르다. Excel 대조 시 다중집합으로 봐야 한다.
§4 가 "타일 순서가 곧 출력 정렬 순서"라고 못박고 있어 규칙을 바꾸지 않았다.

## 2026-08-16 · 기본 분할 3×3 → 4×4

발견 6(타일당 계기 8개 상한 초과)에 대한 조치. `max_tokens: 1000` 은 계기 8개
분량인데 3×3 에서는 타일 하나에 최대 13개가 들어와 실호출에서 응답이 잘린다.

| 분할 | 타일 | 내용 있는 타일 | 타일당 최대 | 8개 초과 타일 | 도면당 호출 | 모델이 보는 해상도 |
|---|---|---|---|---|---|---|
| 3×3 | 9 | 5 | **13** | 3 | 10 | 128 DPI |
| **4×4** | 16 | 7 | **8** | **0** | 17 | 170 DPI |

4×4 에서 상한을 넘는 타일이 사라진다. 해상도도 128 → 170 DPI 로 올라가 덤이다.
비용은 도면당 10회 → 17회로 1.7배.

### 회귀 테스트 — 세 격자 모두 12/12

픽스처를 **페이지 좌표로 한 번만** 적고 타일 배분은 계산하도록 다시 짰다
(`dev/fixture_p6.mjs`). 격자를 바꿀 때마다 손으로 좌표를 옮기면 그 자체가 오류원이
된다. 덕분에 같은 정답 데이터로 여러 격자를 한 번에 검증할 수 있다.

```

4x4  판독 12행 · 일치 12/12
5x4  판독 12행 · 일치 12/12
```

중복 제거가 격자에 무관하게 동작한다는 뜻이다. 발견 5 의 수정(같은 타일 안에서는
합치지 않기 · 최근접만 · 반경 1%)이 특정 격자에 맞춘 미봉책이 아니었음을 보인다.

### 발견 10 — ExcelJS 로는 이 양식을 못 연다 (§5 지정 라이브러리 교체)

§5 는 ExcelJS 를 쓰라고 지정했지만 이 양식을 넣으면 파싱에서 죽는다.

```
20:13: unexpected close tag
```

`xl/drawings/vmlDrawing1.vml` 20행이다. 양식에 **셀 메모용 VML 도형**이 들어 있는데
VML 은 엄밀한 XML 이 아니라(`<font ...>` 를 닫는 방식이 HTML 계열) ExcelJS 의 SAX
파서가 못 넘긴다. 라이브러리 문제라 옵션으로 우회되지 않는다.

**조치 — 파일을 해석하지 않는다.** `fflate` 로 zip 을 열어 `xl/worksheets/sheet1.xml`
하나만 다시 쓰고 나머지 부품(스타일·병합·열 너비·도형·외부링크·다른 시트 5개)은
**바이트 그대로** 되넣는다. 서식이 '유지'되는 게 아니라 애초에 건드리지 않는다.
ExcelJS 로 새로 그리는 것보다 충실도가 높다 — §5 가 ExcelJS 를 지정한 이유가
'폰트·서식 지정' 이었으므로 취지에는 더 맞는다.

곁가지로 필요한 처리 두 가지.

- `<c r="E8" s="207"/>` 같은 **자기닫힘 셀**을 정규식이 삼키지 않도록 두 단계로
  끊어 읽는 스캐너를 쓴다. 한 번에 훑으면 다음 셀 내용까지 먹는다.
- `xl/calcChain.xml` 은 지운다. 행 수가 바뀌면 캐시가 어긋나 엑셀이 복구를 묻는다.
  지우면 엑셀이 알아서 다시 만든다.

값은 `inlineStr` 로 넣어 `sharedStrings.xml` 을 손대지 않는다.

### 발견 19 — 보여 드린 것이 미리보기였고, 그게 제품처럼 보였다

`index.html` 에는 기록 결과가 없다. 기록은 `dev/build_artifact.py` 가 **미리보기 배포본**

### 발견 20 — fflate 를 아예 뺐다 (발견 17 후속)

"그대로 아티팩트로" 시키는 방식은 Claude 가 파일을 **다시 써야** 하므로 크기가 곧
성공률이다. 브라우저에 이미 있는 `CompressionStream`/`DecompressionStream`
(`deflate-raw`) 과 200 줄 남짓한 zip 읽기·쓰기로 대체했다. 88 KB → **60 KB**.

부수 효과가 더 낫다 — **손대지 않는 부품은 풀지도 않는다.** 압축된 바이트를 그대로
옮기므로 서식·도형·다른 시트가 달라질 여지가 원천적으로 없다. 확인: 원본 43개 부품 중

빠진 하나는 일부러 뺀 `xl/calcChain.xml`.

### 발견 21 — 모바일 아티팩트에서 파일 고르기가 안 열렸다

드롭존을 누르면 JS 가 숨은 `<input type="file">` 의 `click()` 을 부르는 구조였다.
샌드박스 iframe 에서는 이게 **조용히 막힌다** — 오류도 안 나고 창도 안 뜬다.
사용자 제스처가 input 에 직접 닿아야 브라우저가 파일 고르기를 연다.

**조치:** 숨긴 input 을 상자 안으로 옮기고 `position:absolute; inset:0; width:100%;
height:100%; opacity:0; cursor:pointer` 로 **상자 전체를 덮었다.** 사용자가 실제로
누르는 것이 input 자신이다. `zone.click → input.click()` 줄은 지웠다.

끌어다 놓기는 그대로 둔다. 떨어뜨린 파일도 input 위에 떨어지지만 상자의 `drop`
핸들러가 `preventDefault()` 를 부르므로 input 의 기본 동작이 취소되고 **한 번만**
처리된다(확인: 처리 1회).

곁들여 고친 것 둘:

- 안드로이드 파일 고르기는 확장자가 아니라 MIME 으로 거른다. `accept=".xlsx"` 만
  두면 목록에서 아무것도 못 고르는 일이 생겨 정식 MIME 을 같이 적었다.
- `change` 뒤 `value` 를 비운다. 같은 파일을 다시 골라도 `change` 가 오게.

확인(390×844 모바일 뷰포트): 두 상자 모두 **모서리·가운데 3점이 전부 input**,
탭 → 파일 고르기 창 열림 → PDF 58쪽 읽힘, 끌어다 놓기 1회 처리, pageerror 없음.

(xlsx 는 이 뷰어의 허용 확장자가 아니다).

### 발견 25 — `pdfjsLib is not defined` · CDN 하나에 앱 전체가 걸려 있었다

`<script src="cdnjs…/pdf.min.js">` 가 막히면 그걸로 끝이었다. 화면은 멀쩡히 뜨고,
PDF 를 넣는 순간 `pdfjsLib is not defined` 만 뜬다. 이 문구는 **무엇이 잘못됐는지
말해 주지 않는다** — 사용자는 앱이 고장 난 줄 안다.

fflate 때(발견 17·20)와 같은 병이다. 그때는 라이브러리를 없애 해결했지만 pdf.js 는
1MB 라 `index.html` 에 심을 수 없다 — 심으면 claude.ai 대화창에 붙여 아티팩트로
만들 수가 없다(모델이 파일을 통째로 다시 써야 한다). 그래서 다르게 푼다.

**조치 둘:**

1. `ensurePdfjs()` — 정적 `<script src>` 를 없애고 **CDN 세 곳을 차례로** 시도한다
   (cdnjs → jsdelivr → unpkg). PDF 를 넣는 순간에만 부른다.
2. 전부 막히면 **막힌 호스트 이름과 다음 행동을 그대로 쓴다.**
   "pdf.js 를 못 불러왔습니다 — cdnjs.cloudflare.com, cdn.jsdelivr.net, unpkg.com
   가 모두 막혔습니다. 이 화면이 외부 파일을 차단하고 있습니다. …"

`<!-- PDFJS_INJECT` 자리를 두어 배포본과 개발 서버가 같은 방식으로 pdf.js 를 심는다.
심으면 `ensurePdfjs()` 가 `window.pdfjsLib` 를 보고 즉시 돌아가 CDN 을 아예 안 건드린다.

확인 (`dev/verify_cdn.mjs`):

```
(a) cdnjs 만 막힘    → cdn.jsdelivr.net 에서 가져옴 · PDF 58쪽 열림
(b) 세 곳 다 막힘    → 막힌 호스트를 이름까지 적고 멈춤
(c) 심어 둔 배포본   → CDN 요청 0건 · PDF 58쪽 열림
```

회귀: p6 3x3/4x4/5x4 각 12/12 · p6+p38 58행 · 9쪽 실호출 경로 32행 ·
모바일 파일 고르기 · 호출 차단 시 중단 — 전부 유지, pageerror 없음.

### 발견 26 — 오류 화면만 보고는 **어느 런타임인지** 알 수 없었다

같은 "Claude 호출이 막혀 있습니다" 가 세 곳에서 뜬다 — Claude Code publish 아티팩트,
claude.ai 대화창 아티팩트, 그냥 연 파일. 그런데 **원인과 대책이 각각 다르다.**
사용자가 화면을 캡처해 보내도 어디인지 구분이 안 돼 진단이 한 번씩 헛돌았다.

**조치:** 앱이 스스로 밝힌다. §4 에 `실행 환경` 줄을 항상 띄우고, 호출 실패 문구
끝에도 같은 내용을 붙인다.

```
실행 환경 — iframe 안 · 상위 https://claude.ai · 이 창 null(샌드박스) · window.claude 있음
```

네 조각이 각각 답을 준다 — 최상위 창인가 iframe 안인가 / 상위 문서가 누구인가
(`location.ancestorOrigins`, 없으면 `document.referrer`) / 이 창의 origin 이
`null`(샌드박스)인가 / `window.claude` 가 주입돼 있는가.

확인: 최상위 창 → `최상위 창 · 상위 알 수 없음 · 이 창 http://localhost:8124 ·
window.claude 없음` / 샌드박스 iframe → `iframe 안 · 상위 file:// · …`.

### 발견 27 — claude.ai 경로가 막히는 진짜 이유는 **파일 크기**였다

"index.html 을 붙이고 그대로 아티팩트로 만들어 줘" 는 대화창의 Claude 가 파일을
**통째로 옮겨 적어야** 성립한다. 74KB 는 출력 2만 5천 토큰이 넘는다. 느리고, 한
글자만 어긋나도 앱이 깨진다. 링크를 아무리 다시 올려도 이 병목은 그대로였다.

**조치:** `dev/minify.mjs` — esbuild 로 CSS·JS 를 압축해 `dist/index.min.html` 을
만든다. **74KB → 47KB (36% 감소).**

지키는 것:

- **이름을 안 바꾼다** (`minifyIdentifiers: false`). 최상위 `function` 선언이 그대로
  `window` 에 올라야 회귀 시험이 앱을 몰 수 있고 사람이 읽고 고칠 수도 있다.
- `<!-- PDFJS_INJECT -->` 자리를 남긴다. 빌드와 개발 서버가 여기에 pdf.js 를 심는다.
- 원본 `index.html` 이 계속 원본이다. 압축본은 배포용 사본이다.

만들면서 밟은 함정 둘:

1. **esbuild 의 기본 `charset` 은 ascii** 라 한글을 `\uXXXX` 로 바꾼다. 글자당
   3바이트가 6바이트가 되어 74KB 가 **101KB 로 늘었다.** `charset:'utf8'` 필요.
2. **`String.replace` 의 두 번째 인자를 문자열로 주면 `$&` `$'` `$1` 이 치환된다.**
   압축된 JS 에는 `$` 가 잔뜩 있어(`$` 헬퍼·템플릿 리터럴) 파일 꼬리가 통째로
   복제됐다. 함수로 넘겨야 한다.

`MIN=1 python3 dev/serve_local.py …` 로 **압축본에 회귀를 그대로 돌린다.**
결과: p6 3x3/4x4/5x4 각 12/12 · p6+p38 58행 · 9쪽 실호출 32행 · 모바일 파일 고르기 ·
중단 경로 2회 호출 · pageerror 없음 — 원본과 동일.
