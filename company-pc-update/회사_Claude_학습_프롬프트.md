# 회사 Claude Code 학습 프롬프트 — 세션 A · B

> 설계: [`LEARNING_DESIGN.md`](../LEARNING_DESIGN.md) · 만든 곳: 오케스트레이터 세션 · 2026-11-07
> 쓰는 법: 회사 PC 의 Claude Code 에서 **새 세션**을 열고 ① 학습 시작 프롬프트를 통째로 붙여 넣는다 → 사용자가 직접 가르친다 →
> 학습이 끝나면 ② 추출 프롬프트를 붙여 넣는다 → 나온 **md 파일 하나**를 개인 Claude Code(오케스트레이터)에 올린다.
> ★ **회사 업데이트 파일을 적용하기 전에 먼저 ② 추출을 해서 보낸다** — 업데이트는 최신으로 덮어써서, 보내지 않은 엔진 고침은 백업으로만 남는다.

| 세션 | 무엇을 배우나 | 회사 밖으로 나가는 것 |
|---|---|---|
| **A. P&ID · LOGIC 양식 학습** | 프로젝트마다 다른 도면 양식(종이 크기 · 테두리 · 표제란 · 범례 · 버블 · Logic 칸) | 엔진 코드 고침 · 이름 없는 양식 카드 · 회귀 숫자 |
| **B. 도서 · 3D 스펙 학습** | 프로젝트 스펙(사양서 · 기준서)의 내용 → 툴이 쓰는 지식 파일 | 스펙을 **읽는 방법**(엔진)의 고침만 — 지식 파일 · 스펙 내용은 안 나감 |

## A-① 학습 시작 프롬프트 (세션 A 를 열 때 한 번)

```text
너는 회사 PC 의 "A. P&ID · LOGIC 양식 학습" 세션이다. 나(사용자)가 직접 새 프로젝트 양식을 가르치고, 너는 그 학습으로 엔진을 좋아지게 한다.

[목적]
새 PJT 의 새 양식 · 새 크기 PDF 를 넣으면 P&ID 분석 · LOGIC 분석이 안 되는 문제를 줄인다.
한 PJT 에만 맞추지 말고, 비슷한 양식 모두에 통하게 엔진을 고친다. 그 엔진 개선값만 나중에 개인 Claude Code 로 보낸다.

[자리]
- 개발 폴더: C:\Claude\PID_dev  (여기서만 고친다)   · 운영 폴더: C:\Claude\PID (포트 8000 · 직접 고치지 않는다)
- 자료(회사 밖으로 안 나감): PID_dev 의 app\_data\ (또는 pid_data\) — 프로젝트별 학습 기록
  · P&ID 도면 가르치기: app\_data\projects\<PJT>\form_teach.json · title_block_cells.json   (app/form_teach.py · app/teach_propose.py)
  · LOGIC 가르치기: app\_data\logic\<job>\overrides.json 의 "teach"   (app/logic/overrides.py)
- 먼저 읽을 것: PID_dev 의 CLAUDE.md → docs/handoff/pid.md · docs/handoff/logic.md (필요한 절만)
- 학습 작업 폴더: C:\Claude\학습\A\  (없으면 만든다 · 회사 밖으로 안 나감)

[시작할 때 한 번]
1. 화면 띠의 '업데이트 N' 과 app\_update.json 의 rev 를 C:\Claude\학습\A\기준판.txt 에 적는다.
2. PID_dev 가 git 저장소이면 지금 커밋을 기준으로 적는다. 아니면 엔진 폴더(app · config · spike · tests)를
   C:\Claude\학습\A\기준_<날짜>\ 로 복사해 둔다 (나중에 바뀐 것만 뽑기 위해 — app\_data 는 복사하지 않는다).
3. C:\Claude\학습\금지낱말.txt 가 없으면 만들고, 나에게 발주처 · PJT 이름 · 프로젝트 번호 · 문서번호 꼴을 물어 채운다.
   이 파일은 절대 회사 밖으로 보내지 않는다.

[가르치는 방법 — 내가 하는 것]
- 분석이 멈춘 화면에서 '도면 가르치기'(P&ID) · '가르치기'(LOGIC)로 자리를 짚거나, 너에게 말로 알려 준다
  (예: "이 양식은 범례가 3장, 버블이 육각형, 표제란이 오른쪽 위").

[네가 할 것]
1. 가르친 것을 그 PJT 의 학습 기록으로 저장한다 (기존 기능을 쓴다 — 없는 것을 만들기 전에 있는 것을 찾는다).
2. 같은 문제가 다른 PJT 에도 생길 수 있으면 엔진을 고친다. 지킬 것 (CLAUDE.md §4):
   - 판정 값은 그 도면의 범례 · 도면에서 런타임에 잰다. 코드에 치수 · 임의값 · 태그 값을 박지 않는다.
   - 도면에 없는 값은 만들지 않는다 (비우고 사유). 검출에 LLM 을 쓰지 않는다.
   - 회귀 기준선(spike/baselines_3p.json)이 움직이면 원인을 칸 단위로 밝힌다.
3. 가르친 양식을 '이름 없는 양식 카드'로 C:\Claude\PID_dev\config\form_library\FORM-<번호>.yaml 에 남긴다:
   id · 종이(크기 · 방향) · 테두리 비율 · 표제란 자리(비율) · NOTES 자리 · 범례(장 수 · 칸 머리말 일반 낱말) ·
   버블(모양 · 지름 범위 mm) · LOGIC(칸 배치 · 게이트 표기 꼴) · 처음 실패 사유 · 고친 엔진 부분.
   발주처 · PJT 이름 · 번호 · 실제 태그 값은 넣지 않는다 (예시가 필요하면 <TAG> 같은 자리표시).
4. 고친 뒤 회사의 다른 PJT 들로 다시 돌려 본다 (spike/regression_3p.py 와 같은 방식). 숫자만 적는다:
   PJT 수 · 장 수 · 고치기 전/후 읽힌 장 · 실패 사유별 개수.
5. 작업할 때마다 C:\Claude\학습\A\학습일지.md 에 한 줄씩: 날짜 · FORM 번호 · 무엇을 가르쳤나(이름 없이) · 엔진 어디를 고쳤나 · 회귀 숫자.

[하지 말 것]
- 도면 · 결과 · 학습 기록을 C:\Claude\학습 밖으로 복사하거나 외부로 보내지 않는다.
- 운영 폴더(C:\Claude\PID)를 직접 고치지 않는다. 회사 업데이트 zip 을 만들지 않는다 (개인 쪽 오케스트레이터가 만든다).
- 내가 "추출해" 라고 하기 전에는 내보낼 파일을 만들지 않는다.

먼저 [시작할 때 한 번] 1~3 을 하고 결과를 짧게 알려 줘. 그다음 내가 첫 PJT 를 가르친다.
```

## A-② 추출 프롬프트 (세션 A 학습이 끝나면)

```text
지금까지의 학습으로 좋아진 엔진 개선값만 md 파일 하나로 뽑아 줘. 개인 Claude Code(오케스트레이터)가 이 파일로 엔진을 다시 학습시킨다.

[파일]
C:\Claude\학습\A\보낼것\엔진개선값_A_<YYYYMMDD>.md   (300KB 넘으면 _1 · _2 로 나눈다)

[담는 것 — 이 순서 · 제목 그대로]
# 엔진 개선값 — A. P&ID · LOGIC — <YYYY-MM-DD>
## 0. 반출 점검          (아래 [반출 점검] 결과 표 · 전부 통과여야 파일을 만든다)
## 1. 기준 판            (업데이트 N · app\_update.json rev · git 커밋 또는 기준 복사 날짜)
## 2. 무엇이 좋아졌나    (쉬운 말 3~7줄 — 비전공자가 읽는다)
## 3. 양식 카드          (config\form_library\FORM-*.yaml 을 카드마다 ```yaml 블록으로 · 이름 없이)
## 4. 엔진 코드 변경     (기준 판 대비 바뀐 파일마다 ```diff 블록 = unified diff · 새 파일은 전체 · 지운 파일은 목록)
                          엔진 파일만: app\ (app\_data 제외) · config\ · spike\ · tests\ — 그 밖은 담지 않는다
## 5. 회귀 결과          (숫자만: PJT 수 · 장 수 · 전/후 읽힌 장 · 실패 사유별 개수 · 기준선 변화와 원인)
## 6. 학습일지 요약      (학습일지.md 를 이름 없이 줄여서)
## 7. 개인 쪽에 부탁     (합칠 때 볼 것 · 질문 · 아직 못 고친 양식의 실패 사유)

[반출 점검 — 파일을 만들기 전에 md 본문 전체를 검사하고, 하나라도 걸리면 만들지 말고 무엇이 걸렸는지 알려 줘]
1. 파일 종류: PDF · Excel · DXF · 그림 · DB · zip 내용이나 app\_data · projects · logic\<job> 의 파일이 들어 있지 않다.
2. 금지 낱말: C:\Claude\학습\금지낱말.txt 의 낱말이 하나도 없다 (대소문자 · 띄어쓰기 무시). 결과에는 낱말 자체가 아니라 '개수'만 적는다.
3. 도면 값: 실제 태그 번호 꼴(예: 글자 1~4개 + 숫자 3~5개)이 코드 · 카드 · 예시에 박혀 있지 않다 — 시험 코드 예시는 <TAG> 자리표시나 지어낸 꼴로.
4. 문서번호 · 도면번호 · 날짜가 붙은 파일 이름 · 사람 이름이 없다.
5. 범례 머리말처럼 여러 발주처가 같이 쓰는 일반 낱말(LINE VALVES 등)은 괜찮다.
## 0 에 표로: 항목 · 결과(통과/걸림) · 개수.

다 만들면 파일 위치 · 크기 · 담긴 FORM 개수 · 바뀐 엔진 파일 개수를 알려 줘. 내가 그 md 를 직접 개인 쪽에 올린다.
```

## B-① 학습 시작 프롬프트 (세션 B 를 열 때 한 번)

```text
너는 회사 PC 의 "B. 도서 검토 · 3D 계측제어 스펙 학습" 세션이다. 회사가 프로젝트 스펙을 지정 폴더에 넣으면, 너는 그것을 읽어 대시보드 툴이 쓰는 지식 파일을 만든다.
나(사용자)가 무엇을 배워야 하는지 직접 알려 준다.

[목적]
대시보드의 '도서검토'와 '3D 계측제어'가 프로젝트를 고르면 그 프로젝트 스펙을 근거로 답하고 MR 초안을 쓰게 한다.
스펙 내용과 지식 파일은 회사 안에만 둔다. 학습하다가 툴이 스펙을 '읽는 방법'(엔진)을 고쳤으면 그 고침만 나중에 개인 Claude Code 로 보낸다.

[자리]
- 스펙 넣는 곳:   C:\Claude\Specs\<PJT>\      (회사가 넣는다 · 사양서 · 기준서 · Datasheet 꼴 · PDF/DOCX/XLSX)
- 지식 파일 쓰는 곳: C:\Claude\Knowledge\<PJT>\  (네가 만든다 · 회사 밖으로 안 나감)
    books\  도서검토용 — 개념 · 근거 노트. 꼴은 도서검토의 kb.js 와 같게: 개념마다 [출처 문서 · 쪽, 요약] 노트
    ic3d\   3D 계측제어용 — 항목(PSV · Ball Valve · Transmitter …)별 스펙 값. 꼴은 IC_Dashboard 의 'Spec for each Item' 과 같게
            (값마다 출처 문서 · 쪽 · '미확인' 표시를 그대로 — 근거 없는 값은 만들지 않는다)
- 툴 자리: 도서검토 = C:\Claude\PID_dev\app\static\books (PID 서버 /books) ·
           3D 계측제어 = IC_Dashboard 폴더 (어디 풀었는지 나에게 물어본다 — 앞으로 PID 서버 /ic3d 로 들어갈 예정)
- 학습 작업 폴더: C:\Claude\학습\B\   · 금지 낱말: C:\Claude\학습\금지낱말.txt (A 와 같은 파일 · 없으면 나에게 물어 만든다)

[시작할 때 한 번]
1. 도서검토 판(app\static\books\index.html 의 VERSION) · IC_Dashboard 판을 C:\Claude\학습\B\기준판.txt 에 적는다.
2. 툴 엔진 폴더(app\static\books · app\books*.py · IC_Dashboard\app)를 C:\Claude\학습\B\기준_<날짜>\ 로 복사해 둔다 (바뀐 것만 뽑기 위해).
3. C:\Claude\Specs\ 아래 PJT 폴더와 문서 수를 세어 알려 준다.

[네가 할 것 — 내가 "<PJT> 학습해" 라고 하면]
1. C:\Claude\Specs\<PJT>\ 의 문서를 읽어 Knowledge\<PJT>\books · ic3d 지식 파일을 만든다. 값마다 출처(문서 · 쪽)를 단다.
2. 툴이 Knowledge\<PJT>\ 를 아직 못 읽으면, 기존 구조를 따라 가장 작게 '프로젝트 지식 읽기' 를 넣는다
   (도서검토: 프로젝트를 고르면 그 노트를 답변 상자 근거로 · 3D: 항목 스펙 값을 MR 초안에). 외부 서버 · CDN · API 를 새로 쓰지 않는다.
3. 문서를 못 읽거나 잘못 읽으면(표 머리가 두 줄 · 쪽 번호 꼴 · 단위 표기 …) 그 '읽는 방법'을 엔진에서 고친다 — 한 문서에만 맞추지 말고 같은 꼴 모두에.
4. 지식 파일을 만든 뒤 내가 질문 3~5개로 확인한다. 답이 근거 쪽과 맞는지 함께 본다.
5. 작업할 때마다 C:\Claude\학습\B\학습일지.md 에 한 줄씩: 날짜 · PJT 번호 대신 '프로젝트 1·2…' · 문서 꼴 · 고친 엔진 부분 · 확인 결과.

[하지 말 것]
- 스펙 · 지식 파일 · 그 요약을 C:\Claude 밖으로 복사하거나 외부로 보내지 않는다.
- 사내 데이터를 외부 서비스로 보내는 기능(외부 번역 · 외부 LLM 답변)을 켜지 않는다.
- 회사 업데이트 zip 을 만들지 않는다. 내가 "추출해" 라고 하기 전에는 내보낼 파일을 만들지 않는다.

먼저 [시작할 때 한 번] 1~3 을 하고 결과를 짧게 알려 줘.
```

## B-② 추출 프롬프트 (세션 B 학습이 끝나면)

```text
지금까지의 학습으로 툴 엔진이 좋아진 부분만 md 파일 하나로 뽑아 줘. 스펙 내용 · 지식 파일은 절대 담지 않는다.

[파일]
C:\Claude\학습\B\보낼것\엔진개선값_B_<YYYYMMDD>.md   (300KB 넘으면 _1 · _2 로 나눈다)

[담는 것 — 이 순서 · 제목 그대로]
# 엔진 개선값 — B. 도서 검토 · 3D 계측제어 — <YYYY-MM-DD>
## 0. 반출 점검          (아래 [반출 점검] 결과 표 · 전부 통과여야 파일을 만든다)
## 1. 기준 판            (도서검토 VERSION · IC_Dashboard 판 · 기준 복사 날짜)
## 2. 무엇이 좋아졌나    (쉬운 말 3~7줄)

## 6. 학습일지 요약      (이름 · 번호 없이)
## 7. 개인 쪽에 부탁     (합칠 때 볼 것 · 아직 못 읽는 문서 꼴과 사유)
